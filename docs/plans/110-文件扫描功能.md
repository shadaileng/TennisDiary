# Step 110：文件扫描功能

## 一、目标

为 Admin 文件管理添加**孤立文件扫描**能力，用于：
1. 扫描 `data/uploads` 目录，发现未在 File 表中注册的文件
2. 提供"纳入管理"操作，将选中的文件注册到 File 表
3. 在 Admin 文件管理页面展示扫描结果

## 二、现状问题分析

### 2.1 当前文件管理

| 现状 | 问题 |
|------|------|
| File 表记录已注册的文件 | 无法追踪未注册的孤立文件 |
| 手动上传的文件（如备份、旧数据）可能未注册 | 磁盘空间浪费 |
| 无法批量发现和管理孤立文件 | 运维困难 |

### 2.2 孤立文件来源

| 来源 | 说明 |
|------|------|
| 旧版本上传 | 版本升级前上传的文件，未注册到 File 表 |
| 手动放置 | 管理员手动放置到 uploads 目录的文件 |
| 备份恢复 | 从备份恢复的文件，File 记录未同步 |
| 业务遗留 | 业务删除时未正确清理 File 记录 |

## 三、设计方案

### 3.1 扫描逻辑

**核心思路**：遍历 `data/uploads` 目录，与 File 表中已注册的 `rel_path` 对比，找出未注册的文件。

**扫描流程**：
```
遍历 uploads 目录 → 收集所有文件路径 → 查询 File 表已注册路径 → 计算差集 → 返回未注册文件列表
```

**路径映射规则**：
```
avatars/1/xxx.jpg     → user_id=1, upload_source=avatar
gears/1/xxx.jpg       → user_id=1, upload_source=gear_image
videos/1/xxx.mp4      → user_id=1, upload_source=video
analyses/1/xxx.jpg    → user_id=1, upload_source=video_frame
```

### 3.2 API 端点

| 端点 | 方法 | 功能 |
|------|------|------|
| `/api/admin/files/scan` | POST | 扫描 uploads 目录，返回未注册文件列表 |
| `/api/admin/files/register` | POST | 将选中的文件注册到 File 表 |
| `/api/admin/files/register-all` | POST | 一键注册所有未注册文件 |

### 3.3 数据模型

**扫描结果响应**：
```python
class OrphanFileInfo(BaseModel):
    """未注册文件信息"""
    rel_path: str = Field(description="相对路径")
    size_bytes: int = Field(description="文件大小（字节）")
    modified_at: float = Field(description="最后修改时间戳")
    inferred_user_id: int | None = Field(default=None, description="推断的用户 ID")
    inferred_source: str = Field(default="other", description="推断的上传来源")

class ScanResultResponse(BaseModel):
    """扫描结果"""
    total_files: int = Field(description="uploads 目录总文件数")
    registered_files: int = Field(description="已注册文件数")
    orphan_files: int = Field(description="未注册文件数")
    orphans: list[OrphanFileInfo] = Field(description="未注册文件列表")
    total_orphan_size: int = Field(description="未注册文件总大小（字节）")
```

**注册请求**：
```python
class RegisterFilesRequest(BaseModel):
    """注册文件请求"""
    files: list[str] = Field(description="要注册的文件相对路径列表")
    default_user_id: int = Field(default=0, description="默认用户 ID（路径无法推断时使用）")
```

## 八、注意事项

1. **性能考虑**：大目录扫描可能耗时，建议异步或分页返回
2. **路径推断**：从路径结构推断 user_id 和 upload_source，无法推断时使用默认值
3. **幂等性**：重复注册同一文件不会创建重复记录
4. **权限控制**：仅管理员可执行扫描和注册操作
5. **日志记录**：扫描和注册操作需记录审计日志
