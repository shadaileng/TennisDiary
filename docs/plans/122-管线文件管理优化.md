# 管线文件管理优化

## 1. 背景

电子教练分析管线（`/api/analyses/start`）生成多种文件，但部分文件未纳入文件管理系统：

| 文件 | 生成阶段 | 文件管理 | 删除分析时级联 |
|------|---------|:-------:|:-------------:|
| 原始视频 | 上传时 | ✅ `video` | ✅ |
| 裁剪视频 `_seg0.mp4` | video_service | ❌ 未登记 | ✅（通过 `video_url`） |
| 采样帧 `_f{i}.jpg` | video_service | ❌ 未登记 | ❌ |
| 骨架帧 `_sk{i:04d}.jpg` | pose_service | ✅ `skeleton_frame` | ✅ |
| 骨架视频 `_skeleton.mp4` | pose_service | ✅ `skeleton_video` | ✅ |

**问题：**
- 裁剪视频未登记 File 表，管理界面不可见
- 采样帧未登记 File 表，小程序不使用，成为磁盘孤儿文件

## 2. 目标

1. 裁剪视频纳入文件管理（`upload_source=video_playback`）
2. 采样帧在分析完成后清理（不纳入管理，小程序不使用）
3. 移除 `pose.skeleton_thumb` 冗余字段（与 `analysis.thumb` 重复）

## 3. 文件清理策略

### 3.1 各文件的使用与管理情况

| 文件 | 小程序使用 | Admin 使用 | 纳入管理 | 删除分析时清理 |
|------|:---------:|:---------:|:-------:|:-------------:|
| 原始视频 | ✅ `video_url` | ✅ | ✅ | ✅ |
| 裁剪视频 `_seg0.mp4` | ✅ `video_url` | ✅ | ❌ → ✅ | ✅ |
| 采样帧 `_f{i}.jpg` | ❌ | ❌ | ❌ | ❌ → ✅ 清理 |
| 骨架帧 `_sk{i:04d}.jpg` | ❌（死代码） | ✅ | ✅ | ✅ |
| 骨架视频 `_skeleton.mp4` | ✅ | ✅ | ✅ | ✅ |
| `pose.skeleton_thumb` | ❌（与 thumb 重复） | ✅ | ✅ | ✅ |

### 3.2 小程序骨架帧使用情况

小程序 `report.vue` 中骨架帧的降级逻辑是**死代码**：

```vue
<!-- 有骨架视频或原视频时显示视频区域 -->
<view v-if="skeletonVideoSrc || originalVideoSrc" class="pose-video">
  <video :src="activeVideoSrc" controls />
</view>

<!-- 仅当两个视频都不可用时才降级显示帧列表 -->
<scroll-view v-else-if="skeletonFrameSrcs.length > 0" scroll-x>
  <image v-for="(src, i) in skeletonFrameSrcs" :key="i" :src="src" />
</scroll-view>
```

实际行为：无骨架视频时不显示骨架选项，直接使用原视频。骨架帧降级逻辑不会执行。

**结论**：骨架帧文件可保留给 Admin 使用，小程序不受影响。

## 4. 技术方案

### 4.1 裁剪视频纳入 File 表

**文件：`pipeline.py` - `_process_video`**

在更新 `video_url` 后，将裁剪视频登记到 File 表：

```python
def _process_video(self, video_path: str, metadata: dict) -> dict:
    # ... 现有逻辑 ...
    
    if self.analysis_id:
        working_path = result.get("working_path")
        rel_video_url = file_service.abs_path_to_rel(working_path) if working_path else None
        self._update_analysis_field(video_url=rel_video_url)
        
        # 新增：裁剪视频纳入文件管理
        if rel_video_url and result.get("trimmed"):
            file_service.get_or_create_file(
                db=self.db,
                user_id=self._get_user_id(),
                rel_path=rel_video_url,
                upload_source="video_playback",
                original_name=f"{os.path.basename(working_path)}_playback",
                business_type="analysis",
                business_id=self.analysis_id,
            )
    
    return result
```

**分析：**
- `decrement_analysis_files` 已处理 `analysis.video_url`，删除分析时会递减引用计数 ✅
- Admin 文件管理界面可见 `video_playback` 类型文件 ✅
- 秒传检测：MD5 相同的裁剪视频会复用已有记录 ✅

### 4.2 管线完成后清理采样帧

**文件：`pipeline.py` - `_finalize`**

新增 `_cleanup_sampled_frames` 方法，在分析完成后删除采样帧：

```python
def _cleanup_sampled_frames(self, video_url: str) -> None:
    """删除采样帧文件（_f{i}.jpg），这些是 AI/姿态推理的中间数据"""
    import glob
    
    video_dir = os.path.dirname(file_service.rel_path_to_abs(video_url))
    base = os.path.splitext(os.path.basename(video_url))[0]
    # 匹配 {base}_f*.jpg（采样帧），不匹配 _sk*.jpg（骨架帧）
    pattern = os.path.join(video_dir, f"{base}_f*.jpg")
    cleaned = 0
    for path in glob.glob(pattern):
        try:
            os.remove(path)
            cleaned += 1
        except OSError as exc:
            log.warning("删除采样帧失败: %s - %s", path, exc)
    if cleaned:
        log.info("已清理采样帧: {} 个文件 business=analysis/{}", cleaned, self.analysis_id)
```

**分析：**
- 采样帧未登记 File 表，无需递减引用计数
- 删除时机在 `_finalize` 之后，AI 和姿态推理已完成
- 使用 `glob.glob` 匹配 `_f*.jpg`，不会误删 `_sk*.jpg`（骨架帧）

### 4.3 移除 `pose.skeleton_thumb` 冗余字段

**文件：`pipeline.py` - `_write_pose_result`**

`pose.skeleton_thumb` 与 `analysis.thumb` 指向同一文件（`_sk0000.jpg`），从 pose JSON 中移除：

```python
pose_for_db = {
    "frames": pose_result.get("frames"),
    "metrics": pose_result.get("metrics"),
    "detected": pose_result.get("detected"),
    "skeleton_frames": [f["rel_path"] for f in (pose_result.get("skeleton_frames") or [])],
    "skeleton_video_url": pose_result.get("skeleton_video_url"),
    # 移除 skeleton_thumb，使用 analysis.thumb 替代
}
```

**文件：`admin/src/views/analyses/index.vue`**

Admin 分析详情页改为使用 `a.thumb`：

```vue
<!-- 修改前 -->
v-if="fileUrl(pose.skeleton_thumb)"
:src="fileUrl(pose.skeleton_thumb)"

<!-- 修改后 -->
v-if="fileUrl(a.thumb)"
:src="fileUrl(a.thumb)"
```

**分析：**
- 小程序 `report.vue`：不使用 `pose.skeleton_thumb`，无影响 ✅
- Admin `analyses/index.vue`：需要适配 ⚠️

## 5. 风险评估

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 采样帧清理影响重新分析 | 低 | 分析完成后已无需采样帧，重新分析会重新生成 |
| 裁剪视频登记重复 | 低 | `get_or_create_file` 内部有 MD5 秒传检测 |
| `pose.skeleton_thumb` 移除影响旧数据 | 低 | 旧数据保留该字段，Admin 改为读取 `a.thumb` |
