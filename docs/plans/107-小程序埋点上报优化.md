# Step 107：小程序埋点上报优化

## 一、目标

补全小程序端缺失的埋点事件，重点完善电子教练的完整端点级链路追踪，启用 warn 级别和 network 类型，管理端支持 trace_id 一键复制。

## 二、现状分析

### 2.1 参数问题汇总

#### A. 缺少 trace_id（链路断裂，共 11 处）

| # | 文件 | action | 影响 |
|---|------|--------|------|
| 1 | `request.ts` | `api_error` | 网络层无 traceId，无法关联业务调用方 |
| 2 | `request.ts` | `http_error` | 同上 |
| 3 | `request.ts` | `network_error` | 同上 |
| 4 | `data.ts` | `video_upload_failed` | createTraceId 传了但 extra 未携带 |
| 5 | `stores/diary.ts` | `diary_list_load_failed` | fetchList 无 traceId |
| 6 | `stores/gear.ts` | `gear_list_load_failed` | 同上 |

| 8 | `App.vue` | fatal crash | logFatal 无 action，extra 仅 errMsg |
| 9 | `share.vue` | `share_qr_load_failed` | 缺 trace_id |
| 10 | `share.vue` | `share_persist_save_failed` | 缺 trace_id |
| 11 | `share.vue` | `share_canvas_failed` | 缺 trace_id |

#### B. 关键业务参数缺失

| 位置 | action | 缺失字段 | 影响 |
|------|--------|---------|------|
| `stores/auth.ts` | `profile_update` | `user_id` / `nickname` | 无法追踪谁更新了资料 |
| `stores/diary.ts` | `diary_create` | `date` | 不知道是哪天的日记 |
| `stores/diary.ts` | `diary_update` | `type` | 更新时无法知道日记类型 |
| `data.ts` | `video_upload_failed` | `file_size` / `duration` | 无法分析上传失败的文件特征 |
| `analyze.vue` | `analysis_failed` | 缺少 HTTP status | 无法区分后端 5xx vs 客户端错误 |

#### C. 电子教练链路追踪信息不足

当前 `analysis_started` / `analysis_completed` / `analysis_failed` 的 extra 缺少：
- 各后台端点耗时（无法定位慢环节）
- 失败步骤标识（无法区分是上传/分析/落库失败）
- 视频/裁剪详情（无法分析用户使用模式）

#### D. 页面曝光缺失（9个页面）

`page_view_diary` / `page_view_gear` / `page_view_weight` / `page_view_stats` / `page_view_mine` / `page_view_coach` / `page_view_analyze` / `page_view_report` / `page_view_share`

#### E. 日志级别/类型未充分利用

| 问题 | 建议 |
|------|------|
| `logWarn` 零使用 | token 过期、请求超时等中等严重场景使用 |
| `network` 类型零使用 | request.ts 网络错误应指定 type="network" |

## 三、电子教练链路参数设计

4个后台端点是同一个原子操作，以 `traceId` 串联为一条完整链路。通过在 `analysis_started` / `analysis_completed` / `analysis_failed` 的 `extra` 中记录各环节耗时和状态，实现链路追踪。

### 3.1 analysis_started（增强 extra）

```typescript
{
  trace_id: "t1723123456789-abc123",
  mode: "single",           // single | full
  kind: "正手",             // 正手 | 反手 | 发球 | 综合
  has_cuts: true,           // 是否有裁剪片段
  video_duration: 12.5,     // 视频原始时长（秒）
  segment_count: 1,         // 裁剪片段数
}
```

### 3.2 analysis_completed（增强 extra）

```typescript
{
  trace_id: "t1723123456789-abc123",
  analysis_id: 42,
  mode: "single",
  kind: "正手",
  steps: {
    upload: {
      duration_ms: 5200,              // 上传耗时
      video_url: "https://...",       // 上传后视频URL
      frame_count: 8,                 // 抽帧数
      duration: 12.5,                 // 视频时长
    },
    ai: {
      duration_ms: 32000,             // AI分析耗时
      score: 78,                      // 技术评分
      ntrp: "3.5",                    // NTRP等级
    },
    pose: {
      duration_ms: 18000,             // 姿态分析耗时
      detected: true,                 // 是否检测到人体
      has_skeleton: true,             // 是否有骨架视频
    },
    create: {
      duration_ms: 450,               // 落库耗时
      analysis_id: 42,
    },
  },
  total_duration_ms: 55650,           // 总耗时
}
```

### 3.3 analysis_failed（增强 extra）

```typescript
{
  trace_id: "t1723123456789-abc123",
  error: "视频上传失败: 网络超时",
  mode: "single",
  kind: "正手",
  failed_step: "upload",              // 失败环节：upload | ai | pose | create
  completed_steps: {
    upload: false,                    // 各环节是否完成
    ai: false,
    pose: false,
    create: false,
  },
  total_duration_ms: 8200,            // 总耗时（到失败为止）
}
```

### 3.4 设计原则

- 原子操作 = 一次「开始分析」按钮点击 → 成功/失败，对应一条事件记录
- traceId 贯穿全链路，管理端按 traceId 可聚合查看完整链路
- 各端点耗时通过 `Date.now()` 在前端计算，记录在 extra 中
- 失败时记录 `failed_step`，便于快速定位问题环节

## 四、各事件参数补全清单

### 4.1 eventLogger.ts - 新增 type 参数支持

当前 `logInfo`/`logError` 的 `type` 字段硬编码为 `"business"`，无法指定 `"network"` 类型。需新增 `type` 参数：

```typescript
// logInfo: 新增 type 参数（第3位，action 前）
export function logInfo(
  message: string,
  extra?: Record<string, any>,
  type?: EventType,    // 新增，默认 "business"
  action?: string,
  traceId?: string,
): void

// logError: 新增 type 参数（第3位，action 前）
export function logError(
  message: string,
  extra?: Record<string, any>,
  type?: EventType,    // 新增，默认 "business"
  action?: string,
  stack?: string,
  traceId?: string,
): void
```

> 注意：原计划的 `logPageView` 辅助函数已移除（用户反馈价值不大）。

### 4.3 电子教练链路参数增强

**文件**：`miniapp/src/pages/coach/analyze.vue`

#### analysis_started（增强）

当前：
```typescript
logInfo("开始AI分析", { trace_id: traceId, mode: mode.value, kind: kind.value }, "analysis_started", traceId);
```

改为：
```typescript
logInfo("开始AI分析", {
  trace_id: traceId, mode: mode.value, kind: kind.value,
  has_cuts: !!formData.cuts, video_duration: videoDuration.value,
  segment_count: segments.value.length,
}, "analysis_started", traceId);
```

#### analysis_completed（增强）

当前：
```typescript
logInfo("AI分析完成", { trace_id: traceId, analysis_id: analysis.id, kind: kind.value, mode: mode.value, has_pose: !!pose }, "analysis_completed", traceId);
```

改为：
```typescript
logInfo("AI分析完成", {
  trace_id: traceId, analysis_id: analysis.id,
  mode: mode.value, kind: kind.value,
  steps: {
    upload: { duration_ms: uploadDuration, video_url: uploaded.video_url, frame_count: uploaded.frame_urls?.length, duration: uploaded.duration },
    ai: aiResult.status === "fulfilled"
      ? { duration_ms: aiDuration, score: aiResult.value.score, ntrp: aiResult.value.ntrp }
      : { duration_ms: aiDuration, error: String(aiResult.reason) },
    pose: poseResult.status === "fulfilled"
      ? { duration_ms: poseDuration, detected: poseResult.value.detected, has_skeleton: !!poseResult.value.skeleton_video_url }
      : { duration_ms: poseDuration, error: String(poseResult.reason) },
    create: { duration_ms: createDuration, analysis_id: analysis.id },
  },
  total_duration_ms: Date.now() - t0,
}, "analysis_completed", traceId);
```

#### analysis_failed（增强）

当前：
```typescript
logError("AI分析失败", { trace_id: traceId, error: msg, kind: kind.value, mode: mode.value }, "analysis_failed", undefined, traceId);
```

改为：
```typescript
logError("AI分析失败", {
  trace_id: traceId, error: msg,
  mode: mode.value, kind: kind.value,
  total_duration_ms: Date.now() - t0,
}, "analysis_failed", undefined, traceId);
```

### 4.4 页面曝光（已移除）

用户反馈页面曝光事件价值不大，已移除 `logPageView` 函数和所有页面的 `onShow` 曝光事件。

### 4.5 request.ts 启用 network 类型和 warn

**文件**：`miniapp/src/services/request.ts`

```typescript
// 网络错误使用 network 类型（type 为第3参数）
fail: (err) => {
  logError(`网络请求失败 ${method} ${url}: ${err.errMsg || "未知错误"}`, {
    method, url, status: -1,
  }, "network");
  reject(new ApiError(-1, err.errMsg || "网络请求失败"));
},

// 401 非登录接口使用 warn
if (statusCode === 401 && !url.includes("/auth/")) {
  logWarn("请求返回401但非登录接口", { method, url, statusCode });
}
```
