# Step 74：日志查看倒序分页优化

## 一、背景

Admin 后台「日志查看」页面存在**看不到最新日志**的问题：

1. **后端取的是最早日志**：`server/app/routers/admin/system.py` 的 `query_logs` 从头到尾顺序读文件，匹配到 `limit` 条就 `break`。而 loguru 是追加写日志，**最新日志在文件尾部**。当文件行数 > `limit` 时，拿到的永远是最早的 `limit` 条，最新日志被排除在外。

```python
# server/app/routers/admin/system.py（当前实现，第 130-158 行）
@router.get("/logs", response_model=ApiResponse[dict])
def query_logs(
    level: str | None = None,
    keyword: str | None = None,
    limit: int = 100,
    admin: Admin = Depends(get_current_admin),
):
    """日志查询（支持按文件/级别/关键字过滤）"""
    log_file = Path(settings.LOG_DIR) / settings.LOG_FILE
    if not log_file.exists():
        return ApiResponse(data={"logs": [], "total": 0})

    logs = []
    try:
        with open(log_file, encoding="utf-8") as f:
            for line in f:
                if level:
                    # loguru 输出格式：`INFO     `（无方括号，大写）
                    if f"{level.upper():<8}" not in line:
                        continue
                if keyword and keyword not in line:
                    continue
                logs.append(line.strip())
                if len(logs) >= limit:
                    break
    except (OSError, ValueError) as e:
        raise HTTPException(status_code=500, detail=f"读取日志文件失败: {e!s}") from e

    return ApiResponse(data={"logs": logs, "total": len(logs)})
```

2. **前端写死 `limit: 500` 且无分页/刷新**：`admin/src/views/system/logs.vue` 固定传 `limit: 500`，无翻页、无手动刷新，页面数据一经加载即为旧数据快照。

```ts
// admin/src/views/system/logs.vue（当前实现，第 72-83 行）
const fetchLogs = async () => {
  try {
    const data = await getLogs({
      level: filters.level || undefined,
      keyword: filters.keyword || undefined,
      limit: 500
    })
    logs.value = data.logs
  } catch (e) {
    console.error('Failed to fetch logs:', e)
  }
}

onMounted(fetchLogs)
```

## 二、目标

1. 日志列表**最新优先**展示（tail 语义），默认即能看到最新日志。
2. 支持「加载更早」分页（`offset` 游标 + `has_more` 标记），可回溯历史日志。
3. 增加手动「刷新」按钮，可随时拉取最新日志。
4. 大文件读取高效（只读文件尾部，不整读不占内存）。
5. 不破坏现有测试与既有调用参数语义（`level`/`keyword`/`limit` 不变）。

## 三、方案设计

### 3.1 后端：倒序读取 + `offset` 游标 + `has_more`

重写 `server/app/routers/admin/system.py` 的 `query_logs`，采用「tail 语义」从文件末尾向前分块扫描，匹配到就收集，凑够 `limit` 即停；新增 `offset` 参数（跳过最近已加载的匹配数）与 `has_more` 返回标记。

```python
import os
from pathlib import Path
# ... 其余 import 保持不变 ...

@router.get("/logs", response_model=ApiResponse[dict])
def query_logs(
    level: str | None = None,
    keyword: str | None = None,
    limit: int = 100,
    offset: int = 0,
    admin: Admin = Depends(get_current_admin),
):
    """日志查询（尾部倒序读取，最新优先；offset 用于向前翻页加载更早）"""
    log_file = Path(settings.LOG_DIR) / settings.LOG_FILE
    if not log_file.exists():
        return ApiResponse(data={"logs": [], "total": 0, "has_more": False})

    def _matches(line: str) -> bool:
        if level and f"{level.upper():<8}" not in line:
            return False
        if keyword and keyword not in line:
            return False
        return True

    collected: list[str] = []
    matched = 0  # 已扫描到的匹配总数（从新到旧累计，用于 offset 游标）
    try:
        with open(log_file, "rb") as f:
            f.seek(0, os.SEEK_END)
            size = f.tell()
            chunk_size = 64 * 1024  # 每块 64KB，大文件也快
            pos = size
            carry = b""  # 块首残行，需与更早的块拼接
            while pos > 0 and len(collected) < limit:
                read_size = min(chunk_size, pos)
                pos -= read_size
                f.seek(pos)
                data = f.read(read_size) + carry
                lines = data.split(b"\n")
                carry = lines[0]
                for raw in reversed(lines[1:]):
                    if not raw:
                        continue
                    line = raw.decode("utf-8", errors="replace")
                    if not _matches(line):
                        continue
                    matched += 1
                    if matched > offset and len(collected) < limit:
                        collected.append(line.strip())
            # 处理文件最开头残留的一行
            if carry and len(collected) < limit:
                line = carry.decode("utf-8", errors="replace")
                if _matches(line):
                    matched += 1
                    if matched > offset:
                        collected.append(line.strip())
    except (OSError, ValueError) as e:
        raise HTTPException(status_code=500, detail=f"读取日志文件失败: {e!s}") from e

    # 循环停止时 pos 为尚未扫描的字节区段起点：
    # - pos > 0：凑满 limit 提前停止，更早的日志仍存在 → has_more=True
    # - pos == 0：整个文件已扫描完毕 → has_more=False
    return ApiResponse(
        data={
            "logs": collected,            # 从新到旧
            "total": matched,             # 本次扫描范围内匹配总数（新→旧累计，供游标计算）
            "has_more": pos > 0,
        }
    )
```

要点：

- **高效**：从文件尾部按 64KB 分块倒读，凑够即停，大文件不整读、不占内存；`total` 是「已扫描范围内匹配总数」，非全量统计（全量需扫完整个文件，无必要）。
- **兼容**：`level`/`keyword`/`limit` 语义不变，仅新增长 `offset`；返回顺序由「旧→新」变为「新→旧」。
- **游标语义**：`offset` 为「跳过最近已加载的匹配条数」。前端续载时传已加载条数即可，不依赖行号，轮转/追加不影响。
- **边界**：文件不存在时返回空数组 + `has_more=False`；`utf-8` 解码失败用 `errors="replace"` 兜底。

### 3.2 前端：加载更早分页 + 手动刷新

更新 `admin/src/api/system.ts`，`LogEntry` 增加 `has_more`，`getLogs` 增加 `offset` 参数：

```ts
export interface LogEntry {
  logs: string[]
  total: number
  has_more: boolean
}

export function getLogs(params: {
  level?: string
  keyword?: string
  limit?: number
  offset?: number
}): Promise<LogEntry> {
  return request.get('/api/admin/system/logs', { params })
}
```

更新 `admin/src/views/system/logs.vue`：

**操作区**（在「查询」旁增加「刷新」）：

  </button>

**列表头**（显示已加载条数 + 「加载更早」）：

```vue
<div class="p-4 border-b flex items-center justify-between">
  <span class="text-sm text-gray-600">已加载 {{ logs.length }} 条</span>
  <button
    @click="loadMore"
    :disabled="!hasMore"
    class="px-3 py-1 text-sm bg-olive-50 text-olive-700 rounded-md
           hover:bg-olive-100 disabled:opacity-40 disabled:cursor-not-allowed"
  >
    加载更早
  </button>
</div>
```

**脚本逻辑**（`reset=true` 为全新查询；`reset=false` 为续载更早）：

```ts
import { ref, reactive, onMounted, onUnmounted } from 'vue'
import { getLogs } from '@/api/system'

const PAGE_SIZE = 500
const logs = ref<string[]>([])
const hasMore = ref(false)
const filters = reactive({ level: '', keyword: '' })
// 若翻过页，暂停自动刷新，避免打断查看历史
let viewedOlder = false

const fetchLogs = async (reset = true) => {
  try {
    const data = await getLogs({
      level: filters.level || undefined,
      keyword: filters.keyword || undefined,
      limit: PAGE_SIZE,
      offset: reset ? 0 : logs.value.length  // 续载则跳过已加载的匹配数
    })
    logs.value = reset ? data.logs : [...logs.value, ...data.logs]
    hasMore.value = data.has_more
    if (reset) viewedOlder = false
  } catch (e) {
    console.error('Failed to fetch logs:', e)
  }
}

const loadMore = () => {
  viewedOlder = true
  fetchLogs(false)
}

onMounted(fetchLogs)
```

### 3.3 可选：自动轮询最新日志

仅在停留在最新页（未翻页）时自动刷新，避免打断历史查看：

```ts
let timer: ReturnType<typeof setInterval> | undefined
onMounted(() => {
  fetchLogs()
  timer = setInterval(() => !viewedOlder && fetchLogs(), 10_000)
})
onUnmounted(() => clearInterval(timer))
```

> 若觉得轮询多余，仅保留手动「刷新」按钮即可；该步骤为可选项，落地时按需取舍。

## 七、注意事项

1. **返回顺序变化**：`logs` 由「旧→新」变为「新→旧」，若其他调用方依赖原顺序需同步确认（当前仅 Admin 页面使用）。
2. **`total` 语义**：为「已扫描范围内匹配总数」，非文件全量匹配数；前端文案用「已加载 N 条」，避免误导。
3. **`offset` 游标**：基于匹配条数而非行号，`LOG_ROTATION="10 MB"` 轮转/追加写入不影响游标正确性。
4. **轮转文件不查历史**：loguru 轮转产生的旧文件（如 `app.log.2026-08-13_10-00-00`）不在当前查询范围，如需查历史可后续扩展「选择日志文件」参数（本期不做）。
5. **测试隔离**：新用例沿用 `tmp_path` + `monkeypatch` 隔离 `LOG_DIR` 的模式，与 Step 73 的 autouse fixture 兼容。
6. **长远可选**：若日志量极大且需要按时间区间/条件组合查询，可考虑运行日志落库（类似现有 `event_logs` 表）走 SQL 分页；当前「倒序读取 + 游标分页」性价比最高。
