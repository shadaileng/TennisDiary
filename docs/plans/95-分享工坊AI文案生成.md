# 95：分享工坊 AI 文案生成

## 一、背景与目标

### 1.1 问题描述

分享工坊（`pages/share/share.vue`）的「重新生成」按钮当前实现为**确定性本地模板**：

```typescript
function regenerate() {
  const pipe = buildContext(tpl.value, { diaries, analysis }, MOOD, INTENSITY);
  caption.value = genCaption(pipe); // 同一模板 + 同一数据 → 永远相同文案
  uni.showToast({ title: "已重新生成", icon: "none" });
}
```

`genCaption()`（`miniapp/src/utils/shareCanvas/caption.ts`）是无随机性的纯函数，**多次点击"重新生成"产出完全相同的文案**，实际行为等同于"重置"，与按钮语义不符。

### 1.2 目标

| 目标 | 说明 |
|------|------|
| AI 生成 | 「重新生成」按钮改为调用后端 AI 生成**风格化、有变化**的分享文案 |
| 多风格可选 | 支持 活泼 / 简洁 / 专业 三种文案风格，用户可切换 |
| 数据自动获取 | 后端根据模板类型 + 当前用户身份自动查库取数，**前端不传业务数据** |
| 优雅降级 | AI 未配置 / 超时 / 失败时回退到现有本地模板文案，前端无感 |
| 安全 | AI Key 仅存服务端（复用现有 `ai.*` 配置体系），不暴露给前端 |

## 二、现状

| 项 | 现状 |
|----|------|
| AI 服务 | `server/app/services/ai_service.py` 已有 `chat_vision()`（多模态，`httpx` 直调 OpenAI 兼容端点）、`extract_json()` |
| AI 配置 | `config_service.get_ai_config()` 已解析 `ai.provider / ai.api_key / ai.base_url / ai.model`（DB 覆盖 > 服务商 > env 默认） |
| AI 路由 | `server/app/routers/ai.py` 已有 `POST /api/ai/analyze`（鉴权 + 降级模式），可仿照新增 `POST /api/ai/caption` |
| 前端数据 | `share.vue` 已持有 `diaries` / `analysis` 完整数据，`caption` 为可编辑 textarea |
| 本地模板 | `miniapp/src/utils/shareCanvas/caption.ts` 的 `genCaption()` 可复用为降级兜底 |
| 模板类型 | `ShareTemplate = "月度战报" \| "今日日记" \| "技术评分"`（`miniapp/src/utils/shareCanvas/config.ts`） |

## 三、详细方案

### 3.1 后端

#### 3.1.1 新增 Schema（`server/app/schemas/schemas.py`）

```python
class CaptionRequest(BaseModel):
    """AI 文案润色请求：只传模板类型 / 风格 / 当前文案，业务数据由后端按当前用户查库"""
    template: Literal["月度战报", "今日日记", "技术评分"]
    style: Literal["活泼", "简洁", "专业"] = "活泼"
    text: str = Field(default="", description="当前 textarea 内容，AI 在此基础上润色")


class CaptionResponse(BaseModel):
    caption: str
```

#### 3.1.2 新增服务函数（`server/app/services/ai_service.py`）

| 函数 | 职责 |
|------|------|
| `chat_text(prompt, ai_config, max_tokens=1000)` | 纯文本版 `chat_vision`：复用其 httpx 逻辑，`messages` 仅含文本 content（`{"type": "text", "text": prompt}`），无图片 |
| `build_caption_context(db, user, template)` | 按模板类型查库组装数据摘要：<ul><li>`月度战报`：当月日记数 / 时长合计 / 花费合计</li><li>`今日日记`：最新一篇日记（日期/类型/时长/笔记）</li><li>`技术评分`：最新一条分析（kind/score/summary/最佳维度/改进项）</li></ul> |
| `generate_caption(template, style, context, ai_config, text="")` | 组装润色 prompt → `chat_text` → 返回文案字符串；失败抛异常由路由降级 |
| `build_local_caption(template, context)` | 本地降级模板文案（与前端 `genCaption` 逻辑等价） |

**Prompt 设计要点（润色模式）**：

- 角色：**网球运动社群文案创作者**；
- 输入：模板类型 + 数据摘要（JSON 化）+ **当前文案** + 风格要求；
- 任务：在用户已有文案基础上**润色改写**，保留核心意思与个人风格，结合数据丰富内容；
- 风格约束：
  - 活泼：emoji 丰富、口语化、感叹号、小红书体；
  - 简洁：短句、少 emoji、干净利落；
  - 专业：技术术语、教练口吻；
- 输出：**纯文案字符串**（首尾可换行，含 2-4 个话题标签 `#网球 #网球日记 …`），**不要 JSON 包裹**、不要前后缀说明；
- 空文案兜底：`text` 为空时 prompt 标注 `当前文案：（无）`。

#### 3.1.3 新增路由（`server/app/routers/ai.py`）

```
POST /api/ai/caption
```

| 项 | 说明 |
|----|------|
| 鉴权 | `get_current_user`（`X-Auth-Token`） |
| 入参 | `{ template, style, text }` |
| 流程 | `get_ai_config(db)` → 无 Key 直接本地降级 → `generate_caption()` → 成功返回 `ApiResponse(data={"caption": ...})` |
| 降级 | 无 Key / 抛异常 → 返回**本地模板文案**（与 `caption.ts` 一致的生成逻辑，服务端实现一份 Python 版） |

> 本地降级文案生成函数 `build_local_caption(template, context)` 与前端 `genCaption` 逻辑等价，保证 AI 不可用时行为与现状一致。

### 3.2 前端（`miniapp/`）

#### 3.2.1 新增 API（`miniapp/src/services/data.ts`）

```typescript
/** AI 文案润色（30s 超时，失败由后端降级返回本地文案） */
export function generateCaption(template: string, style: string, text: string): Promise<{ caption: string }> {
  return post<{ caption: string }>("/ai/caption", { template, style, text }, { timeout: 30000 });
}
```

#### 3.2.2 更新分享工坊页（`miniapp/src/pages/share/share.vue`）

1. **风格选择器**：配文卡标题下新增三选一 pill（活泼 / 简洁 / 专业），`ref<CaptionStyle>("活泼")`；
2. **按钮**：`重新生成` → `润色文案`，loading 文案 `AI 生成中…` → `润色中…`；前端所有用户可见文案不含"AI"字眼；
3. **regenerate()** 重写：

```typescript
async function regenerate() {
  if (regenerating.value) return;

  // 空态检查：无数据时不调润色接口
  if (tpl.value === "月度战报") {
    const monthDiaries = diaries.value.filter((d) => monthKey(d.date) === monthKey(todayStr()));
    if (monthDiaries.length === 0) {
      uni.showToast({ title: "还没有打卡记录，去记一篇吧～", icon: "none" });
      return;
    }
  } else if (tpl.value === "今日日记") {
    if (diaries.value.length === 0) {
      uni.showToast({ title: "还没有日记，先去记一篇吧～", icon: "none" });
      return;
    }
  } else if (tpl.value === "技术评分") {
    if (!analysis.value?.report) {
      uni.showToast({ title: "还没有分析报告，先去做一次分析吧～", icon: "none" });
      return;
    }
  }

  const traceId = createTraceId();
  regenerating.value = true;
  try {
    const res = await generateCaption(tpl.value, style.value, caption.value);
    caption.value = res.caption || caption.value;
    uni.showToast({ title: "已润色文案", icon: "none" });
  } catch {
    const pipe = buildContext(tpl.value, { diaries, analysis }, MOOD, INTENSITY);
    caption.value = genCaption(pipe);
    uni.showToast({ title: "润色失败，已用模板文案", icon: "none" });
  } finally {
    regenerating.value = false;
  }
}
```

3. **交互细节**：
   - 润色中按钮文案变为「润色中…」并禁用（防重复提交）；
   - 润色成功埋点 `share_caption_ai`，失败埋点 `share_caption_ai_failed`（复用 `eventLogger`）；
   - 前端所有用户可见文案不出现"AI"字眼（logInfo/logError 事件名保留后端追踪用途）。
