# Step 82：姿态模型获取与随包打包（pose_landmarker_lite.task）

## 一、背景

[75-3](./75-3-MediaPipe姿态推理.md) 已实现 `POST /api/pose/analyze`（33 关键点 + 肘/膝/躯干角），运行依赖 MediaPipe 姿态模型文件，默认路径 `server/models/pose_landmarker_lite.task`（`config.py` 的 `POSE_MODEL_PATH`，见 `server/app/core/config.py:51-54`）。

当前现状：

| 项 | 现状 |
|----|------|
| `server/models/` | 仅 `.gitkeep` 占位，**模型文件缺失**（75-3 按约定不纳入版本管理） |
| 本地开发 | 模型缺失 → `find_model()` 返回 `None` → 姿态接口 503，AI 评分走本地降级 |
| Docker 镜像 | 两个 Dockerfile（`server/Dockerfile`、`server/modelscope/Dockerfile`）均未 `COPY models/` → **生产环境姿态功能不可用** |
| 魔搭部署 | `deploy-modelscope.sh` 的 `FILES_TO_COPY` 不含 `models`；GitHub CI 触发部署时 runner 检出目录也没有模型 |
| 网络可达性 | 生产部署在魔搭（阿里云国内环境），`storage.googleapis.com`（Google 存储）**可能不可达**，构建期/运行期直接 curl 官方源不可靠 |

根因：75-3 已确定"模型随镜像打包"策略，但**获取与打包动作从未落地**。本方案补齐这一环节，使姿态功能在本地开发与生产（魔搭）真正可用。

## 二、目标

1. **获取**：提供可复现的下载脚本 `server/scripts/download-pose-model.sh`，官方源下载 + 环境变量支持国内镜像覆盖，下载后固化 sha256 校验。
2. **隔离**：`server/models/` 整体加入 `server/.gitignore`（保留 `.gitkeep`），模型**不进 GitHub 主仓库**（75-3 约定）。
3. **打包**：两个 Dockerfile 均 `COPY models/ ./models/`，模型随镜像离线打包，构建期零外部依赖。
4. **部署**：`deploy-modelscope.sh` 打包清单增加 `models`；CI/本地部署前若模型缺失自动调用下载脚本（GitHub runner 可达官方源）。
5. **验证**：下载幂等、文件校验、`/api/pose/analyze` 端到端推理通过。

## 三、模型来源

| 项 | 说明 |
|----|------|
| 模型 | MediaPipe Pose Landmarker（BlazePose GHUM 3D，33 关键点），float16 |
| 官方地址 | `https://storage.googleapis.com/mediapipe-models/pose_landmarker/pose_landmarker_lite/float16/1/pose_landmarker_lite.task` |
| 版本路径 | 固定 `float16/1/`（可复现）；`float16/latest/` 为滚动最新（Google AI Edge 官方文档推荐） |
| 体积 | 约 5.7MB |
| 许可 | Apache 2.0（MediaPipe / Google AI Edge） |
| 官方文档 | [Pose landmark detection guide](https://ai.google.dev/edge/mediapipe/solutions/vision/pose_landmarker) |
| 国内可达性 | `storage.googleapis.com` 在国内**不稳定/不可达**；魔搭构建环境禁用外部下载 → 不做构建期/运行期直连官方源 |

**镜像策略**：下载脚本支持 `POSE_MODEL_URL` 环境变量覆盖官方源（可指向 hf-mirror 等国内代理上的副本），本地在国内网络开发时使用；生产仍以"随镜像打包"为准，不依赖任何外部网络。

## 四、方案设计

### 4.1 下载脚本 `server/scripts/download-pose-model.sh`

```
用法：
  bash scripts/download-pose-model.sh              # 默认官方源
  POSE_MODEL_URL=https://... bash scripts/download-pose-model.sh   # 国内镜像
```

行为：

- 目标文件 `$SERVER_DIR/models/pose_landmarker_lite.task`（`$SERVER_DIR` 为脚本上级目录，即 `server/`）；
- **幂等**：目标文件已存在且大小 > 1MB → 打印现有 sha256 并跳过，不重复下载；
- 下载到临时文件后校验：大小 > 1MB + 计算 sha256 与脚本内置固定值比对（首次下载后固化为已知正确值），不匹配则删除并报错退出；
- 完成后打印 sha256，供 `POST /api/pose/analyze` 端到端验证前确认文件完整；
- `set -euo pipefail`，错误码非 0；文件命名唯一（加时间戳），避免半截文件污染目标路径。

### 4.2 版本管理隔离

`server/.gitignore` 追加：

```gitignore
# MediaPipe 姿态模型（约 5.7MB 二进制，不纳入 GitHub 仓库，随镜像打包）
models/
!models/.gitkeep
```

- 仅本地开发 / GitHub runner 上由下载脚本生成，不进主仓库；
- `.gitkeep` 保留，保证 `server/models/` 目录随仓库存在。

### 4.3 Docker 镜像打包

`server/Dockerfile` 与 `server/modelscope/Dockerfile` 均追加（runtime 阶段，在 `COPY scripts/` 之后）：

```dockerfile
# 姿态推理模型（随镜像打包；构建前须存在 server/models/pose_landmarker_lite.task，
# 可用 scripts/download-pose-model.sh 下载。按文件 COPY，缺失时构建失败 → fail-fast）
COPY models/pose_landmarker_lite.task ./models/
```

- **按文件 COPY**（而非整目录 `COPY models/`）：整目录 COPY 在仅剩 `.gitkeep` 时不会失败，无法 fail-fast；按文件 COPY 在模型缺失时构建直接报错 `file not found`；
- 两个 Dockerfile 保持一致性（modelscope 版头部注释已要求"修改本文件请同步考虑根目录 Dockerfile"）；
- 不采用构建期 `ARG + curl` 下载：魔搭（阿里云）构建环境访问 Google 存储不可靠，且多一层网络失败点。

### 4.4 魔搭部署脚本 `deploy-modelscope.sh`

1. **自动下载**：在 `FILES_TO_COPY` 打包前，若 `$SERVER_DIR/models/pose_landmarker_lite.task` 缺失，调用 `bash scripts/download-pose-model.sh`（GitHub Actions runner 可访问官方源；本地手动部署在国内网络下可用 `POSE_MODEL_URL` 覆盖）；
2. **打包清单**：`FILES_TO_COPY` 数组追加 `"models"`，使模型随部署目录 `git add -A` 推送进魔搭创空间仓库（约 5.7MB，远低于魔搭仓库容量限制）；
3. 模型随 studio 仓库存在 → 魔搭侧 Docker 构建时 `COPY models/` 命中本地文件，**构建期/运行期零外部下载**。

> 说明：本地 GitHub 仓库因 `server/.gitignore` 不包含模型，因此**必须**由部署脚本在打包时自动补齐，不能依赖 CI 检出的仓库内容。

### 4.5 其他部署路径

| 路径 | 处置 |
|------|------|
| 本地开发 | `bash scripts/download-pose-model.sh` 后 `uv run uvicorn ...`，姿态接口可用 |
| docker-compose（OCI） | 构建前先跑下载脚本（构建上下文 `server/` 需含 `models/`）；`server/Dockerfile` 已含 `COPY models/` |
| OCI GitHub Actions（停用中） | 同魔搭：runner 上下载模型后随代码打包；`deploy-oci.sh` 待启用时同步 `models` 清单（本次同步魔搭 + 本地脚本，OCI 脚本一并补齐清单，因其为同目录复制逻辑） |

### 4.6 不做的事（范围外）

- **不做运行期动态下载**（`docker-entrypoint.sh` 不增加下载逻辑）：模型缺失时姿态接口按 75-3 既有契约返回 503，AI 侧走本地降级，行为已定义且可接受；
- **不改变 `POSE_MODEL_PATH` 默认值**（`server/models/pose_landmarker_lite.task` 保持），`config_registry.py` 已有该配置项，Admin 可在线覆盖路径；
- **不将模型提交到 GitHub 主仓库**。

## 八、风险与注意事项

| 风险 | 说明与对策 |
|------|-----------|
| 官方源国内不可达 | 本地国内网络用 `POSE_MODEL_URL` 指向镜像；生产以随包打包为准，不依赖外部网络 |
| 模型版本漂移 | 固定 `float16/1/` 路径 + sha256 固化校验；升级时显式更新常量 |
| 魔搭仓库体积 | 5.7MB 单文件远低于仓库限制；后续若换 full/heavy 需重新评估 |
| Docker 构建失败 | 按文件 `COPY models/pose_landmarker_lite.task` fail-fast（整目录 COPY 在仅剩 `.gitkeep` 时不会失败）；Dockerfile 注释说明先跑下载脚本 |
| CI runner 无模型 | 部署脚本打包前自动下载，规避"依赖 CI 检出内容"的坑 |
| 模型被误提交 | `server/.gitignore` 隔离 + 提交前 `git status` 复核 |
