# 微信内容安全API集成

## 问题描述

小程序审核不通过，原因是上传图片视频缺少内容安全检查，违反《微信小程序平台运营规范常见拒绝情形3.2》。

**审核失败原因**：
1. 上传封面功能缺少内容安全验证
2. 需要接入微信内容安全API（`msgSecCheck`/`imgSecCheck`/`mediaCheckAsync`）

**当前状态**：
- 后端 `wx_service.py` 只实现了 `code_to_openid`，没有 `get_access_token` 方法
- 三个上传场景（头像/装备封面/视频）均无内容安全检查
- 装备封面使用 base64 存储，未走文件上传接口

## 微信内容安全API说明

| 接口 | 路径 | 用途 | 限制 |
|------|------|------|------|
| 文本内容安全识别 | `/wxa/msg_sec_check` | 检查文本是否违规 | 4000次/分钟 |
| 图片内容安全识别 | `/wxa/img_sec_check` | 同步检查图片（≤1MB） | 2000次/分钟 |
| 多媒体内容安全识别 | `/wxa/media_check_async` | 异步检查图片/音频/视频（≤10MB） | 2000次/分钟 |

所有接口都需要 `access_token`，有效期2小时。

## 修复方案

### 1. 后端：`wx_service.py` 添加 access_token 获取

```python
_ACCESS_TOKEN_CACHE: dict = {"token": "", "expires_at": 0}

def get_access_token_sync() -> str:
    """同步获取微信 access_token（带缓存，提前5分钟过期）"""
    return _fetch_access_token()

async def get_access_token() -> str:
    """异步版本（内部调用 _fetch_access_token）"""
    return _fetch_access_token()
```

### 2. 后端：新建 `content_security.py` 服务

实现同步 + 异步两套 API 调用（同步版本供 `@audit` 装饰器的同步路由使用）：
- `check_text(content, openid)` → 调用 `/wxa/msg_sec_check`
- `check_image_sync(file_path, openid)` → 调用 `/wxa/img_sec_check`（同步，≤1MB）
- `check_media_sync(file_path, openid, media_type)` → 调用 `/wxa/media_check_async`（异步提交）

### 3. 后端：修改上传路由

**`upload.py`（头像 + 装备封面）**：
- 保存文件后调用 `check_image_sync()`
- 违规则删除文件，返回 400 错误
- 安全检查异常（网络/格式等）也阻断上传

**`video.py`（视频）**：
- 保存文件后调用 `check_media_sync()`（视频类型）
- 异步检查不阻断上传，但记录 trace_id 供后续处理

### 4. 后端：修改 `media.py` 归属校验

`_owned()` 添加 `gears/{user_id}/` 路径支持，否则装备图片 403。

### 5. 前端：修改 `choosePhoto()` 函数

将 base64 方式改为上传到服务器：
- 调用新的 `/api/upload/gear-image` 接口
- 返回服务器相对路径 URL

### 6. 前端：更新装备表单

将 `photo` 字段从 base64 改为 URL：
- 新数据使用服务器URL
- 旧数据兼容 base64 格式（`resolveUploadUrl` 判断前缀）

## 装备图片存储迁移（v1.3.0）

原方案中装备封面使用 base64 存储（`TEXT` 字段），存在：
- 数据库体积膨胀
- 无法走统一的内容安全检查流程
- 与头像/视频的文件上传模式不一致

**迁移方案**：
1. 后端新增 `POST /api/upload/gear-image` 端点，接收图片文件 → 安全检查 → 保存到 `data/gears/{user_id}/` → 返回相对路径
2. `Gear.photo` 字段从 `TEXT` 改为 `VARCHAR(500)`（存 URL，兼容旧 base64 数据）
3. 前端 `choosePhoto()` 改为调用 `uploadGearImage()` 上传到服务器
4. `resolveUploadUrl()` 判断前缀：`/uploads/` → 拼接后端域名，否则视为 base64 直接展示

## 头像安全检查说明

`<button open-type="chooseAvatar">` 使用微信原生头像选择器，其流程为：
1. 用户选择头像 → 微信客户端上传到 `snsuploadsimple`（腾讯服务器）
2. 微信在客户端侧完成内容安全预检
3. 违规图片被微信拦截，返回"无法使用该头像"错误
4. 合规图片返回临时 URL，miniapp 调用 `POST /api/upload/avatar` 保存

**结论**：头像场景由微信内置安全检查覆盖，后端 `upload.py` 的 `imgSecCheck` 作为二次保障。

## 已知问题与修复（v1.1.0）

### 问题 1：安全检查无成功/失败日志

`check_image_sync` 成功时无日志，无法确认微信 API 是否真正被调用。

**修复**：添加成功日志 `logger.info("图片安全检查通过", file_path=file_path)`

### 问题 2：`except Exception` 静默放行

`upload.py` 的 `except Exception` 捕获所有异常后不阻断上传，导致即使安全检查失败也放行。

**修复**：改为 `except Exception as exc: ... raise HTTPException(status_code=400, detail="安全检查失败")`

### 问题 3：`media.py` 不支持 `gears/` 路径

`_owned()` 只校验 `videos/{user_id}/`，装备图片 `gears/{user_id}/` 返回 403。

**修复**：`parts[0] in ("videos", "gears")`

### 问题 4：`@audit` 装饰器未提取 `current_user`

`upload.py` 和 `video.py` 的路由使用 `@audit` 装饰器，但装饰器 `wrapper()` 未从 `kwargs` 提取 `current_user`，导致审计日志 `user_id=None`。

**修复**：`decorators/audit.py` 的 `wrapper()` 中添加 `current_user = kwargs.get("user") or kwargs.get("current_user")`
