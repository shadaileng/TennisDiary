# Pipeline 写表步骤批量插入优化

## 1. 问题背景

线上日志显示 analysis_id=4 的管线总耗时 70.92s，其中**写表步骤耗时 56.50s**，占总耗时的 79.7%。

```
2026-08-31 11:04:51.328 | INFO | pipeline:run_pipeline:209 - 管线-写表耗时: 56.50s
2026-08-31 11:04:51.528 | INFO | pipeline:run_pipeline:225 - 管线完成 analysis_id=4 total=70.92s
```

该分析仅处理 2.345s 视频（裁剪后 2.02s），抽取 7 帧，但生成了 61 帧骨架帧。写表步骤中大量 `file_service:get_or_create_file` 的秒传命中查询是瓶颈根因。

## 3. 根因分析

### 3.1 当前调用链路

```
_write_pose_result()
  └─ for frame_path in skeleton_frames:   # 61 帧循环
       └─ with self.db.begin_nested():    # 每帧一个 savepoint
            └─ file_service.get_or_create_file()
                 ├─ compute_md5_from_path()     # 磁盘读 + MD5 计算
                 ├─ os.path.getsize()            # 磁盘 stat
                 ├─ SELECT WHERE md5=...         # 查询 1：MD5 去重
                 ├─ ensure_unique_name()         # 查询 2：original_name 唯一
                 ├─ db.add() + db.flush()        # 插入 + flush
                 └─ savepoint COMMIT/RELEASE     # 隐式提交
```

### 3.2 每帧 DB 操作开销

| 操作 | 次数 | 单次耗时（网络存储） |
|------|:----:|:-------------------:|
| `begin_nested()` savepoint 开启 | 1 | ~120ms |
| `compute_md5_from_path` + `os.path.getsize` 磁盘读 | 2 | ~10ms |
| SELECT md5 去重查询 | 1 | ~120ms |
| `ensure_unique_name` 查 original_name | 1 | ~120ms |
| `db.flush()` | 1 | ~120ms |
| savepoint 结束 COMMIT/RELEASE | 1 | ~120ms |
| **合计** | **7** | **~610ms** |

### 3.3 总开销估算

61 帧 × 610ms/帧 ≈ **37.2s**（与日志 56.5s 吻合，差异来自磁盘 I/O 抖动）

## 4. 优化方案

### 4.1 核心思路

**预计算 MD5/size + 批量插入 + 合并 commit**

1. **预计算前移**：在 `pose_service` 生成骨架帧时计算 MD5/size，写表阶段零磁盘 I/O
2. **批量去重**：一次性 `SELECT WHERE md5 IN (...)` 找出已有记录
3. **批量插入**：`bulk_save_objects()` 一次性创建所有新记录
4. **合并提交**：骨架帧/视频/封面 + Analysis 更新合并为一次 commit

### 4.2 改动文件

| 文件 | 改动内容 |
|------|---------|
| `server/app/services/file_service.py` | 新增 `batch_get_or_create_files()` |
| `server/app/services/pose_service.py` | 骨架帧写入磁盘时预计算 MD5/size 并返回 |
| `server/app/services/pipeline.py` | `_write_pose_result()` 改为批量模式 + 合并 commit |

#### 4.3.2 `file_service.py` 新增批量函数

```python
def batch_get_or_create_files(
    db: Session,
    user_id: int,
    files: list[dict],  # [{rel_path, md5, size, upload_source}, ...]
    business_type: str | None = None,
    business_id: int | None = None,
) -> list[File]:
    """批量登记文件：一次查询 MD5 + original_name，一次 bulk insert

    files: 预计算结果列表，每项包含 rel_path, md5, size, upload_source
    注意：调用方必须确保 md5/size 已预计算，本函数不做任何磁盘读取
    """
    if not files:
        return []

    # 1. 批量查询已有 MD5 记录（一次查询）
    all_md5s = [f["md5"] for f in files if f.get("md5")]
    existing_map = {}
    if all_md5s:
        existing_records = (
            db.query(File)
            .filter(
                File.user_id == user_id,
                File.md5.in_(all_md5s),
                File.deleted_at.is_(None),
                File.ref_count > 0,
            )
            .all()
        )
        for rec in existing_records:
            existing_map[rec.md5] = rec

    # 2. 批量预查询 original_name 唯一性（避免逐条查询）
    existing_names = set()
    if files:
        candidate_names = [os.path.basename(f["rel_path"]) for f in files]
        existing_names = set(
            row[0]
            for row in db.query(File.original_name)
            .filter(
                File.original_name.in_(candidate_names),
                File.deleted_at.is_(None),
            )
            .all()
        )

    # 3. 构建新记录列表
    new_records = []
    name_counter: dict[str, int] = {}  # 跟踪同名文件的后缀计数
    for info in files:
        md5 = info.get("md5")
        if not md5:
            continue

        existing = existing_map.get(md5)
        original_name = os.path.basename(info["rel_path"])
        base, ext = os.path.splitext(original_name)

        # 生成唯一名称（批量模式，内存内计算）
        unique_name = original_name
        if original_name in existing_names:
            counter = name_counter.get(original_name, 1)
            while f"{base}_{counter}{ext}" in existing_names:
                counter += 1
            unique_name = f"{base}_{counter}{ext}"
            name_counter[original_name] = counter + 1
        existing_names.add(unique_name)

        if existing:
            # 秒传：复用路径
            new_record = File(
                user_id=user_id,
                md5=md5,
                original_name=unique_name,
                rel_path=existing.rel_path,
                size_bytes=existing.size_bytes,
                mime_type=existing.mime_type,
                upload_source=info["upload_source"],
                business_type=business_type,
                business_id=business_id,
                ref_count=1,
                created_at=time.time(),
            )
            existing.ref_count += 1
        else:
            # 正常上传
            new_record = File(
                user_id=user_id,
                md5=md5,
                original_name=unique_name,
                rel_path=info["rel_path"],
                size_bytes=info.get("size", 0),
                upload_source=info["upload_source"],
                business_type=business_type,
                business_id=business_id,
                ref_count=1,
                created_at=time.time(),
            )
        new_records.append(new_record)

    # 4. 批量插入 + 单次 flush
    if new_records:
        db.add_all(new_records)
        db.flush()

    return new_records
```

#### 4.3.3 `pipeline.py` 改为批量模式 + 合并 commit

```python
def _write_pose_result(self, pose_result: dict) -> None:
    """写入姿态结果到数据库（零磁盘 I/O，单次 commit）"""
    if not (self.analysis_id and pose_result):
        return

    from app.services import file_service

    skeleton_frames = pose_result.get("skeleton_frames") or []
    skeleton_video = pose_result.get("skeleton_video_info")
    skeleton_thumb = pose_result.get("skeleton_thumb_info")
    user_id = self._get_user_id()

    # 批量登记所有文件（骨架帧 + 视频 + 封面）
    # pose_service 已返回包含 upload_source 的预计算结果
    all_files = list(skeleton_frames)
    if skeleton_video:
        all_files.append(skeleton_video)
    if skeleton_thumb:
        all_files.append(skeleton_thumb)

    if all_files:
        try:
            file_service.batch_get_or_create_files(
                db=self.db,
                user_id=user_id,
                files=all_files,
                business_type="analysis",
                business_id=self.analysis_id,
            )
        except Exception as exc:
            log.warning(
                "文件批量登记失败(非致命): %s - %s",
                type(exc).__name__,
                str(exc)[:120],
            )

    # 单次提交：文件登记 + Analysis 更新
    stmt = (
        sa_update(Analysis)
        .where(Analysis.id == self.analysis_id)
        .values(
            pose=json.dumps(pose_result, ensure_ascii=False),
            thumb=skeleton_thumb["rel_path"] if skeleton_thumb else None,
        )
    )
    self.db.execute(stmt)
    self.db.commit()
```

#### 4.4.1 `ensure_unique_name` 添加 `deleted_at` 过滤

```python
# 优化前
def ensure_unique_name(db: Session, user_id: int, original_name: str) -> str:
    base, ext = os.path.splitext(original_name)
    candidate = original_name
    counter = 1
    while (
        db.query(File)
        .filter(File.original_name == candidate)  # 未过滤已删除记录
        .first()
    ):
        candidate = f"{base}_{counter}{ext}"
        counter += 1
    return candidate

# 优化后
def ensure_unique_name(db: Session, user_id: int, original_name: str) -> str:
    base, ext = os.path.splitext(original_name)
    candidate = original_name
    counter = 1
    while (
        db.query(File)
        .filter(
            File.original_name == candidate,
            File.deleted_at.is_(None),  # 新增：只查未删除记录
        )
        .first()
    ):
        candidate = f"{base}_{counter}{ext}"
        counter += 1
    return candidate
```

### 4.5 预期收益

| 指标 | 优化前 | 优化后 | 提升 |
|------|--------|--------|------|
| DB round-trip | ~427 次（61帧×7） | ~3 次 | **99.3%** |

### 4.6 风险评估

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 批量插入中单条失败导致全部回滚 | 高 | `batch_get_or_create_files` 内部保留逐条容错 |
| MD5 批量查询结果过大 | 低 | 骨架帧 MD5 几乎不重复，实际结果集很小 |
| `ensure_unique_name` 批量场景下的并发冲突 | 低 | 骨架帧文件名由系统生成，无并发冲突 |
