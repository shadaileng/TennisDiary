# 99：电子教练时间轴多段剪辑

## 一、背景与目标

### 1.1 现状问题

小程序端电子教练（`pages/coach/analyze.vue`）上传视频后**整片直传**：
- 服务端 `process_video` 对上传视频整体做时长校验（原 single ≤ 15s / full ≤ 90s），超长直接拒绝，用户只能先到系统相册裁短再选
- 长视频里的多余片段无法去掉，也无法从一条对拉视频里挑多个挥拍/回合拼接分析
- 端上无法本地抽帧（微信无该 API），时间轴缩略图胶片带不可行

### 1.2 目标

1. 小程序端提供**时间轴剪辑**：双指捏合缩放 + 纵向分区手势（上拖播放头/下拖平移）+ 播放头逐帧预览 + 多段起止标记
2. 片段约束在端上与后端**双重校验**：按序、不重叠、单段 ≥ 0.6s、总长 ≤ 整片上限
3. 服务端用 ffmpeg **裁切并拼接**为单 mp4 后再抽帧，下游（报告视频/骨架视频/帧率适配）零改动
4. 整片上传上限 180s（3 分钟），single/full 不再按模式额外收紧时长

## 二、约束与语义

| 项 | 值 | 说明 |
|---|---|---|
| 上传整片上限 | 180 s | 超长须先在相册裁剪 |
| 选择器 `maxDuration` | **不传** | 微信 `chooseVideo` 硬上限 60s，传入会前置报错（`maxDuration can not over 60`）；180s 由选后预检查 + 服务端校验兜底 |
| 片段总长上限 | 与整片一致（180s，不分模式） | 拼接后时长；single 15s / full 90s 已解除 |
| 段数上限 | single 1 / full 8 | — |
| 单段最短 | 0.6 s | — |
| 段约束 | 按 start 升序、不重叠（可相切）、`[start,end) ⊆ [0,duration]` | 服务端权威校验 |
| `hit_time` | **拼接后相对时间** | 客户端按片段前缀长度换算 |

## 三、实现设计

### 3.1 后端：多段裁切拼接 + 整片上限

`server/app/services/video_service.py`：

- 新增 `_UPLOAD_MAX_DURATION = 180.0`、`_MIN_SEGMENT_LEN = 0.6`、`_MAX_SEGMENTS = {single:1, full:8}`、`InvalidCutError`
- `validate_cuts(cuts, mode, duration)`：片段数上限 → 排序 → 单段范围/最短时长 → 重叠校验 → 拼接总长校验
- `trim_video(src, dst, start, length)`：**输出端 seek**（`-ss` in 之后）+ libx264 重编码（yuv420p + faststart），音频 `-c:a copy` 失败兜底 `-an`
- `trim_and_concat(src, cuts, mode)`：逐段裁切命名 `{base}_seg{i}.mp4` → 单段直接返回 / 多段 concat demuxer `-c copy`，失败降级重编码拼接 → 清理临时产物
- `process_video(path, mode, hit_time, cuts=None)`：整片 ≤180s 校验 → 提供 cuts 时先裁剪拼接、删除原片、重探测产物时长/帧率 → 后续流程不变；返回新增 `trimmed`、`segments`

`server/app/routers/video.py`：新增 `cuts: str | None` 表单字段（JSON 数组），`JsonDecodeError`/`InvalidCutError` → 400，`FfmpegUnavailableError` → 503。

### 3.2 前端：手写触摸时间轴（`analyze.vue`）

`movable-view` 不支持多指捏合，故手写 `@touchstart/@touchmove/@touchend`：

- **坐标模型**：`barWidth`/`barLeft`/`barTop`/`barHeight` 用 `createSelectorQuery().boundingClientRect` 测量；时间窗 `[viewStart, viewStart+visibleSpan]` ↔ 像素，`t2x`/`x2t` 互转；`clampViewStart` 统一夹紧可见窗（全览时归 0）
- **双指捏合缩放**：`touches.length ≥ 2` 时按两指距离比例缩放 `visibleSpan`（最小 2s），以播放头为锚点滚动 `viewStart`
- **播放头逐帧预览**：时间轴**纵向分区**——上半区域（`touch.clientY < barTop + barHeight/2`）单指拖动 → `x2t` 映射秒 → 节流（50ms）`videoCtx.seek(t)` 实时预览 + 拖到窗口边缘自动滚窗；`@loadedmetadata` 就绪后重绑 video 上下文 + seek 后暂停态 `play()/pause()` 强制刷新帧（模拟器/真机通用），松手 `flushPlayhead` 补最后一帧
- **平移视野（放大后浏览）**：下半区域单指拖动 → `Δx/barWidth × visibleSpan` 仅滚动 `viewStart`，**播放头时间不变不 seek**；双指抬指剩单指时按剩余手指 y 重新分区；**点击片段色块** → `centerOnSegment` 视野居中该片段并预览中点帧
- **多段标记**：`➕起点` 在播放头开段（须晚于上一段终点）→ 移动 → `✋终点` 闭合（≥0.6s、总长 ≤ 上限校验）；片段色块+序号、点击 ✕ 删除、重置按钮；single 限 1 段
- **击球瞬间换算**：`captureHitTime` 将原始时间按片段前缀换算为**拼接后相对时间**（`toConcatTime`），落在片段间隙则忽略并提示
- **上传统一**：存在片段时 `formData.cuts = JSON.stringify(cuts)`；无片段整片直传（兼容旧逻辑）。`startAnalysis` 前端预检查：整片未裁剪且时长超 `modeLimit`（或时长未加载）时拦截并引导到时间轴裁剪，避免整片直传撞上后端超限报错；后端超限兜底消息附「请在时间轴选择片段」引导

### 3.3 类型适配

- `miniapp/src/types/index.ts`：`VideoUploadResult` 增加 `trimmed?`、`segments?`
- `miniapp/src/services/data.ts`：`uploadVideo` 的 `formData` 增加 `cuts?: string`

## 五、交互优化（v1.1.0 / v1.2.0）

### 5.1 优化背景

原时间轴采用**播放头移动 + 纵向分区**交互模式：
- 上半区拖动移动播放头（scrub）
- 下半区拖动平移视野（pan）
- 缩放以播放头为锚点

此模式存在以下问题：
- 用户需要记忆分区规则（上拖/下拖），学习成本高
- 播放头位置不直观，需要视觉追踪
- 起始/结束点只能靠按钮设置，无法直观拖拽

### 5.2 v1.1.0：固定播放头 + 拖动时间轴

**核心改变**：播放头固定在时间轴中间（50% 位置），拖动时间轴时视野移动，播放头不动。

| 交互 | 行为 | 说明 |
|------|------|------|
| 单指拖动 | 平移视野 | 播放头始终在中间，时间 = `viewStart + visibleSpan / 2` |
| 双指缩放 | 以中间为锚点 | 播放头位置不变，视野大小变化 |
| 点击片段色块 | 居中片段 | 将片段中点移到播放头位置 |

### 5.3 v1.2.0：剪映式轨道 + 可拖起止把手

**核心改变**：彻底重构为完整长度的视频轨道（像素/秒 = pps 可缩放的 pps 模型），播放头固定在容器中间，轨道可左右拖动选帧；轨道起止两侧有可拖把手，直接对齐中线即设置起止帧。

#### 5.3.1 pps 坐标模型

```typescript
const pps = ref(TRACK_PPS);            // 每秒像素（80px/s，可缩放）
const playhead = ref(0);                // 播放头时间（秒），固定在容器中间
const trackOffset = computed(
  () => barWidth / 2 - playhead * pps,  // 轨道偏移，始终使播放头居中
);
// 时间 t 的容器内像素位置
const containerX = (t) => barWidth / 2 + (t - playhead) * pps;
// 位置换算
const x2t = (x) => playhead + (x - barWidth / 2) / pps;
```

缩放范围：`pps ∈ [barWidth/duration（全览）, barWidth/MIN_ZOOM_SPAN（2s 满屏）]`，以播放头为锚点。

#### 5.3.2 交互设计（v1.3.0）

| 交互 | 行为 | 说明 |
|------|------|------|
| 拖动轨道 | 改变播放头帧 | `playhead -= dx / pps`，节流 seek 视频预览 |
| 双指缩放 | 改变 pps | 手指张开 → 放大（pps 增大），播放头帧不变 |
| **放大按钮 ＋** | 时间轴上方控件 | 透明背景，`pps × 1.5`，clamp 至 `[minPps, maxPps]` |
| **缩小按钮 −** | 时间轴上方控件 | 透明背景，`pps ÷ 1.5`，clamp 至 `[minPps, maxPps]` |
| **设置起点**按钮 | 起始帧 = 播放头帧 | 无片段时创建 `[t, duration]`，有片段时调整首段起点 |
| **设置终点**按钮 | 结束帧 = 播放头帧 | 无片段时创建 `[0, t]`，有片段时调整首段终点 |
| 点击片段色块 | 播放头跳到片段中点 | 便于快速定位某段 |

**v1.3.2 多段剪辑流程**：
- 点击「设置起点」→ 开新段（`pendingStart = playhead`），轨道上显示橄榄绿竖线 + ▶ 标记
- 点击「设置终点」→ 闭合当前段（`segments.push({start: pendingStart, end: playhead})`），清空 pendingStart
- 按钮文字动态变化，视觉反馈清晰
- full 模式最多 8 段，single 模式仅 1 段且已有片段时禁止新开段
- 开放中的段可跨多次拖动操作完成，不受片段顺序限制

**v1.3.1 击球瞬间自动跟随**：
- 用 `watch(playhead, ...)` 监听播放头变化，自动调用 `toConcatTime` 转换为拼接后相对时间
- 播放头落在片段内 → 自动设置击球瞬间；不在片段内 → 自动清除
- 按钮改为「清除击球瞬间」，用于清空已设时间

**v1.3.0**：移除左右起止把手（不再支持拖把手调节范围），起止帧均通过「设置起点/设置终点」按钮在播放头帧处设定；时间轴上方新增透明背景的放大（＋）/缩小（−）控件（×1.5 步进），取代单一依赖双指缩放。

**核心流程**：
1. 拖动轨道预览帧（播放头帧随动节流刷新视频画面）
2. 拖动手柄到中线对齐起始帧 / 结束帧（6px 内吸附）
3. 或拖动到目标帧后点「设置起点 / 设置终点」按钮
4. 片段色块实时显示裁剪范围，左右把手不可交叉（最短 0.6s）

#### 5.3.3 时间刻度

时间刻度固定在容器上方，刻度位置 = `containerX(t)`，以播放头为时间参考（播放头刻度恒居中），随拖动态实时移动。
