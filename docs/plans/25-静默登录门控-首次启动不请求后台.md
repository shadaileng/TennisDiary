# Step 25：静默登录门控 — 首次启动不请求后台

## 一、背景与问题

现状：`auth` store 的 `ensureLogin()` 在无 token 时**无条件**走 `wx.login` → 后端 `/api/auth/login` → `/api/auth/me` 全链路，`App.onLaunch` 每次启动都会调用。首次安装启动（从未登录）也会立刻请求后台并自动创建用户。

目标：增加「曾登录」状态记录，**只有曾登录过的用户**启动时才触发静默登录；首次启动（从未登录）不请求后台，等待用户后续手动登录（登录入口另行设计）。

## 二、决策记录

| 决策点 | 结论 |
|---|---|
| 状态载体 | 新增 storage 键 `td_has_logged_in`（`STORAGE_KEYS.hasLoggedIn`），与 `td_token` / `td_user` 平级收口在 `constants/storage.ts` |
| 登出语义 | `logout()` **清除** `hasLoggedIn` → 登出后下次启动不再自动登录，需用户再次手动登录（用户已确认） |
| 登录入口 | 本次**仅做门控**，手动登录入口（如 mine 页登录按钮）后续另行设计（用户已确认） |
| 门控位置 | `ensureLogin()` 前置判断；`App.vue` 仍调 `ensureLogin()`，逻辑内聚在 store |
| 401 与标志关系 | `request.ts` 的 401 清 token 不涉及本标志；token 过期被清后标志仍为 true，下次启动可静默续签，符合预期 |

## 三、技术方案

### 3.1 `miniapp/src/constants/storage.ts`

```ts
export const STORAGE_KEYS = {
  token: "td_token",
  user: "td_user",
  hasLoggedIn: "td_has_logged_in",   // 新增：是否曾登录
  settings: "td_settings",
} as const;
```

### 3.2 `miniapp/src/stores/auth.ts`

- `state` 新增 `hasLoggedIn: boolean`（默认 `false`）
- `init()`：从 storage 恢复 `hasLoggedIn`
- `login()`：显式登录成功后 `setAuth`，置 `hasLoggedIn = true` 并 `setStorageSync`
- `ensureLogin()` 门控：
  ```ts
  async ensureLogin() {
    if (this.isLoggedIn) return;      // 已有 token
    if (!this.hasLoggedIn) return;    // 从未登录过 → 不请求后台
    try {
      await this.login();
    } catch (e) { /* 原逻辑：提示 + logout */ }
  }
  ```
- `logout()`：清除 `hasLoggedIn`（同时清 token / user 及对应 storage）

### 3.3 `miniapp/src/App.vue`

保持 `onLaunch` 调用 `ensureLogin()`，更新注释说明门控行为。
