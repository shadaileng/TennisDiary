# 100：hit_time 裁剪后时间基准修复

## 问题描述

电子教练分析流程中，用户选择裁剪片段后上传视频，姿态检测返回 200 但骨骼视频未生成。只有 1 个骨架帧（应有 7 个），`skeleton_video_url` 为 null。

## 根因分析

### 时间基准不一致

| 角色 | hit_time 基准 | 示例值 |
|------|--------------|--------|
| 小程序端 | 原始视频绝对时间 | 14.97s |
| 后端 `build_sampling_times` | 裁剪后视频相对时间 | 应为 1.1s |

### 数据流

```
用户选择原始视频 (121.12s)
  → 设置裁剪段 [{start:13.87, end:16.07}]
  → 设置击球点 hitTime = 14.97s (原始视频绝对时间)
  → formData.hit_time = "14.97"
  → 后端 process_video:
      duration = probe_duration(裁剪后) = 2.22s
      times = build_sampling_times('single', 2.22, 14.97)
        hit = min(max(0.01, 14.97), 2.1) = 2.1  ← 被 clamp！
        times = [1.5, 1.75, 1.95, 2.1, 2.1, 2.1, 2.1]
```

### 后果

采样点集中在 [1.5, 2.1]（视频末尾），如果人物动作不在此时段，MediaPipe 检测不到姿态，骨架帧为 0 或 1。

## 证据

| id | video_url | cuts | skeleton_frames | 说明 |
|----|-----------|------|-----------------|------|
| 6 | c6e2c4a5.mp4 | 无 | 7 | 正常 |
| 7 | da3f2e89.mp4 | 无 | 7 | 正常 |
| 8 | dbcca0e5_seg0.mp4 | [{start:13.87, end:16.07}] | 1 | 异常 |

## 修复方案

### 后端修复（主方案）

在 `process_video` 中，裁剪后自动将 `hit_time` 转换为相对时间：

```python
# video_service.py process_video()
if cuts and hit_time is not None:
    hit_time = hit_time - cuts[0]['start']  # 绝对时间 → 裁剪后相对时间
```

### 前端修复（兼容性加固）

确保前端传递的 `hit_time` 始终是相对于原始视频的时间（当前行为已正确），后端负责统一处理。

## 影响范围

- 仅影响有裁剪的视频上传场景
- 无裁剪时 `cuts` 为 None，不触发转换
- 向前兼容：旧数据无影响
