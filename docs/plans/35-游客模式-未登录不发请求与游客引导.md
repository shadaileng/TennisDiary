# Step 35：游客模式 — 未登录不发请求与游客引导

## 一、背景

### 1.1 问题现象

未登录状态下，点击各个 tab 页面仍会请求后台。排查确认根因如下：

1. **启动时无条件静默登录**：`App.vue` 的 `onLaunch` 调用 `auth.ensureLogin()`，只要 `hasLoggedIn`（`td_has_logged_in`）为 true，就会自动执行 `wx.login` → `POST /api/auth/login` → `getMe()` → `setAuth()` 把 token 写回 storage。
2. 于是"用户以为未登录"，实际静默登录已自动填充 token，各 tab 页 `onShow` 里的 `fetchList()`/`getStats()` 都能正常请求后台。
3. 请求层的本地短路（`request.ts` 第 94-97 行：`auth && !getToken()` 直接 reject）只在**确实无 token** 时生效，被静默登录"绕过"了。

### 1.2 参考方案：tarot 项目的处理模式

参考仓库 [shadaileng/tarot](https://github.com/shadaileng/tarot)，其处理模式为：

| 维度 | tarot 的做法 |
|---|---|
| 启动时 | **不主动静默登录**。`onLaunch` 仅用 `isLoggedIn()` 检查本地 token，有效则已登录，无效则标记为「游客模式」，打印日志区分 |
| 登录态判断 | `isLoggedIn()` = **token 存在** 且 **JWT `exp` 未过期**（前端解析 JWT payload 判断） |
| 静默登录触发 | **被动触发**：仅在接口返回 401 时通过 `onUnauthorized` 回调自动重登，配合 `isRefreshing` 锁防并发 |
| 请求层 | 无本地短路，无 token 直接发请求，靠后端 401 兜底 |
| 游客可用性 | 核心功能依赖本地存储，游客也可用，登录态只影响云端同步等 |

### 1.3 目标

将 Tennis Diary 改造为参考 tarot 的**游客模式**：

- 未登录即为游客，**启动时不再自动静默登录填充 token**；
- 游客态下点击各 tab，业务接口**不发请求后台**，页面展示游客引导；
- 登录态判断基于 **token 有效性**（而非 `hasLoggedIn` 标志）。

### 1.4 与当前实现的差异

| 维度 | 当前实现 | 本方案（游客模式） |
|---|---|---|
| 启动时 | `ensureLogin()` 无条件静默登录 | 仅恢复登录态，不主动登录 |
| 登录判断 | `hasLoggedIn` 标志（曾登录） | token 有效（存在且未过期） |
| 游客身份 | 无明确概念 | 明确 `isGuest` 游客态 |
| 未登录点 tab | 静默登录已填充 token，能请求 | 不发请求，展示游客引导 |
| 请求层 | 保留本地短路 | 保留本地短路（兜底） |
| 静默续登 | 启动时主动 | 移除（或改由 401 被动触发） |

## 二、决策记录

| 决策点 | 结论 | 说明 |
|---|---|---|
| 登录态判断依据 | **token 存在且未过期**，放弃 `hasLoggedIn` 标志 | 参考 tarot 的 `isLoggedIn()`。后端 JWT 目前由 `python-jose` 签发，payload 仅 `{"sub": openid}` **无 `exp` 字段**，故前端解析时对无 `exp` 的 token 视为未过期（宽松处理，与 tarot `isTokenExpired` 逻辑一致） |
| 启动时静默登录 | **移除 `auth.ensureLogin()`**，`onLaunch` 仅 `init()` 恢复登录态 | 未登录即真游客，不主动打后台。`ensureLogin` 保留但改为「仅在已有有效 token 时续期」或不调用 |
| `hasLoggedIn` 标志 | **废弃**，不再作为登录判断；`logout()` 时一并清除 | 保留 storage 键以兼容旧数据清理，但业务逻辑不再依赖 |
| 请求层 | **保留 request.ts 本地短路**（`auth && !getToken()` reject） | 比 tarot「直接发请求靠 401」更省流量；游客不发请求是 Step 33 已有能力，继续沿用 |
| 业务页游客引导 | 各 tab 页 `onShow` 先判断 `isLoggedIn`，未登录不发请求并展示**游客空态** | 复用现有 `Empty` 组件，引导跳转「我的」页登录 |
| 游客访问范围 | 业务页（日记/装备/统计）游客展示空态；「我的」页展示登录入口 | 与 tarot「游客可用本地功能」不同：Tennis Diary 数据全在云端，游客无法使用核心功能，故只做引导 |
| 401 处理 | 保留现有：清凭证 + `promptLogin()` 引导 | 后续可选扩展「401 被动静默重登」（本期不做） |

## 三、技术方案

### 3.1 `miniapp/src/utils/jwt.ts`（新增）— JWT 解析与过期判断

参考 tarot `token.ts` 的 `isTokenExpired`，新增工具，兼容微信小程序环境（无 `atob`，需自实现 base64url 解码）：

```ts
/**
 * 解码 JWT payload（微信小程序无 atob，自行实现 base64url 解码）。
 * 解析失败返回 null。
 */
export function decodeJwtPayload(token: string): Record<string, unknown> | null {
  try {
    const [, payload] = token.split(".");
    if (!payload) return null;
    // base64url → base64
    let b64 = payload.replace(/-/g, "+").replace(/_/g, "/");
    const pad = b64.length % 4;
    if (pad) b64 += "=".repeat(4 - pad);
    // base64 → 二进制 → 按 UTF-8 解码
    const binary = uni.base64ToArrayBuffer(b64);
    const bytes = new Uint8Array(binary as ArrayBuffer);
    let str = "";
    for (let i = 0; i < bytes.length; i++) str += String.fromCharCode(bytes[i]);
    return JSON.parse(str);
  } catch {
    return null;
  }
}

/**
 * 判断 token 是否已过期。
 * - 无 exp 字段 → 视为未过期（宽松处理，兼容当前后端无 exp 的 token）
 * - 有 exp 字段 → `Date.now() >= exp * 1000` 即为过期
 * - 解析失败 → 视为过期（安全失败）
 */
export function isTokenExpired(token: string): boolean {
  const payload = decodeJwtPayload(token);
  if (!payload) return true;
  const exp = payload.exp as number | undefined;
  if (typeof exp !== "number") return false;
  return Date.now() >= exp * 1000;
}

/** 是否已登录：token 存在且未过期 */
export function isLoggedIn(token: string): boolean {
  if (!token) return false;
  return !isTokenExpired(token);
}
```

> 注：若后续后端 JWT 补充 `exp` 字段（`python-jose` 签发时传入 `expires_delta`），本逻辑自动生效，无需改动前端。

### 3.2 `miniapp/src/stores/auth.ts` — 游客态改造

- **移除 `hasLoggedIn` 作为登录依据**：`isLoggedIn` getter 改为基于 token 有效性（调用 `isLoggedIn(token)` 工具）。
- **新增 `isGuest` getter**：`!isLoggedIn`，供页面判断游客态。
- **`init()`**：恢复 token 后即完成，不再读 `hasLoggedIn`。
- **`ensureLogin()`**：改为**仅在本地已有有效 token 时才续期**（参考 tarot 被动续登）；从未登录/已登出则直接返回，不发请求。若本期选择彻底不续登，也可在 `App.vue` 直接不调用。

```ts
import { isLoggedIn as isTokenValid } from "@/utils/jwt";

getters: {
  /** 是否已登录：本地 token 有效（存在且未过期） */
  isLoggedIn: (state): boolean => isTokenValid(state.token),
  /** 是否为游客：未登录或 token 已失效 */
  isGuest: (state): boolean => !isTokenValid(state.token),
}

async ensureLogin() {
  // 已有有效 token 直接返回；无有效 token 则不静默登录（游客态）
  if (this.isLoggedIn || !this.token) {
    return;
  }
  try {
    await this.login();
  } catch (e) {
    console.error("静默登录失败", e);
    this.logout();
  }
}
```

- `setAuth` / `logout`：仍持久化/清除 token 与 user；`logout` 额外清除 `HAS_LOGGED_IN_KEY`（清理旧数据，逻辑不再依赖）。

### 3.3 `miniapp/src/App.vue` — 移除无条件静默登录

`onLaunch` 改为仅恢复登录态，不再主动触发登录：

```ts
onLaunch(() => {
  // 恢复持久化的登录态与偏好设置；不主动静默登录，未登录即为游客
  const auth = useAuthStore();
  auth.init();
  useSettingsStore().init();
  // auth.ensureLogin();  // 移除：未登录不请求后台，保持游客态
  console.log("App Launch");
});
```

### 3.4 各业务页 — 游客不发请求 + 游客空态

在 `diary.vue` / `gear.vue` / `stats.vue` 的 `onShow` 中，**先判断游客态**，未登录则不发请求并展示游客空态：

```ts
import { useAuthStore } from "@/stores";
const authStore = useAuthStore();

onShow(() => {
  // 游客态：不发请求，展示游客空态
  if (authStore.isGuest) {
    diaryStore.setDiaries([]); // 清空，避免残留上一账号数据
    return;
  }
  diaryStore.fetchList();
});
```

Template 侧新增游客空态（复用 `Empty`），引导跳转「我的」页：

```html
<view v-if="authStore.isGuest">
  <Empty
    icon="🔒"
    text="登录后即可记录与同步网球数据"
    button-text="去登录"
    @action="goMine"
  />
</view>
<template v-else>
  <!-- 原业务内容 -->
</template>
```

```ts
function goMine() {
  uni.switchTab({ url: "/pages/mine/mine" });
}
```

> `stats.vue` 同理：`onShow` 中游客态跳过 `weightStore.fetchList()` 与 `getStats()`。

### 3.5 请求层兜底（保留）

`request.ts` 的未登录本地短路（第 94-97 行）**保持不变**，作为游客态的最后兜底（即便某处遗漏判断，也不会真正打到后台）。
