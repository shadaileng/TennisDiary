# Step 109：文件管理系统

## 一、目标

建立统一文件管理系统，将所有上传文件纳入数据库管理，提供：
1. **File 数据模型**：记录每个文件的元信息（路径、大小、MIME、MD5、原始文件名、所属用户/业务、上传时间、引用计数）
2. **MD5 校验**：上传时计算文件 MD5，用于重复检测和秒传
3. **秒传**：MD5 相同的物理文件只存一份，但每次业务引用创建独立 File 记录
4. **上传前置注册**：先创建 File 记录（含 MD5），再写入物理文件，确保记录完整性
5. **引用计数**：记录每个物理文件被引用的次数，用于判断是否可安全删除
6. **软删除**：业务记录删除时，File 标记 `deleted_at`，引用归零的物理文件自动清理
7. **Admin 文件管理 API**：列表查询、批量删除、文件详情、统计聚合
8. **Admin 前端文件管理页**：可视化文件列表，支持筛选、删除

## 二、现状问题分析

### 2.1 当前文件引用方式

| 业务模型 | 文件字段 | 路径示例 |
|---------|---------|---------|
| `User.avatar_url` | String(512) | `avatars/1/<uuid>.jpg` |
| `Gear.photo` | Text | `gears/1/<uuid>.jpg` |
| `Analysis.thumb` | Text (nullable) | `videos/1/<base>_f0.jpg` |

- 归属校验分散且不完整（`files.py` 只校验 Gear.photo，`media.py` 靠路径前缀）
- 无秒传能力，相同文件重复上传会重复存储

## 三、设计方案

### 3.1 核心设计原则

**物理文件去重 + File 记录独立**：
- 每次业务引用都创建**独立的 File 记录**（含原始文件名、业务类型、业务 ID）
- 若检测到 MD5 重复（秒传），**物理文件**复用已有路径（不写新文件），但 File 记录仍然独立
- `ref_count` 表示**该物理文件被多少条 File 记录引用**
- 删除业务时：删除对应的 File 记录，对应物理文件的 `ref_count -= 1`，归零才考虑清理

**约束设计**：
- 唯一约束 `(user_id, original_name)`：同一用户不允许两个文件同名
  - 冲突处理：上传端点生成重命名后缀（`abc.jpg` → `abc_1.jpg`），**不依赖数据库阻拦**
- **不设** `(user_id, md5)` 唯一约束：同用户重复上传同一文件应创建独立记录（秒传基础）

**优势**：
- 每次业务引用都有独立 File 记录（便于追溯）
- 相同内容的物理文件只存一份（节省磁盘）
- 删除业务只删自己的 File 记录，不影响其他引用

    business_id = Column(Integer, nullable=True, index=True)         # 业务记录 ID

    created_at = Column(Float, default=0)                            # 上传时间戳

    # 唯一约束：同用户不允许两个文件同名（冲突时上传端点重命名，不依赖数据库阻拦）
    # 不设 (user_id, md5) 约束：同用户重复上传同一文件应创建独立记录（秒传基础）

### 3.3 上传注册流程（前置注册 + 秒传）

**前置注册模式**：所有上传端点采用"先建记录，再写文件"流程：

```
接收文件 → 计算 MD5 → 查询秒传 → 创建/更新 File 记录 → 写物理文件 → 提交事务
```

**秒传检测逻辑**：
```python
def get_or_create_file(
    db: Session,
    user_id: int,
    md5: str,
    rel_path: str,
    upload_source: str,
    original_name: str = "",
    size_bytes: int = 0,
    mime_type: str = "",
) -> tuple[File, bool]:
    """获取或创建 File 记录（秒传主入口）
    
    返回：(File 记录, 是否秒传)
    """
    # 查询是否存在相同 MD5 的有效记录（不同 rel_path 也可复用）
    existing = db.query(File).filter(
        File.user_id == user_id,
        File.md5 == md5,
        File.deleted_at.is_(None)
    ).first()
    
    if existing and existing.ref_count > 0:
        # 秒传：复用物理文件路径，创建新记录
        new_record = File(
            user_id=user_id,
            md5=md5,
            original_name=original_name,
            rel_path=existing.rel_path,  # 复用路径
            size_bytes=existing.size_bytes,
            mime_type=existing.mime_type,
            upload_source=upload_source,
            ref_count=1,
            created_at=time.time(),
        )
        db.add(new_record)
        # 递增原记录的引用计数
        existing.ref_count += 1
        return new_record, True
    
    # 正常上传：创建新记录
    new_record = File(
        user_id=user_id,
        md5=md5,
        original_name=original_name,
        rel_path=rel_path,
        size_bytes=size_bytes,
        mime_type=mime_type,
        upload_source=upload_source,
        ref_count=1,
        created_at=time.time(),
    )
    db.add(new_record)
    return new_record, False
```

**`original_name` 重命名逻辑**（上传端点调用，避免唯一约束冲突）：
```python
def ensure_unique_name(db: Session, user_id: int, original_name: str) -> str:
    """检查 (user_id, original_name) 是否已存在，存在则追加后缀"""
    import os
    base, ext = os.path.splitext(original_name)
    candidate = original_name
    counter = 1
    while db.query(File).filter(
        File.user_id == user_id,
        File.original_name == candidate,
        File.deleted_at.is_(None),
    ).first():
        candidate = f"{base}_{counter}{ext}"
        counter += 1
    return candidate
```

**MD5 计算**（流式读取，避免大文件内存溢出）：
```python
import hashlib

def compute_md5(file_obj, chunk_size=8192) -> str:
    """流式计算文件 MD5"""
    md5 = hashlib.md5()
    while chunk := file_obj.read(chunk_size):
        md5.update(chunk)
    file_obj.seek(0)  # 重置文件指针
    return md5.hexdigest()
```

**修改以下上传端点**：

| 端点 | 修改点 |
|------|--------|
| `POST /api/upload/avatar` | 先建记录（含 MD5），再写文件；若秒传则复用路径 |
| `POST /api/upload/gear-image` | 先建 Gear，再建 File 记录，写文件；若秒传则复用路径并更新 Gear.photo |
| `POST /api/video/upload` | 先建 File 记录，再写原视频和抽帧文件；若秒传则复用路径 |

**异常处理**：若写文件失败，回滚事务并删除已创建的 File 记录。

def decrement_analysis_files(db: Session, analysis: Analysis) -> int:
    """递减 Analysis 关联的所有文件（含骨架产物）的引用计数"""
    count = 0
    # 主文件（thumb、highlights、video_url）
    if analysis.thumb:
        decrement_ref_count(db, analysis.user_id, analysis.thumb)
        count += 1
    if analysis.video_url:
        decrement_ref_count(db, analysis.user_id, analysis.video_url)
        count += 1
    # 骨架产物（从 pose JSON 提取）
    pose = json.loads(analysis.pose) if analysis.pose else {}
    for path in (pose.get("skeleton_frames") or []):
        decrement_ref_count(db, analysis.user_id, path)
        count += 1
    skeleton_video = pose.get("skeleton_video_url")
    if skeleton_video:
        decrement_ref_count(db, analysis.user_id, skeleton_video)
        count += 1
    skeleton_thumb = pose.get("skeleton_thumb")

### 10.2 统一工具设计

**新增文件**：`server/app/services/file_service.py`

**公共路径工具**：

```python
def resolve_safe_path(rel_path: str) -> str | None:
    """将相对路径解析为 UPLOAD_DIR 内的绝对路径，越界返回 None"""
    upload_dir = os.path.abspath(settings.UPLOAD_DIR)
    candidate = os.path.normpath(os.path.join(upload_dir, rel_path))
    if candidate != upload_dir and not candidate.startswith(upload_dir + os.sep):
        return None
    return candidate

def rel_path_to_abs(rel_path: str) -> str:
    """相对路径 → 绝对路径（不校验，用于已知合法路径）"""
    return os.path.abspath(os.path.join(settings.UPLOAD_DIR, rel_path))

def abs_path_to_rel(abs_path: str) -> str:
    """绝对路径 → 相对路径（正斜杠）"""
    return os.path.relpath(abs_path, settings.UPLOAD_DIR).replace(os.sep, "/")

def build_upload_dir(base_dir: str, user_id: int) -> str:
    """构建并返回 UPLOAD_DIR/base_dir/{user_id}/ 绝对路径（自动创建）"""
    rel_dir = os.path.join(base_dir, str(user_id))
    abs_dir = os.path.abspath(os.path.join(settings.UPLOAD_DIR, rel_dir))
    os.makedirs(abs_dir, exist_ok=True)
    return abs_dir

def make_rel_path(base_dir: str, user_id: int, filename: str) -> str:
    """生成 {base_dir}/{user_id}/{filename} 格式相对路径（正斜杠）"""
    return os.path.join(base_dir, str(user_id), filename).replace(os.sep, "/")

def file_exists(abs_path: str) -> bool:
    """安全判断文件是否存在（异常时返回 False）"""
    try:
        return os.path.isfile(abs_path)
    except Exception:
        return False

def get_file_size(abs_path: str) -> int:
    """获取文件大小（字节），文件不存在返回 0"""
    try:
        return os.path.getsize(abs_path)
    except Exception:
        return 0

def safe_unlink(abs_path: str, log=None) -> bool:
    """安全删除文件，不存在时不抛错，返回是否成功删除"""
    try:
        if os.path.isfile(abs_path):
            os.unlink(abs_path)
            return True
        return False
    except Exception as exc:
        if log:
            log.warning("文件删除失败: %s", exc)
        return False
```

### 12.2 事件钩子设计

在 `UploadOptions` 中增加回调，实现解耦：

```typescript
export interface UploadOptions {
  path: string;
  filePath: string;
  formData?: Record<string, string>;
  fieldName?: string;
  timeout?: number;
  onProgress?: (p: { percent: number; transferred: number; total: number }) => void;
  
  // 业务回调
  onSuccess?: (result: UploadResult, durationMs: number) => void;
  onFailed?: (error: Error, durationMs: number) => void;
  onMirage?: (result: UploadResult, durationMs: number) => void;  // 秒传专属
}
```

### 12.3 `uploadFile` 实现

```typescript
export function uploadFile(options: UploadOptions): Promise<UploadResult> {
  const startTime = Date.now();
  
  return new Promise((resolve, reject) => {
    const task = uni.uploadFile({
      url: `${BASE_URL}${API_PREFIX}${options.path}`,
      filePath: options.filePath,
      name: options.fieldName || "file",
      formData: options.formData || {},
      timeout: options.timeout || 60000,
      header: { "X-Auth-Token": getToken() },
      success: (res) => {
        // ... 原有解析逻辑 ...
        resolve(result);
        
        const duration = Date.now() - startTime;
        if (result.mirage) {
          options.onMirage?.(result, duration);  // 秒传回调
        }
        options.onSuccess?.(result, duration);    // 成功回调
      },
      fail: (err) => {
        const duration = Date.now() - startTime;
        options.onFailed?.(new Error(err.errMsg), duration);  // 失败回调
        reject(new Error(err.errMsg));
      },
    });
    
    // 进度回调
    if (options.onProgress) {
      task.onProgressUpdate((r) => options.onProgress?.({
        percent: r.progress,
        transferred: r.totalBytesSent,
        total: r.totalBytesExpectedToSend,
      }));
    }
  });
}
```
