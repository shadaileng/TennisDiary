## 问题描述

小程序端请求 API 时，若后端返回 HTTP 401（token 过期/无效），网络层 `request.ts` 的 `clearAuth()` 函数**仅清除了 `uni.setStorageSync` 中的 token/user，但未同步更新 auth store 的内存态**（`token`、`user`、`hasLoggedIn`），导致：

1. `authStore.isLoggedIn` 仍返回 `true`（`state.token` 未被清空）
2. 页面不会切换到游客态引导（`v-if="authStore.isGuest"` 不触发）
3. 用户看到空列表或请求失败，但没有"去登录"入口
4. 后续请求仍携带已失效的 token，持续触发 401

**复现路径**：token 过期后打开日记页 → 401 → 页面无反应 → 无法登录

## 根因分析

`request.ts` 第 65-69 行 `clearAuth()` 实现：

```ts
function clearAuth() {
  uni.removeStorageSync(TOKEN_KEY);  // ✓ 清 storage
  uni.removeStorageSync(USER_KEY);   // ✓ 清 storage
  // ✗ 缺少：authStore.token / authStore.user / authStore.hasLoggedIn 未清空
}
```

该函数只操作了 storage，没有调用 `authStore.logout()` 更新 Pinia store 的响应式状态。页面组件依赖 `authStore.isLoggedIn` / `authStore.isGuest` 切换模板，但这些 getter 读取的是 `state.token`，而 `state.token` 未被同步清空。

## 修复方案

### 修改文件

`miniapp/src/services/request.ts`

### 具体变更

1. **新增导入** `useAuthStore`（从 `@/stores/auth`）
2. **修改 `clearAuth()`**，在清除 storage 后调用 `useAuthStore().logout()`

```ts
import { useAuthStore } from "@/stores/auth";

function clearAuth() {
  uni.removeStorageSync(TOKEN_KEY);
  uni.removeStorageSync(USER_KEY);
  useAuthStore().logout();  // 同步清除内存态，触发页面响应式更新
}
```

### 循环依赖安全性分析

导入链：`request.ts` → `stores/auth.ts` → `services/auth.ts` → `request.ts`

这是循环导入，但 **运行时安全**，原因：

1. ES module 使用 live binding，`services/auth.ts` 中的 `get/post/put` 引用在实际调用时才解析
2. `stores/auth.ts` 仅在 `login()` action 内部调用 `loginApi()`，不在模块顶层调用
3. `services/auth.ts` 仅在函数体内（`getMe()`、`login()`、`updateProfile()`）调用 `get/post/put`，不在模块顶层调用
4. 同项目中 `request.ts` 已导入 `stores/app.ts`，`stores/app.ts` 被多个模块导入的模式已验证可行

### 修复后效果

| 场景 | 修复前 | 修复后 |
|------|--------|--------|
| 401 返回后页面状态 | 仍显示已登录内容 | 自动切换到游客引导（`v-if="authStore.isGuest"`） |
| 后续请求 | 继续携带失效 token | `getToken()` 返回空，请求前短路并引导登录 |
| toast 提示 | "请到「我的」页登录后使用" | 不变（已有） |
| 日记/装备/统计页 | 空列表或请求失败 | 显示游客空态 + "去登录"按钮 |

## 测试要点

1. 清除本地 token 模拟过期 → 打开日记页 → 确认 401 后自动切换到游客引导
2. 登录后请求日记列表 → 确认正常加载（无循环依赖导致的异常）
3. token 过期后连续并发请求 → 确认只触发一次登出引导（throttle 3s）
