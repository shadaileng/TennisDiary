# 126：小程序昵称输入隐私授权修复 + 渲染层错误埋点

## 一、背景与目标

### 1.1 问题描述

设置昵称时，`<input type="nickname">` 组件未弹出微信昵称选择面板，报错：

```
[渲染层错误] [Component] <input>: showNicknameAccessory:fail input nickname component will degrade as input component when privacy permission is unauthorized , errno:104
```

**根本原因**：`input type="nickname"` 是微信隐私接口，需要用户先同意隐私授权才能正常显示昵称选择面板。

### 1.2 微信隐私接口特殊性

根据微信官方文档，`input type="nickname"` 有以下特殊性：

> 需要注意的是，对于 `<input type="nickname">` 组件，由于 `<input>` 的特殊性，如果用户未同意隐私协议，则 `<input type="nickname">` 聚焦时**不会触发 `onNeedPrivacyAuthorization` 事件**，而是**降级为 `<input type="text">`**。

| 行为 | 说明 |
|------|------|
| 未授权时聚焦 | **不会触发** `onNeedPrivacyAuthorization` 事件，直接降级 |
| 降级后果 | 渲染层 `errno:104` 报错 + 无法弹出微信昵称选择面板 |
| 授权状态 | 一次授权后长时间生效（直到用户清除小程序数据 / 声明变更） |

### 1.3 方案演进回顾

| 版本 | 方案 | 结果 |
|------|------|------|
| v1.0.0 | 手动 `await wx.getPrivacySetting()`（回调 API 当 Promise 用） | ❌ `undefined`，且未授权时 `nickname` 不触发弹窗即降级 |
| v2.0.0 | 参考 tarot **简化**：删除手动授权，完全依赖微信自动弹窗 | ❌ 真机实测**自动弹窗时机不可控**——`nickname` 输入未授权即静默降级，不主动拉起授权则始终无法用昵称能力 |
| **v3.0.0** | **主动隐私引导**（强化版）：未授权用 `text` 输入避免降级；用户在**手势内**点击昵称时主动 `requirePrivacyAuthorize`，授权通过后重建 `type="nickname"` 并聚焦 | ✅ 真机/开发者工具验证通过 |

> **关键认知**：微信对 `input type="nickname"` **不会**像 `button open-type="chooseAvatar"` 那样自动拉起隐私弹窗，而是**静默降级**。因此想真正启用昵称选择面板，必须在**用户手势回调内主动**调用 `wx.requirePrivacyAuthorize`（官方限定此调用必须在点击等手势同步/近同步阶段，否则会被微信忽略）。

## 二、解决方案（v3.0.0 主动隐私引导）

### 2.1 核心思路

1. **进入页面保持普通 `text` 输入**：未授权前不要用 `type="nickname"`，避免聚焦即静默降级（`errno:104`）也避免回填时触发降级。
2. **点击昵称时（用户手势内）主动引导**：
   - 先 `checkPrivacySetting()` 查是否已授权；
   - 已授权 → 直接切 `nickname` + 聚焦；
   - 需授权 → 调用 `requirePrivacyAuthorize()` 拉起官方弹窗；
   - 同意 → 切 `nickname` + 聚焦弹出微信昵称选择；拒绝/低版本 → 保持手动输入 + 一次轻提示。
3. **防重入与防反复打扰**：`privacyPrompting` 防弹窗并发；`privacyAttempted` 记录"本次进入页面已完成引导"，避免每次点击都弹。
4. **渲染层错误分级埋点**：`wx.onError` 中把已知且无危害的降级（`showShareMenu`、`getPrivacySetting`、`nickname`/`showNicknameAccessory`）按 `warn` 低打扰上报，其余按 `fatal` 上报。

### 2.2 状态机

| 状态 | 值 | 含义 |
|------|-----|------|
| `nicknameNickNameEnabled` | `false` | 普通 `text` 输入（默认，页面进入复位） |
| `nicknameNickNameEnabled` | `true` | 已授权，启用 `type="nickname"` |
| `privacyPrompting` | `true` | 隐私弹窗拉起中（防重入） |
| `privacyAttempted` | `true` | 本次已引导过（授权成功或拒绝均置位） |

### 2.3 头像设置说明

`<button open-type="chooseAvatar">` 头像**不需要修改**：微信会在用户首次点击时自动弹出隐私授权弹窗，与昵称输入框行为不同。

### 2.4 埋点 action 清单

| 埋点 | action | 触发时机 |
|------|--------|----------|
| 发起昵称隐私引导 | `privacy_nickname_request` | 手势内点击昵称且需授权 |
| 昵称隐私授权通过 | `privacy_nickname_agree` | `requirePrivacyAuthorize` success |
| 昵称隐私授权被拒 | `privacy_nickname_denied` | fail / 用户拒绝 |
| 昵称隐私授权异常 | `privacy_nickname_error` | 调用抛异常 |
| 渲染层已知降级（低打扰） | —（`logWarn`） | `wx.onError` 命中白名单 |
| 渲染层致命错误 | —（`logFatal`） | `wx.onError` 非白名单错误 |

## 四、实施方案

### 4.1 privacy.ts：隐私授权引导工具（新增）

封装微信回调式 API 为 Promise，低版本基础库/异常均安全兜底：

```typescript
/** 查询当前隐私授权状态；低版本基础库或异常时按「无需授权」兜底 */
export function checkPrivacySetting(): Promise<{ needAuthorization: boolean; privacyContractName: string }> {
  return new Promise((resolve) => {
    // #ifdef MP-WEIXIN
    if (typeof wx !== "undefined" && typeof wx.getPrivacySetting === "function") {
      wx.getPrivacySetting({
        success: (res) => resolve(res),
        fail: () => resolve({ needAuthorization: false, privacyContractName: "" }),
      });
      return;
    }
    // #endif
    resolve({ needAuthorization: false, privacyContractName: "" });
  });
}

/**
 * 在用户手势内编程式拉起微信隐私授权弹窗。
 * - 已授权 / 低版本基础库：立即成功
 * - 用户同意：resolve(true)；用户拒绝或接口失败：resolve(false)
 */
export function requirePrivacyAuthorize(): Promise<boolean> {
  return new Promise((resolve) => {
    // #ifdef MP-WEIXIN
    if (typeof wx !== "undefined" && typeof wx.requirePrivacyAuthorize === "function") {
      wx.requirePrivacyAuthorize({ success: () => resolve(true), fail: () => resolve(false) });
      return;
    }
    // #endif
    resolve(true);
  });
}

/** 打开官方「用户隐私保护指引」全文 */
export function openPrivacyContract(): void {
  // #ifdef MP-WEIXIN
  if (typeof wx !== "undefined" && typeof wx.openPrivacyContract === "function") {
    wx.openPrivacyContract({});
  }
  // #endif
}
```

> **关键点**：v1.0.0 的 bug 是把回调式 `wx.getPrivacySetting()` 当 Promise 用（返回 `undefined`）。这里显式用 Promise 包装 `success/fail` 回调。

### 4.2 env.d.ts：回调式类型声明

```typescript
declare const wx: {
  onError(callback: (errMsg: string) => void): void
  // 隐私接口（微信均为回调式，勿按 Promise 使用）
  getPrivacySetting(options: {
    success: (res: { needAuthorization: boolean; privacyContractName: string }) => void
    fail?: (err: any) => void
    complete?: () => void
  }): void
  requirePrivacyAuthorize(options?: {
    success: () => void
    fail?: (err: any) => void
    complete?: () => void
  }): void
  openPrivacyContract(options?: { fail?: (err: any) => void; complete?: () => void }): void
  onNeedPrivacyAuthorization(resolve: (options: { buttonId?: string; event: 'agree' | 'disagree' | 'exposureAuthorization' }) => void, eventInfo: { referrer: string }): void
}
```

### 4.3 profile-edit.vue：昵称双态 + 主动引导

模板层根据 `nicknameNickNameEnabled` 二选一渲染输入框：

```vue
<!-- 未授权：普通 text 输入，点击时在用户手势内触发隐私引导 -->
<input
  v-if="!nicknameNickNameEnabled"
  v-model="nickname"
  type="text"
  class="form-input"
  :maxlength="24"
  placeholder="设置昵称"
  @click="ensurePrivacyForNickname"
  @blur="saveNickname"
  @confirm="saveNickname"
/>
<!-- 已授权：type="nickname"，切换时用 :key 强制重建以触发聚焦拉起昵称选择 -->
<input
  v-else
  :key="nicknameInputKey"
  ref="nicknameInputRef"
  v-model="nickname"
  type="nickname"
  class="form-input"
  :maxlength="24"
  placeholder="设置昵称"
  @blur="saveNickname"
  @confirm="saveNickname"
/>
```

逻辑层：

```typescript
/** 点击昵称输入：未启用 nickname 能力时，在用户手势内请求微信隐私授权。 */
async function ensurePrivacyForNickname() {
  // #ifdef MP-WEIXIN
  if (nicknameNickNameEnabled.value || privacyPrompting.value || privacyAttempted.value) return;

  // 已授权（如点头像授权过）可直接启用 nickname
  const setting = await checkPrivacySetting();
  if (!setting.needAuthorization) {
    nicknameNickNameEnabled.value = true;
    privacyAttempted.value = true;
    await focusNickName();
    return;
  }

  privacyPrompting.value = true;
  logInfo("昵称隐私授权引导", { privacy_contract: setting.privacyContractName }, undefined, "privacy_nickname_request");
  try {
    const granted = await requirePrivacyAuthorize();
    if (granted) {
      nicknameNickNameEnabled.value = true;
      privacyAttempted.value = true;
      logInfo("昵称隐私授权通过", undefined, undefined, "privacy_nickname_agree");
      await focusNickName();
    } else {
      privacyAttempted.value = true;
      logWarn("昵称隐私授权被拒，使用手动输入", undefined, "business", "privacy_nickname_denied");
      uni.showToast({ title: "未授权隐私，可手动输入昵称", icon: "none" });
    }
  } catch (err: any) {
    privacyAttempted.value = true;
    logWarn("昵称隐私授权异常", { error: err?.message }, "business", "privacy_nickname_error");
  } finally {
    privacyPrompting.value = false;
  }
  // #endif
}

/** 切换为 nickname 输入后聚焦以弹出微信昵称选择 */
async function focusNickName() {
  nicknameInputKey.value += 1; // 强制重建 input，触发 nickname 能力
  await nextTick();
  const input = nicknameInputRef.value;
  if (input && typeof input.focus === "function") {
    input.focus();
  }
}
```

进入页面（`onShow`）时复位为普通输入，避免回填后 `type="nickname"` 触发降级：

```typescript
onShow(() => {
```

### 4.4 App.vue：渲染层错误分级埋点

```typescript
wx.onError((errMsg: string) => {
  if (typeof errMsg !== "string" || !errMsg) return;
  // 已知且无危害的降级错误：作为 warn 上报（低打扰）
  if (errMsg.includes("showShareMenu") || errMsg.includes("getPrivacySetting")) {
    logWarn("渲染层已知降级", { errMsg });
    return;
  }
  // nickname 输入在隐私未授权时静默降级为普通输入（errno:104）：属预期降级，warn 上报便于追踪
  if (errMsg.includes("showNicknameAccessory") || errMsg.includes("nickname")) {
    logWarn("渲染层 nickname 降级", { errMsg });
    return;
  }
  logFatal("渲染层错误", { errMsg });
});
```

> 分级而非一刀切过滤：已知降级用 `warn`（后台可追踪），真正的逻辑层错误仍按 `fatal` 上报，避免掩盖严重问题。

## 六、注意事项

1. **`wx.getPrivacySetting` 是回调式**，不是 Promise，不能直接 `await`；必须用 `success/fail` 回调（本次用 Promise 包装）。
2. **`requirePrivacyAuthorize` 必须在用户手势内调用**（如 `@click` 同步路径），异步 setTimeout 后调用可能被微信忽略。
3. **未授权阶段勿用 `type="nickname"`**：会静默降级并产生 `errno:104`，且不触发 `onNeedPrivacyAuthorization`；主动引导后再切换才是正确姿势。
4. **每次进入页面复位为普通输入**，避免回填或复用组件时在非手势上下文触发 nickname 能力。
5. **渲染层错误分级**：已知降级 `warn`、未知 `fatal`，勿整段过滤以免掩盖逻辑层真实错误。
6. 隐私接口在低版本基础库可能不存在，所有封装均做 `typeof wx.xxx === "function"` 守卫并按"无需授权/直接成功"兜底。
