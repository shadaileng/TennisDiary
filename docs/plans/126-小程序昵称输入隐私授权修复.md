# 126：小程序昵称输入隐私授权修复 + 渲染层错误埋点

## 一、背景与目标

### 1.1 问题描述

设置昵称时，`<input type="nickname">` 组件未弹出微信昵称选择面板，报错：

```
[渲染层错误] [Component] <input>: showNicknameAccessory:fail input nickname component will degrade as input component when privacy permission is unauthorized , errno:104
```

**根本原因**：`input type="nickname"` 是微信隐私接口，需要用户先同意隐私授权才能正常显示昵称选择面板。

### 1.2 v1.0.0 方案问题

v1.0.0 方案（手动隐私授权）存在两个问题：

| 问题 | 原因 |
|------|------|
| `wx.getPrivacySetting` 返回 undefined | 该 API 是**回调方式**，不是 Promise，`await wx.getPrivacySetting()` 返回 undefined |
| 渲染层错误先于隐私弹窗出现 | `input type="nickname"` 的特殊性：**未授权时不会触发 `onNeedPrivacyAuthorization` 事件**，直接降级为普通输入框 |

### 1.3 微信隐私接口特殊性

根据微信官方文档，`input type="nickname"` 有以下特殊性：

> 需要注意的是，对于 `<input type="nickname">` 组件，由于 `<input>` 的特殊性，如果用户未同意隐私协议，则 `<input type="nickname">` 聚焦时**不会触发 `onNeedPrivacyAuthorization` 事件**，而是**降级为 `<input type="text">`**。

| 行为 | 说明 |
|------|------|
| 未授权时聚焦 | **不会触发** `onNeedPrivacyAuthorization` 事件，直接降级 |
| 授权方式 | 微信官方自动弹窗（`__usePrivacyCheck__: true`） |
| 授权状态 | 一次授权后永久生效（直到用户清除小程序数据） |

### 1.4 tarot 项目参考

tarot 参考项目（`docs/reference/tarot`）采用**简化方案**：

| 项目 | tarot | 当前项目（v1.0.0） |
|------|-------|-------------------|
| `__usePrivacyCheck__` | `true` | `true` ✅ |
| `wx.getPrivacySetting` | **不调用** | 调用（回调方式错误）❌ |
| `wx.requirePrivacyAuthorize` | **不调用** | 调用（时机错误）❌ |
| `onNeedPrivacyAuthorization` | **不注册** | 不注册 ✅ |
| 昵称输入框处理 | 简单直接 | 复杂手动拦截 ❌ |
| 隐私弹窗机制 | 微信自动弹窗 | 手动触发（失败）❌ |

**tarot 的做法**：删除自定义隐私弹窗（`privacy.ts`、`PrivacyModal.vue`），完全依赖微信官方自动弹窗。

## 二、解决方案

### 2.1 方案选择：删除手动隐私授权，依赖微信自动弹窗

参考 tarot 项目经验，采用**简化方案**：

1. **删除**手动隐私授权逻辑（`getPrivacySetting`、`requirePrivacyAuthorize`）
2. **保留** `manifest.json` 的 `__usePrivacyCheck__: true`
3. **恢复** 昵称输入框为简单实现
4. **添加** 渲染层错误全局埋点

**优点**：
- 与 tarot 项目保持一致，经过验证
- 代码更简洁，维护成本低
- 避免手动隐私授权的各种边界问题

### 2.2 头像设置说明

头像设置**不需要修改**，当前实现与 tarot 一致：

| 组件 | 行为 |
|------|------|
| `<button open-type="chooseAvatar">` | 微信**自动弹出**隐私授权弹窗 ✅ |
| `<input type="nickname">` | 微信**自动弹出**隐私授权弹窗 ✅ |

两者都依赖微信官方自动弹窗，无需手动拦截。

### 2.3 埋点需求

| 埋点 | action | 触发时机 |
|------|--------|----------|
| 渲染层错误 | `render_error` | `wx.onError` 捕获渲染层错误 |

### 4.2 App.vue 修改

添加渲染层错误全局埋点：

```vue
<script setup lang="ts">
import { onLaunch, onShow, onHide, onError } from "@dcloudio/uni-app";
import { logFatal, flushPendingEvents } from "@/utils/eventLogger";

onLaunch(() => {
  // ... 现有代码 ...
  
  // #ifdef MP-WEIXIN
  // 监听渲染层错误
  wx.onError((errMsg: string) => {
    // 过滤已知的非关键错误
    if (typeof errMsg === 'string' && 
        (errMsg.includes('getPrivacySetting') || 
         errMsg.includes('nickname') ||
         errMsg.includes('showShareMenu'))) {
      return;
    }
    logFatal("渲染层错误", { errMsg });
  });
  // #endif
});
</script>
```

## 六、注意事项

1. **与 tarot 保持一致**：当前方案完全参考 tarot 项目的隐私授权策略，经过验证有效
2. **隐私弹窗时机**：微信会在用户首次点击昵称输入框时自动弹出隐私授权弹窗，用户同意后永久生效
3. **渲染层错误**：`input type="nickname"` 未授权时会降级为普通输入框，这是微信的预期行为，通过埋点监控即可
4. **`wx.getPrivacySetting` 陷阱**：该 API 是回调方式，不是 Promise，不能直接 `await`
