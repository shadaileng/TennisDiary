# Step 129：日记装备统计游客本地降级与登录同步

## 一、目标

为**日记（diary）**、**装备（gear）**、**统计页（数据总览 + 体重管理 weight）**三个模块实现**游客本地降级**：

- **未登录游客**可完整使用各模块（列表浏览、新增、编辑、删除、记录体重），数据落地到本地 `storage`，页面顶部提示「本地模式，登录后自动同步」，不再只展示「🔒 去登录」引导空态；
- **统计页**游客态不再引导登录：「数据总览」6 卡改为基于本地日记/装备**实时聚合**（口径对齐后端 `/api/stats`），「体重管理」区基于本地 pending weights；
- **登录成功后**自动**静默同步**：把本地待同步的日记/装备/体重逐条 `POST` 到后台，成功即清理本地项，失败保留待同步标记，埋点并待下次登录重试。

**主体为前端改造；后端仅新增 1 个匿名封面「仅检即弃」检查端点（见 4.10），无 schema/DB/模型变更。**

## 二、需求来源与澄清结论

- 原始需求：「参考 `/workspace/docs/reference/tarot` 为日志和装备增加游客本地降级功能，登录后同步后台」
- 澄清①（游客可用范围）：**完整本地模式** —— 游客可直接完整使用（列表浏览、新增、编辑、删除），页面提示「本地模式，登录后自动同步」。
- 澄清②（同步策略）：**自动静默同步** —— 登录成功后自动把本地待同步数据逐条创建到后台，成功清理本地项；失败保留、埋点、下次登录重试。
- 澄清③（范围扩展）：**统计页也全页降级** —— 数据总览汇总卡 + 体重管理区都本地化。
- 澄清④（封面安全检查，审核合规）：**选图即检（路线 C）** —— 游客态保存装备封面即联网做微信 `imgSecCheck`「检查即弃」（后端新增匿名端点，检查后不落盘、不建 File），违规当场拦截；登录同步仍走正式受检上传，双保险。

### 3.7 本地存储现状与约定

- storage 键常量 `src/constants/storage.ts`（前缀 `td_`）。costTags 用 `td_cost_tags`。
- 埋点 `utils/eventLogger.ts`：`logInfo/logError(desc, params, ?, eventName, traceId)`、`createTraceId()`。Step 127 约定：**日志不打印 photo dataURL 等大字段**（注意 gear store 现有 `photo: body.photo` 埋点是历史遗留，本次改造一并收敛）。
- 工具 `utils/index.ts`：`todayStr/nowTimeStr/fmtMoney/sumCosts/resolveUploadUrl/safeNavigateBack` 等。
- 依赖注入安全：避免 request.ts 与 store 循环 import（Step 97 用 `onSessionExpired` 回调解耦先例）。
- wx storage 容量：单 key 1MB、总量 10MB —— gear 封面 dataURL 数百 KB，需容量容错。
- **登出/401 隔离风险**：`auth.logout()` 只清 auth 持久化，不清 diary/gear/weight store 内存。登录用户的云端数据若残留内存，会在游客态被误当成本地数据显示 → 需列表页 onShow 按 `isGuest` 分流：游客从本地仓库**重新载入内存**（覆盖云端残留）、登录 `fetchList` 拉云端，从根上避免串显。

## 四、方案设计

### 4.1 本地待同步仓库层（核心新增）

新增统一本地仓库模块，封装三个 storage 键的「读 / 写 / 增删改」与容量容错：

- **storage 键**（写入 `constants/storage.ts`）：`pendingDiaries: "td_pending_diaries"`、`pendingGears: "td_pending_gears"`、`pendingWeights: "td_pending_weights"`。
- **数据形态**：每个 storage 值为 `LocalXxx[]`，`LocalXxx` = 业务实体字段 + 本地标记。

```ts
// 本地待同步日记
interface LocalDiary {
  localId: string           // 本地唯一标识，形如 `d_${Date.now()}_${rand}`，代替数字 id
  pending: true             // 是否待同步（本地创建未上传即 true）
  backendId: number | null  // 登录同步成功回填后台 id（预留，便于将来去重/多端合并）
  date: string; time: string; type: SessionType
  duration: number; intensity: 1|2|3|4|5; mood: 1|2|3|4|5
  costs: CostItem[]; gears: GearUse[]; notes: string
  createdAt: number         // 本地创建时间戳(秒)，用于列表排序/展示兜底
}
interface LocalGear { localId; pending; backendId; category; name; buy_date; price; feeling; photo(dataURL); createdAt }
interface LocalWeight { localId; pending; backendId; date; weight; bust?; waist?; hip?; createdAt }
```

- 仓库 API 建议（`services/pendingRepo.ts`）：

```ts
// 全部读取（带损坏容错：JSON.parse 失败 → 返回 [] 并覆盖坏值）
getPendingDiaries(): LocalDiary[]
getPendingGears(): LocalGear[]
getPendingWeights(): LocalWeight[]

// 写回（内部 try/catch，容量不足时 uni.showToast「本地空间不足，请先登录同步」并抛错/返回 false）
savePendingDiaries(list: LocalDiary[]): boolean
savePendingGears(list: LocalGear[]): boolean
savePendingWeights(list: LocalWeight[]): boolean

// 单条增删改的便捷封装（读-改-写）
// 内部实现：读全量 → 头插/过滤/替换 → savePendingXxx → 返回新数组
upsertPendingDiary(item: LocalDiary): LocalDiary[]   // 供 create
updatePendingDiary(localId: string, body): LocalDiary[]  // 供编辑（保留 localId/pending/backendId）
removePendingDiary(localId: string): LocalDiary[]
// gear/weight 同理：upsert/update/remove
```

> 说明：编辑/删除只针对本地项（游客态无云端 id），因此 `backendId` 字段在**本阶段实际始终为 null**；仅同步成功后理论回填。本阶段登录后以云端为准、本地项已删除/清理，故 `backendId` 仅作 schema 预留，不强依赖。若要精简可去掉 `backendId`，保留 `localId+pending+createdAt`。

- **localId 生成**：`util genLocalId(prefix) => prefix + Date.now() + "_" + 随机数`（避免 tab 页快速操作撞 key）。

### 4.2 视图联合类型

列表/表单要对 `Diary | LocalDiary`（`Gear | LocalGear`、`WeightRecord | LocalWeight`）透明，关键在 id：登录态为 `number`，游客态为 `localId: string`。

- 定义导出联合类型 + id 归一化：

```ts
export type AnyDiary = Diary | LocalDiary
export type AnyGear = Gear | LocalGear
export type AnyWeight = WeightRecord | LocalWeight

// 取主键：登录返回 d.id(number)，游客返回 localId(string)
function getEntryId(x: AnyDiary): number | string { return "localId" in x ? x.localId : x.id }
```

- **跳转参数**：`goEdit(id)` 把 `?id=${id}` 透传，form 页 `editingId` 存 `number | string`（登录存 number、游客存 localId 字符串），回填 / save / remove 分流。模板 `:key` 用 `getEntryId` 避免本地项 `undefined id` 冲突。
- 展示字段对游客可完全复用（列表只读 date/time/duration/... 与 photo URL）。

### 4.3 三 store 双路径改造

保持 store action 签名不变，内部按 `authStore.isGuest` 分流，**页面无感知**（`fetchList`/`create`/`update`/`remove`）。

- 需要访问 `authStore`：`store.$onAction` 或 action 内 `useAuthStore()` 惰性取用（**避免 store 顶层 import 导致循环**，用函数内取实例，参考 costTags 不依赖 auth 的做法；diary/gear 需在 action 内 `const auth = useAuthStore()`）。`src/stores/index.ts` 有 auth/diary/gear/weight，同文件互引不构成 chunk 循环，但为稳妥在 action 体内取 auth。

各 action 游客路径：

```ts
// diary store
state: 保持 diaries: Diary[]；新增 const GUEST_SRC = () => ... // 不新增 state，直接读写本地仓库数组

async fetchList() {
  if (useAuthStore().isGuest) { this.diaries = getPendingDiaries() as unknown as Diary[]; return; }
  this.diaries = await getDiaries();
}
async create(body: DiaryCreate): Promise<Diary> {
  if (useAuthStore().isGuest) {
    const item: LocalDiary = { localId: genLocalId("d"), pending: true, backendId: null, ...(body 全字段默认), createdAt: now() };
    this.diaries = upsertPendingDiary(item) as unknown as Diary[]; // 头部插入由仓库处理或本处前插
    return item as unknown as Diary;
  }
  const d = await createDiary(body); this.diaries = [d, ...this.diaries]; return d;
}
async update(id, body) { /* 游客：updatePendingDiary(String(id), body)，map 替换；登录：原逻辑 */ }
async remove(id)       { /* 游客：removePendingDiary(String(id))，过滤；登录：原逻辑 */ }
```

> 注意：`this.diaries` 在游客态持有的是 `LocalDiary`（含 `localId` 而无 `id`），类型声明上仍是 `Diary[]`。为规避 TS 类型断言带来的脆弱，建议把 store 数组态放宽为 `Diary[] | LocalDiary[]`（或直接用 `AnyDiary[]`），同时 getter `sortedDiaries` 返回 `AnyDiary[]`；页面模板按 `getEntryId` 绑定 key。**实现时对 state/getter 类型统一放宽，避免到处 `as`**。

- weight store 同样三处游客路径（remove 入参在游客态为 localId 字符串）。

### 4.4 统计页本地实时聚合（口径对齐后端）

`pages/stats/stats.vue` 游客态不再引导登录，改为**本地源驱动**：

- 汇总源：本地 pending diaries + gears（经 store 内 `diaries`/`gears` 已是本地项）。
- 写一个纯函数聚合（放 `utils/` 或 store getter，便于单测）：

```ts
function aggregateLocalStats(diaries: LocalDiary[], gears: LocalGear[]): Stats {
  const n = diaries.length;
  const total_duration = diaries.reduce((s,d)=>s+(d.duration||0),0);
  const avg_intensity = n ? round2(mean(diaries.map(d=>d.intensity))) : 0;
  const avg_mood      = n ? round2(mean(diaries.map(d=>d.mood)))      : 0;
  const total_cost    = round2(diaries.reduce((s,d)=>s+sumCosts(d.costs),0));
  return { total_sessions:n, total_duration, avg_intensity, avg_mood, total_cost,
           total_gears:gears.length, total_analyses:0, avg_score:0 };
}
```

- stats.vue `onShow` 分支：游客 → `weightStore.setWeights(getPendingWeights())`（本地体重入内存）、`stats = aggregateLocalStats(diaryStore.diaries, gearStore.gears)`（列表页切换过来时 diary/gear store 内存已由各自 onShow 载入本地项；若担心切到 stats 时未先过 diary 页，则在 stats.vue 游客分支也主动 `diaryStore.diaries = getPendingDiaries()` 兜底）；登录 → 现逻辑。
- 体重三格 / 趋势 LineChart / 增删：基于 `weightStore.weights`（游客态为本地项），已有 computed（`latest/delta/weightData`）对 `WeightRecord | LocalWeight` 均成立（只需 date/weight/bust/waist/hip 字段，LocalWeight 同样具备）；`confirmRemove(id)` 与 `weightStore.remove` 在游客态 id 为 localId。
- 「数据总览」游客 `hasAnyData` 判断沿用现有 computed（对本地聚合 Stats 同样成立）。
- stats 页 `statsLoading` 游客态置 false 即可（本地同步聚合无需 loading）。

### 4.5 列表页放开游客 + 本地模式横幅

- save/remove：按 editingId 是 number 还是 string 决定走云端 create/update/remove 还是本地 upsert/update/remove（store action 内已分流，页面 save 照调 store.create/update 即可，store 内部判 guest）。成功后 `costTagsStore.recordUsed(...)` 照常（本地学习标签与登录态无关，可持久化）。

### 4.7 登录后自动静默同步

新增同步服务 `services/sync.ts`，导出 `syncPendingLocalData()`：

```ts
// 仅登录态执行；进程级防并发（模块级 flag）
let syncing = false
export async function syncPendingLocalData(): Promise<void> {
  const auth = useAuthStore()
  if (!auth.isLoggedIn || syncing) return
  syncing = true
  const traceId = createTraceId()
  try {
    // 建议顺序：先体重(无大字段、快) → 再日记 → 最后装备(含 dataURL 封面)
    await syncWeights();  // getPendingWeights 逐条 createWeight，成功 removePendingWeight
    await syncDiaries();  // getPendingDiaries 逐条 createDiary，成功 removePendingDiary
    await syncGears();    // getPendingGears 逐条 createGear，成功 removePendingGear
    // 统计 + 埋点
  } finally { syncing = false }
}

// 单条成功即从本地仓库移除；失败保留该条并计数，继续下一条（不中断批量）
async function syncWeights(): Promise<{ ok: number; fail: number }> { ... }
async function syncDiaries(): Promise<{ ok: number; fail: number }> { ... }
async function syncGears(): Promise<{ ok: number; fail: number }> { ... }
```

- **逐条上传模式**参考 tarot `uploadUnsyncedRecords`：遍历 → `backendId = await createXxx(...)` → 成功 `removePendingX(localId)` + ok++；失败 `fail++` 继续；最终 `logInfo("本地数据同步完成", {diaries_ok, diaries_fail, gears_ok, gears_fail, weights_ok, weights_fail}, ...)`，日志**不打印 photo/dataURL 等大字段**（只打 ok/fail 计数与类型）。
- **防并发**：登录按钮 + 401 重登等路径都只调一次；`syncing` 模块级布尔 + 每次取到的 pending 列表快照，避免与页面并发写冲突。
- 失败项保留在本地：下一次登录成功会再次触发同步；不主动 toast 打扰，仅当存在 fail 时在 mine 页 toast 轻提示一次「部分本地记录同步失败，将自动重试」（可选）。

### 4.8 挂接登录成功

- `mine.vue doLogin()` 在 `authStore.login()` 成功后、hideLoading 前后调用 `syncPendingLocalData()`（不 await 阻塞 UI 也可，或 await 但静默失败）。成功后清空 diary/gear/weight store 内存并触发一次云端重载（用户若在 mine 页看不到列表，切到 diary/gear/stats tab 时 onShow 会重新 fetchList 拉云端，天然一致，无需额外刷新）。
- 登出（`profile-edit.vue`）与 401 后：本地 pending 数据**保留**；各 tab 页 onShow 按 guest 重新从本地仓库载入内存，覆盖云端残留，实现「多账号隔离」——A 登录时云端数据不会在登出后出现在 B 的游客本地态。

### 4.9 容量与容错

- gear 封面 dataURL 单条可达数百 KB：写入前对整列表估算 `JSON.stringify(list).length`，超过单 key 1MB 阈值 → `uni.showToast("本地空间不足，请先登录同步")` 且不写坏数据；**不允许静默丢数据或崩溃**。
- 读取时 `JSON.parse` 失败（历史版本/损坏）→ 返回空数组并清理坏键，不崩溃。
- diary/gear photo 埋点收敛：同步/创建的 eventLogger 不打印 photo 字段（改造 gear store 历史遗留 `photo: body.photo` 埋点一并移除）。

### 4.10 装备封面内容安全检查（审核合规 · 路线 C「检查即弃」）

**动机**
- 微信小程序审核要求：用户上传图片（UGC）的路径必须接入内容安全接口（`security.imgSecCheck` / `mediaCheckAsync`）。现状**唯一检查点在登录态上传端点** `POST /api/upload/gear-image`（`check_image_sync` 检查不通过即删文件返 400）。
- 游客本地模式若纯存 dataURL 不上传，封面完全绕过检查；即便「同步时才上传受检」，审核对「游客保存封面」这一路径（无检测调用）仍有解读风险。
- 微信客户端无可用检测 API（`wx.imgSecCheck`/`wx.msgSecCheck` 客户端版已下线，security.* 必须服务端持 access_token 调用）→ 游客态检测必须走后端。
- **路线 C 结论（用户确认）**：游客选封面时即时联网检测、**检查即弃不落盘**；合规图仍存本地 dataURL；登录同步仍走正式受检上传——「选图即检」满足审核观感，「同步正式上传受检」兜底内容安全，双保险。

**后端新增端点（唯一后端改动）**

```
POST /api/upload/guest-gear-check          # 免鉴权：不依赖 get_current_user，不建用户记录
multipart: file=<压缩图>, code=<wx.login 一次性 code>
流程:
  1) 类型/大小校验（imgSecCheck 限 ≤1MB，前端压缩 900px/0.8 已满足）
  2) wx_service.code_to_openid(code) → openid（失败 → 400「登录态已过期，请重新进入小程序」）
  3) 写临时文件 UPLOAD_DIR/check_tmp/<uuid>.<ext>
  4) content_security.check_image_sync(abs_path, openid)   # security.imgSecCheck
  5) finally 删除临时文件 —— 不落盘、不建 File 记录、不写 DB
  6) 通过 → {"safe": true}；ContentSecurityError → 400 违规文案
滥用防护: 后端无现成 rate-limit 机制，需端点内自建简易节流（按 openid 计数/时间窗）或暂以
          @audit 审计记录降级兜底；临时目录定期清理兜底
```

**前端接入**（`gear/form.vue` 游客态 `onPickPhoto`）
- **先解耦压缩**：`onPickPhoto` 现走 `choosePhoto`（内部会登录上传，游客不可复用）。实施时把 `choosePhoto` 里「`uni.chooseMedia` → `uni.compressImage`(900px/0.8)」拆为独立 helper `compressToDataURL()`（返回本地 `data:`）；登录态维持原 `choosePhoto`（压缩→`uploadGearImage`→URL），游客态走 `compressToDataURL` → 本地 dataURL → guest-check。
- 游客：先调 `guest-gear-check`（`file` + `uni.login` 一次性 code）→ `safe:true` 才写 `form.photo`（本地 dataURL）；违规/损坏 → toast「图片可能包含违规信息，请更换后重试」，不保存。
- 免鉴权封装：游客无 token，新增 `uni.uploadFile` 封装直打 guest-check（**不触发 request.ts 未登录短路**；后端端点不依赖 `get_current_user`），参考现有 `uploadGearImage`（`utils/index.ts`）。注意 `utils/upload.ts` 的 `uploadRaw/uploadFile` 硬编码 `X-Auth-Token: getToken()`（游客为空）——后端免鉴权端点不挂依赖即可接受空 token 头；也可在 guest-check 封装里去掉该头。`data:` dataURL 回显已 OK：`resolveUploadUrl` 对 `data:` 前缀原样返回。
- **fail-open**：检查接口因网络/微信侧故障不可用 → 放行本地保存（dataURL 入本地仓库）；同步正式上传时后端仍会拦截违规 → 内容安全不因游客检查降级而破防。
- 埋点：`guest_gear_img_check_ok/reject/error`（不打印图片内容），沿用 eventLogger。

**隐私与提示**
- 游客封面图会联网发送至后端做「仅检即弃」（服务器瞬时不持久化），与「游客不发业务请求」的既有约定不同，属审核必需例外；「本地模式」横幅文案建议注明「封面将联网检测内容安全，其余数据仅存本机」。

**一致性**
- 同步链路上传 `POST /api/upload/gear-image` 对 dataURL 二次受检 → 最终入库封面必然通过官方检查；guest-check 仅提前拦截，不承担唯一防线。
