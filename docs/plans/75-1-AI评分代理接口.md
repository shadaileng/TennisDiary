# 75-1：AI 评分代理接口

## 一、背景与目标

总纲 75-B2 §4.2 规划将参考 Web 版 `ai.ts` 的 AI 分析能力收敛到 FastAPI 服务端：小程序端把抽帧后的图片（base64 JPEG）发给后端，后端以服务端配置的 `AI_API_KEY` 调用 OpenAI 兼容端点（阿里云百炼），返回六维评分报告。**AI Key 仅存服务端 `.env`，不进入小程序包**。

| 目标 | 说明 |
|------|------|
| 端点 | `POST /api/ai/analyze`（鉴权：`get_current_user`，`X-Auth-Token`） |
| 入参 | `frames`（base64 JPEG 数组）+ `kind`（正手/反手/发球…）+ `mode`（single/full） |
| 出参 | `AnalysisReport`（六维 JSON，契约见 §三） |
| 降级 | 无 Key / 调用失败 → 本地降级报告（score=0 + 说明），不虚构分析 |
| 安全 | AI Key 只存服务端；代理调用不向前端暴露端点域名之外的任何信息 |

## 二、现状

| 项 | 现状 |
|----|------|
| 配置 | `config.py` 已有 `AI_API_KEY / AI_BASE_URL / AI_MODEL`（默认 `qwen-vl-max`） |
| 依赖 | `httpx>=0.28.1` 已具备（dev 组含 pytest） |
| 路由 | `routers/` 无 AI 相关路由；`services/` 仅 `wx_service.py` |
| 参考资产 | `docs/reference/tennis-diary/src/ai.ts`：`chatVision`（120s 超时 / temperature 0.3）、`analyzeSwing`（六维 prompt + NTRP 标尺 + JSON 兜底）、`buildLocalReport`（降级） |

## 三、关键契约（来自 `ai.ts`，须原样保留）

- **六维维度**：`准备启动 / 动力链 / 击球时机 / 随挥收拍 / 拍面控制 / 身体稳定`；
- **报告 JSON**（`AnalysisReport`）：

```json
{
  "score": 0-100,
  "summary": "一句话总结（30字内）",
  "ntrp": "1.0-7.0，0.5 步进",
  "dimensions": [{"name": "...", "score": 0-100, "comment": "25字内"}],
  "rhythm": "节奏与战术观察（50字内）",
  "strengths": ["亮点1", "亮点2"],
  "improvements": [{"issue": "问题", "advice": "改进建议"}]
}
```

- **评分标尺**：90-100 职业级几乎不给；业余视频大多 55-70；`ntrp` 与总分档位一致；画面无法辨识时如实说明，不虚构；
- **兜底校验**：`dimensions` 为空时用六维名称 + 总分补齐，`strengths / improvements` 缺省为空数组；
- **降级路径**：score=0 + 说明文案。

## 四、详细方案

### 4.1 服务层（新建 `server/app/services/ai_service.py`）

| 函数 | 职责 |
|------|------|
| `chat_vision(images, prompt, max_tokens=2000)` | `httpx.AsyncClient` 调 `{AI_BASE_URL}/chat/completions`，`Authorization: Bearer`，`temperature=0.3`，120s 超时；非 2xx 抛异常 |
| `extract_json(text)` | 正则 `\{[\s\S]*\}` 提取首个 JSON 对象并 `json.loads`，失败抛 `ValueError` |
| `analyze_swing(frames, kind, mode)` | 组装 prompt（与 `ai.ts` 一致）→ `chat_vision`（max_tokens=2500）→ `extract_json` → 兜底校验；无 Key / 失败抛异常 |
| `build_local_report(kind, metrics=None)` | 本地降级报告（score=0 + 说明 + 提示配置 AI Key） |

要点：

- prompt 用 `f-string` 模板，`mode` 决定描述文案（single：单次挥拍连续关键帧；full：全片均匀抽样综合分析）；
- 兜底校验与参考版 `analyzeSwing` 尾部一致（`DIMENSIONS.map(name => ({name, score: score||60, comment:'—'}))`）；
- 无 Key 直接抛异常（不发起网络请求），由路由层转降级。

### 4.2 路由（新建 `server/app/routers/ai.py`）

- `POST /api/ai/analyze`，`APIRouter(prefix="/api/ai", tags=["ai"])`；
- 请求体 `AnalyzeRequest`：`frames: list[str]`（base64/dataURL）、`kind: str`、`mode: Literal["single","full"] = "single"`；
- 鉴权：`current_user: User = Depends(get_current_user)`（统一 `X-Auth-Token`）；
- 逻辑：
  1. `settings.AI_API_KEY` 为空 → 直接返回 `build_local_report(kind)`（不请求网络）；
  2. 调用 `ai_service.analyze_swing`，成功 → `ApiResponse(data=report)`；
  3. 异常 → `log.error` 记录 + 返回 `build_local_report(kind)`（**HTTP 200**，前端按 score=0 识别降级）。

### 4.3 Schema（`server/app/schemas/schemas.py`）

新增（放「AI 分析」区块）：

```python
class DimensionScore(BaseModel):
    name: str
    score: int
    comment: str = ""

class AnalysisReportResponse(BaseModel):
    score: int = 0
    summary: str = ""
    ntrp: str | None = None
    dimensions: list[DimensionScore] = []
    rhythm: str = ""
    strengths: list[str] = []
    improvements: list[dict] = []
```

> 说明：`improvements` 用 `list[dict]` 宽松校验（AI 返回内容不强制字段），其余字段做基本类型约束即可，保持与参考版契约松耦合。

### 4.4 路由注册（`server/app/main.py`）

`app.include_router(ai.router)`（用户路由区，`auth` 之后）。

| `analyze` 未登录 | `client`（无 mock 鉴权）→ 401/403 |

## 七、验收标准

- [ ] `POST /api/ai/analyze`（带鉴权）返回完整六维报告，`dimensions` 六项齐全；
- [ ] 无 Key / AI 调用失败时不报 5xx，返回 score=0 降级报告；
- [ ] 未登录请求返回 401/403；
- [ ] `extract_json` 对 AI 返回的「JSON + 前后缀文字」容错；
- [ ] `uv run pytest` 全绿、`ruff check` 无错误。

## 九、风险与注意事项

| 风险 | 说明与对策 |
|------|-----------|
| AI 返回非法 JSON | `extract_json` 正则兜底 + 异常降级 |
| AI 响应超时 | 120s 超时 + 路由层捕获降级 |
| Key 泄露 | 仅存 `.env`；路由层永不回显 Key |
| 请求体过大 | 帧 base64 放大体积，需前端压缩；后端 `max_tokens` 控制响应 |
