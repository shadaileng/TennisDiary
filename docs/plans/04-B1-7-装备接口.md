# Step B1-7：装备 CRUD 接口

## 一、目标

实现 `/api/gears` 装备数据的增删改查接口，复用 B1-6 的建立范式（强制 `user_id` 归属校验、创建时写 `created_at`）。

## 二、前置条件

- B1-3 完成（Gear 模型 `app/models/gear.py`）
- B1-4 完成（Pydantic Schemas：`GearCreate` / `GearUpdate` / `GearResponse`）
- B1-5 完成（JWT 鉴权 `get_current_user`）

## 三、接口设计

| 端点 | 方法 | 说明 | 鉴权 |
|---|---|---|---|
| `/api/gears` | GET | 当前用户装备列表（按 id 倒序） | 是 |
| `/api/gears` | POST | 添加装备 | 是 |
| `/api/gears/{id}` | GET | 装备详情 | 是 |
| `/api/gears/{id}` | PUT | 编辑装备 | 是 |
| `/api/gears/{id}` | DELETE | 删除装备 | 是 |

### 3.1 关键约束

- 所有查询强制 `user_id == current_user.id`，越权访问返回 404。
- Gear 字段均为标量（无 JSON 嵌套），`photo` 存 dataURL 或文件路径字符串。
- `created_at` 入库为 Unix 时间戳（`time.time()`）。
- 更新采用「仅覆盖传入字段」语义（`GearUpdate` 全可选）。

## 四、详细执行步骤

### 4.1 路由模块（`app/routers/gears.py`，新增）

- `list_gears`：`filter_by(user_id=...).order_by(Gear.id.desc())`
- `create_gear`：`GearCreate` → 构造 `Gear`，`commit`/`refresh` 后返回 `GearResponse`
- `get_gear` / `update_gear` / `delete_gear`：经 `_get_owned_gear` 校验归属，不存在或越权返回 404

### 4.2 注册路由（`app/main.py`）

- `from app.routers import gears`
- `app.include_router(gears.router)`
