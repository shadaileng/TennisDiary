# Step 33：未登录友好提示 — 网络层门控与数据层兜底

## 一、背景

未登录时，前端仍会直接请求后台接口（如 `GET /api/stats`），后台返回 `401 Not authenticated`，前端无任何友好提示，控制台仅出现未捕获的 `MiniProgramError`。虽然前端已有静默登录门控（`auth.ensureLogin()`），但它只在 `App.vue` 的 `onLaunch` 调用，管不到业务页在 `onShow` 中无条件发起的请求。

根因：
1. `request.ts` 在 `auth=true` 但本地无 token 时仍发起请求，直接打后台。
2. 业务页 `onShow` 无条件调用 `fetchList()`/`getStats()`。
3. 各 store 的 `fetchList` 无 try/catch，请求失败时产生未捕获的 Promise 异常。

## 二、决策记录

| 决策点 | 结论 |
|---|---|
| 网络层门控 | `request.ts` 入口加未登录硬门控：`auth=true` 且无 token 时**直接短路**，不发请求 |
| 引导交互 | 未登录时不自动跳转，仅 toast 提示「请到『我的』页登录后使用」，由用户自行切到「我的」Tab 登录（选项 2） |
| 节流 | 引导 toast 做 3s 节流，避免多请求/重复触发刷屏 |
| 数据层兜底 | 三个 store 的 `fetchList` 用 try/catch 吞错，且 **必须 `console.error` 打印错误**（用户明确要求不能静默） |
| 401 统一处理 | 401 时清理登录态并统一引导（不重复弹「已过期」） |

## 三、技术方案

### 3.1 `miniapp/src/services/request.ts` — 网络层门控

新增模块级常量与节流标志：

```ts
const LOGIN_GUIDE_THROTTLE = 3000;
let lastLoginGuideAt = 0;

function promptLogin() {
  const now = Date.now();
  if (now - lastLoginGuideAt < LOGIN_GUIDE_THROTTLE) return;
  lastLoginGuideAt = now;
  uni.showToast({ title: "请到「我的」页登录后使用", icon: "none" });
}
```

在 `request()` 入口（`options` 解构后、`fullUrl` 拼接前）加门控：

```ts
if (auth && !getToken()) {
  promptLogin();
  return Promise.reject(new ApiError(401, "请先登录"));
}
```

401 处理改为统一引导（不清 token 后重复提示）：

```ts
if (statusCode === 401 && handle401) {
  clearAuth();
  promptLogin();
}
```

### 3.2 三个 store 的 `fetchList` 加 try/catch + `console.error`

- `miniapp/src/stores/weight.ts`
- `miniapp/src/stores/diary.ts`
- `miniapp/src/stores/gear.ts`

```ts
async fetchList() {
  this.loading = true;
  try {
    this.weights = await getWeights();
  } catch (e) {
    console.error("[weight] 拉取体重记录失败", e);
  } finally {
    this.loading = false;
  }
}
```

（diary / gear 同理，日志前缀分别为 `[diary]`、`[gear]`）

### 3.3 `miniapp/src/pages/stats/stats.vue` — `getStats` 补日志

```ts
.catch((e) => {
  console.error("[stats] 拉取统计数据失败", e);
});
```
