# Step 59-v1.1：业务动作埋点与精确时间

## 一、背景与问题

v1.0.0 已实现网络异常、全局崩溃、自定义事件的埋点，但缺少对**用户核心业务动作**的记录。当前存在两个问题：

1. **时间精度不足**：`created_at` 是后端写入时间（服务端接收时刻），与前端实际操作时刻有网络延迟，且批量上报的多条事件 `created_at` 相同，无法还原操作时序。
2. **操作原子性缺失**：一次操作（如登录、写日记）可能产生多条日志，但这些日志之间没有关联关系，管理端无法将多条事件还原为一次完整操作。

## 二、设计目标

| 目标 | 方案 |
|------|------|
| 精确操作时间 | 前端上报时携带 `client_time`（Date.now() 毫秒时间戳），后端存储并用于排序展示 |
| 操作原子性 | 引入 `trace_id`，同一操作的各条日志共享同一个 trace_id |
| 核心动作覆盖 | 登录、修改资料、日记 CRUD、装备 CRUD、体重 CRUD |

## 三、trace_id 设计

**生成规则**：操作开始时生成一个唯一 ID（基于时间戳 + 随机后缀），在操作链路中透传。

```typescript
// eventLogger.ts 新增
export function createTraceId(): string {
  return `${Date.now()}-${Math.random().toString(36).slice(2, 8)}`
}
```

**透传方式**：
- store action 在操作开始时生成 trace_id
- 将该 trace_id 随 `extra` 传入各级 log 调用
- 后端 `extra` 字段以 JSON 字符串存储，trace_id 可通过 extra 查询

```typescript
// 示例：日记创建
const traceId = eventLogger.createTraceId()
try {
  eventLogger.logInfo("开始创建日记", { traceId, page: "diary-form" })
  const diary = await diaryStore.create(body)
  eventLogger.logInfo("日记创建成功", { traceId, diaryId: diary.id })
} catch (e) {
  eventLogger.logError("日记创建失败", { traceId, error: e.message })
}
```

**管理端查询增强**：支持按 `trace_id` 过滤，一次性展示某次操作的完整日志链。

### 5.2 日记

```typescript
async create(body: DiaryCreate): Promise<Diary> {
  const traceId = eventLogger.createTraceId()
  try {
    eventLogger.logInfo("创建日记", { traceId, page: "diary-form", type: body.type })
    const d = await createDiary(body)
    this.diaries = [d, ...this.diaries]
    eventLogger.logInfo("日记创建成功", { traceId, diaryId: d.id })
    return d
  } catch (e) {
    eventLogger.logError("日记创建失败", { traceId, error: (e as Error).message })
    throw e
  }
}

async update(id: number, body: DiaryUpdate): Promise<Diary> {
  const traceId = eventLogger.createTraceId()
  try {
    eventLogger.logInfo("编辑日记", { traceId, page: "diary-form", diaryId: id })
    const d = await updateDiary(id, body)
    this.diaries = this.diaries.map((x) => (x.id === id ? d : x))
    eventLogger.logInfo("日记更新成功", { traceId, diaryId: id })
    return d
  } catch (e) {
    eventLogger.logError("日记更新失败", { traceId, diaryId: id, error: (e as Error).message })
    throw e
  }
}

async remove(id: number) {
  const traceId = eventLogger.createTraceId()
  try {
    eventLogger.logInfo("删除日记", { traceId, page: "diary-detail", diaryId: id })
    await deleteDiary(id)
    this.diaries = this.diaries.filter((x) => x.id !== id)
    eventLogger.logInfo("日记删除成功", { traceId, diaryId: id })
  } catch (e) {
    eventLogger.logError("日记删除失败", { traceId, diaryId: id, error: (e as Error).message })
    throw e
  }
}
```

## 十、验收标准

| 验收项 | 标准 |
|--------|------|
| client_time 字段 | 后端存储，前端发送，管理端展示毫秒时间戳 |
| trace_id 生成 | 每次操作生成唯一 ID，关联该操作的所有日志 |
| 登录埋点 | 登录开始/成功/失败均记录，共享 trace_id |
| 资料更新埋点 | 修改资料动作记录 info 事件 |
| 日记 CRUD 埋点 | 创建/编辑/删除均记录，分别有 trace_id |
| 装备 CRUD 埋点 | 创建/编辑/删除均记录，分别有 trace_id |
| 体重 CRUD 埋点 | 添加/删除均记录，分别有 trace_id |
| 管理端 trace_id 过滤 | 支持按 trace_id 查询关联事件 |
| 管理端时间排序 | 列表按 client_time 降序，非 created_at |
