# Step 59-v1.1：业务动作埋点与精确时间

## 一、背景与问题

v1.0.0 已实现网络异常、全局崩溃、自定义事件的埋点，但缺少对**用户核心业务动作**的记录。当前存在两个问题：

1. **时间精度不足**：`created_at` 是后端写入时间（服务端接收时刻），与前端实际操作时刻有网络延迟，且批量上报的多条事件 `created_at` 相同，无法还原操作时序。
2. **操作原子性缺失**：一次操作（如登录、写日记）可能产生多条日志，但这些日志之间没有关联关系，管理端无法将多条事件还原为一次完整操作。

## 二、设计目标

| 目标 | 方案 |
|------|------|
| 精确操作时间 | 前端上报时携带 `client_time`（Date.now() 毫秒时间戳），后端存储并用于排序展示 |
| 操作原子性 | `trace_id` 作为独立字段，同一操作的各条日志共享同一个 trace_id |
| 动作分类 | `action` 作为独立字段，标识具体业务动作（如 `profile_update`、`diary_create`） |
| 参数结构化 | `extra` 只保存业务 payload（不确定的业务参数），不包含 trace_id/action |
| 类型赋值 | 业务动作 → `type: "business"`，网络错误 → `type: "network"`，崩溃 → `type: "crash"` |

## 二、上报批次与 trace_id 关系

### 2.1 批次定义

info/warn 级别事件通过防抖批量上报（3s 或 ≥5 条触发一次 `POST /api/events`），**一次 POST 请求内的所有事件构成一个"报送批次"**。

```
trace_id = T1（登录操作）
  ├─ logInfo("开始登录", { trace_id: T1 })  → 加入 pendingBatch
  ├─ logInfo("发送请求",   { trace_id: T1 })  → 加入 pendingBatch
  ├─ logInfo("获取成功",   { trace_id: T1 })  → 加入 pendingBatch
  └─ 防抖 3s 后 flushOne × 3，一次 POST 发出 → 上报批次 = {T1_1, T1_2, T1_3}
```

### 2.2 批次与 trace_id 的关系

| 场景 | trace_id 分布 | 批次分布 | 说明 |
|------|--------------|---------|------|
| 操作在 3s 内完成 | 同一条 trace_id | 同一批次 | ✅ 完整入库 |
| 操作跨越多个防抖周期 | 同一条 trace_id | 不同批次 | ⚠️ 部分入库（方案 A 接受） |
| error/fatal 实时上报 | 同一条 trace_id | 独立批次（不防抖） | ✅ 实时入库 |

### 2.3 方案选择：方案 A（接受跨批次部分入库）

- 大部分操作在 3s 内完成，不会跨批次
- error/fatal 实时上报，关键异常不会丢失
- pending 缓存启动补发时会重试，大部分场景能恢复
- 不引入额外复杂度（方案 B 需扩展 pending 数据结构按 trace_id 重发）

**管理端查询时**：按 `trace_id` 过滤可还原一次操作的**尽可能完整**的日志链，但不保证 100% 完整（极端情况部分事件丢失）。

## 三、trace_id 与 action 设计

**字段独立存储**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `trace_id` | VARCHAR(64) | 操作链路 ID，同一操作的各条日志共享 |
| `action` | VARCHAR(64) | 业务动作标识，如 `profile_update`、`diary_create` |
| `extra` | TEXT | 只保存业务 payload，不包含 trace_id/action |

**生成规则**：
```typescript
// eventLogger.ts
export function createTraceId(): string {
  return `${Date.now()}-${Math.random().toString(36).slice(2, 8)}`
}
```

**上报结构**：

  "extra": { "diary_id": 123 },

async create(body: DiaryCreate): Promise<Diary> {
  const traceId = eventLogger.createTraceId()
  try {
    eventLogger.logInfo("创建日记", { trace_id: traceId, type: body.type }, "diary_create")
    const d = await createDiary(body)
    this.diaries = [d, ...this.diaries]
    eventLogger.logInfo("日记创建成功", { trace_id: traceId, diary_id: d.id }, "diary_created")
    return d
  } catch (e) {
    eventLogger.logError("日记创建失败", { trace_id: traceId, error: (e as Error).message }, "diary_create_failed")
    throw e
  }
}

async update(id: number, body: DiaryUpdate): Promise<Diary> {
  const traceId = eventLogger.createTraceId()
  try {
    eventLogger.logInfo("编辑日记", { trace_id: traceId, diary_id: id }, "diary_update")
    const d = await updateDiary(id, body)
    this.diaries = this.diaries.map((x) => (x.id === id ? d : x))
    eventLogger.logInfo("日记更新成功", { trace_id: traceId, diary_id: id }, "diary_updated")
    return d
  } catch (e) {
    eventLogger.logError("日记更新失败", { trace_id: traceId, diary_id: id, error: (e as Error).message }, "diary_update_failed")
    throw e
  }
}

async remove(id: number) {
  const traceId = eventLogger.createTraceId()
  try {
    eventLogger.logInfo("删除日记", { trace_id: traceId, diary_id: id }, "diary_delete")
    await deleteDiary(id)
    this.diaries = this.diaries.filter((x) => x.id !== id)
    eventLogger.logInfo("日记删除成功", { trace_id: traceId, diary_id: id }, "diary_deleted")
  } catch (e) {
    eventLogger.logError("日记删除失败", { trace_id: traceId, diary_id: id, error: (e as Error).message }, "diary_delete_failed")
    throw e

## 十一、验收标准

| 验收项 | 标准 |
