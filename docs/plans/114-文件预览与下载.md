# Step 114：Admin 文件预览与下载

## 一、目标

为 Admin 文件管理页面添加**文件预览**和**下载**能力。

### 功能范围

| 能力 | 说明 |
|------|------|
| 文件预览 | 图片直接展示、视频/音频内嵌播放、PDF/文本内嵌查看、其他格式提示不支持预览 |
| 下载 | Chromium: `showSaveFilePicker` + `WritableStream` 流式写入磁盘（零内存 + 进度条）；其他浏览器: `<a>` 标签 fallback |
| 后端 | 新增下载端点（禁用 Range）、文件信息端点 |
| 前端 | 预览弹窗、流式下载按钮 + `DownloadProgress` 进度条组件 |

## 二、技术方案

### 2.1 后端

#### 新增端点

| Method | Path | 说明 |
|--------|------|------|
| `GET` | `/api/admin/files/{file_id}/download` | 下载文件（强制 octet-stream，禁止 Range） |
| `GET` | `/api/admin/files/{file_id}/preview` | 获取文件预览信息（mime_type + rel_path） |

#### 下载端点设计

```python
@router.get("/{file_id}/download")
def download_file(file_id: int, ...):
    # 1. 手动鉴权（header 或 query 参数 token）
    # 2. 查询 File 记录，检查 exists
    # 3. resolve_safe_path(rel_path) 拼接 UPLOAD_DIR，校验路径安全
    # 4. 强制 Content-Type: application/octet-stream
    # 5. Content-Disposition: attachment; filename="原始文件名"
    # 6. StreamingResponse 逐块读取（不支持 Range，阻止 Chrome 视频预览）
```

**关键设计决策**：

- **禁用 Range**：Chrome 对 `video/mp4` 自动发送 Range 请求尝试预览，与另存为对话框并发导致 UI 线程死锁。使用 `StreamingResponse` 而非 `FileResponse`，因为 Starlette 的 `FileResponse` 会自动处理 Range 请求。
- **强制 octet-stream**：所有文件类型统一返回 `application/octet-stream`，阻止浏览器根据 MIME 类型尝试预览。
- **强制 attachment**：`Content-Disposition: attachment` 确保浏览器弹出下载对话框而非直接展示。

#### 预览信息端点

```python
@router.get("/{file_id}/preview")
def preview_file(file_id: int, ...):
    # 返回 mime_type + rel_path + size_bytes
    # 前端根据 mime_type 决定渲染方式
    # 图片/视频/音频：可预览
    # 其他：提示不支持
```

### 2.2 前端

#### 下载工具（公共）

下载核心已抽离为公共工具 `src/utils/download.ts`，按 `url` 入参、供所有下载入口复用：

```typescript
export interface DownloadFileInput { url: string; fileName: string; sizeBytes: number }
export interface DownloadOptions {
  onProgress?: (downloaded: number, total: number) => void
  signal?: AbortSignal
  token?: string
}

export async function downloadAdminFile(
  file: DownloadFileInput,
  options: DownloadOptions = {},
): Promise<void> {
  const token = options.token ?? localStorage.getItem('admin_token') ?? ''
  const url = file.url

  if (typeof window.showSaveFilePicker === 'function') {
    let handle
    try {
      handle = await window.showSaveFilePicker({
        suggestedName: file.fileName,
        types: [{ description: '文件', accept: { 'application/octet-stream': [] } }],
      })
    } catch { return }
    const resp = await fetch(url, { headers: { 'X-Auth-Token': token }, signal: options.signal })
    if (!resp.ok) throw new Error(`HTTP ${resp.status}`)
    const writable = await handle.createWritable()
    const total = Number(resp.headers.get('Content-Length') || file.sizeBytes)
    let downloaded = 0
    options.onProgress?.(downloaded, total)
    while (true) {
      const { done, value } = await resp.body!.getReader().read()
      if (done) break
      await writable.write(value)   // 直接写入磁盘，不经过内存
      downloaded += value.length
      options.onProgress?.(downloaded, total)
    }
    await writable.close()
  } else {
    // 非 Chromium fallback：<a> 标签原生下载（token 经查询参数透传）
    const a = document.createElement('a')
    a.href = url + (token ? `?token=${encodeURIComponent(token)}` : '')
    a.download = file.fileName
    a.click()
  }
}
```

**要点**：
- 工具只认 `url`，不再耦合具体端点；调用方负责拼出下载地址（文件端点用 `getDownloadUrl(file.id)`，备份端点用 `VITE_API_BASE_URL + /api/admin/system/backup/download/{name}`）。
- token 默认读 `localStorage.admin_token`，也可由调用方经 `options.token` 显式传入（如备份页用 `authStore.token`）。
- Chromium 走 `X-Auth-Token` 请求头、非 Chromium 回退拼 `?token=`（要求对应后端端点支持查询鉴权双通道）。
- 通过 `onProgress` 回调暴露进度、`signal` 支持 `AbortController` 取消。
- 全程内存占用 ≈ 单个 chunk（8KB），与文件大小无关。

#### 四个下载入口（统一经 downloadAdminFile）

| 入口 | 调用路径 |
|------|---------|
| 表格行「下载」按钮 | `startDownload(row)` → `downloadAdminFile({ url: getDownloadUrl(row.id), ... })` |
| 文件详情弹窗「下载」按钮 | `startDownload(selectedFile)` → 同上 |
| 预览弹窗「下载」按钮 | `FilePreview` 仅 `emit('download', fileId)`，父组件 `onPreviewDownload` 调 `startDownload(...)` |
| 备份管理页「下载」按钮 | 直接 `downloadAdminFile({ url: base + /backup/download/{name}, ... }, { token: authStore.token })` |

`startDownload` 在父组件（`views/files/index.vue`）保留进度浮层 `dl` 与取消逻辑，把 `onProgress` / `signal` 透传给 `downloadAdminFile`。`FilePreview` 改为纯展示 + 事件，不持有任何鉴权或下载实现，保持通用。

**进度条**：使用现有 `DownloadProgress.vue` 组件，显示文件名、已下载/总大小、百分比、取消按钮。

#### 预览弹窗

```vue
<div v-if="previewFile" class="fixed inset-0 z-50 flex items-center justify-center">
  <div class="absolute inset-0 bg-black/70" @click="previewFile = null" />
  <div class="relative bg-white rounded-lg shadow-xl max-w-4xl max-h-[90vh] overflow-hidden flex flex-col">
    <!-- 图片 -->
    <img v-if="isImage" :src="previewUrl" class="max-h-[80vh] object-contain" />
    <!-- 视频 -->
    <video v-else-if="isVideo" :src="previewUrl" controls class="max-h-[80vh]" />
    <!-- 音频 -->
    <audio v-else-if="isAudio" :src="previewUrl" controls class="p-8" />
    <!-- 不支持 -->
    <div v-else class="p-8 text-center text-gray-500">
      该文件类型不支持预览
    </div>
    <!-- 底部「下载」改为 emit('download')，由父组件统一调度 -->
  </div>
</div>
```

预览 URL 构造：复用已有的 `/api/admin/system/files/{rel_path}` 端点（无需认证，支持路径遍历保护），前端拼接完整 URL。

### 2.3 可预览文件类型判定

```typescript
const PREVIEWABLE = {
  image: ['image/jpeg', 'image/png', 'image/gif', 'image/webp'],
  video: ['video/mp4', 'video/webm', 'video/quicktime'],
  audio: ['audio/mpeg', 'audio/wav', 'audio/ogg'],
}

function canPreview(mime_type: string | null): string | false {
  if (!mime_type) return false
  for (const [type, mimes] of Object.entries(PREVIEWABLE)) {
    if (mimes.includes(mime_type)) return type
  }
  return false
}
```

## 四、注意事项

1. **安全**：下载端点需管理员鉴权（手动 header/query 双通道）；路径遍历保护复用 `resolve_safe_path`
2. **Chrome 兼容**：强制 `application/octet-stream` + `attachment` 阻止 Chrome 对 MP4 的视频预览行为，避免另存为对话框卡死
3. **流式写入**：Chromium 使用 `showSaveFilePicker` + `WritableStream`，数据逐块写入磁盘不经过内存；其他浏览器 fallback 到 `<a>` 标签
4. **预览**：复用已有的 `/api/admin/system/files/` 静态文件端点，无需新建端点
5. **CORS**：下载用 `fetch` + `X-Auth-Token` header，同域无 CORS 问题
6. **MIME 映射**：下载端点统一返回 `application/octet-stream`；前端预览根据 `File.mime_type` 判定渲染方式
