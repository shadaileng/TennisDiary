# Step 80：AI 服务商多模型支持（模型列表 + 二选下拉）

## 一、背景

Step 79 引入 `ai_providers` 服务商表与 `ai.provider` 直选，但每条记录只有单个 `model` 字段。实际供应商（如阿里云百炼）支持多个模型（`qwen-vl-max` / `qwen-plus` / ...），切换模型需要手动改 `ai.model` 覆盖或重复维护多个服务商记录。

参考开源 Agent 产品（LobeChat / Dify 等）的 Provider 配置：**一个服务商记录维护多个模型**，配置时「先选服务商、再选模型」两步下拉直选。

## 二、目标

1. `ai_providers.model`（单值）→ `models`（JSON 列表），**默认模型 = 列表首项**（`default_model`）。
2. 配置页 AI 卡片：选中服务商后出现「模型」下拉，选项 = 该服务商 `models`；选择写入 `ai.model` 覆盖，「跟随服务商默认」清除覆盖。
3. 语义保持：`model = ai.model 覆盖 > 服务商默认模型`；`ai.model` 覆盖全局优先，切服务商后旧覆盖残留时以下拉「自定义: X」展示。
4. 服务商管理弹窗表单改为**模型列表编辑器**（多行 + 增删，首行为默认）。
5. 生产数据无损升级：迁移回填 `model` → `models[0]`。

## 三、方案设计

### 3.1 数据模型

```
ai_providers
├── models   Text  JSON 数组字符串，如 '["qwen-vl-max","qwen-plus"]'（沿用 analysis.report / event_log.extra 的 Text+JSON 模式）
```

- `default_model = models[0]`（列表首项）。
- JSON 解析 try/except 兜底，异常返回 `[]`。

### 3.2 迁移（手写，SQLite batch）

1. `batch.add_column(models Text nullable)`
2. 逐行回填 `models = json.dumps([model])`
3. `batch.alter_column(models, nullable=False)` + `batch.drop_column(model)`

### 3.3 后端服务

- `ai_provider_service.py`：`parse_models` / `dump_models`；`_build_provider_item` 返回 `models: list` + `default_model`（替换 `model`）；`_validate_models`（非空、逐项 trim、去空后至少 1 项，否则 400）；`create/update_provider` 改用 `models`。
- `config_service._resolve_ai_config`：`model = _get_override_value("ai.model") or provider.default_model`。
- `schemas/admin.py`：`AiProviderRequest.model: str` → `models: list[str]`（`min_length=1`）。
- ai-status 响应结构不变（`ai.model` 已是解析后的生效模型）。

### 3.4 配置注册表

- `ai.model` 保持 `VALUE_TYPE_STR`（自定义模式自由文本不变），仅更新描述。

### 3.5 Admin 前端

- 状态卡片「模型」行 → 下拉（选中服务商时）：选项 = 服务商 `models` + `跟随服务商默认`；生效模型不在列表时追加 `自定义: X`。选择写 `ai.model`，跟随默认调 `resetConfig('ai.model')`（`DELETE /api/admin/config/{key}`）。
- 服务商管理弹窗：表格「默认模型」列显示 `default_model`；表单改模型列表编辑器（多行输入 + 删除 + 添加，首行为默认）。
- `api/config.ts`：`AiProvider` / `AiProviderPayload` 的 `model` → `models: string[]` + `default_model`。
