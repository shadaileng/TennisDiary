# 75-2：视频上传与抽帧

## 一、背景与目标

总纲 75-B2 §4.3：小程序 `uni.chooseVideo` → `uni.uploadFile`（multipart）直传后端，服务端 `ffmpeg` 按采样时间点抽帧（640px 宽 JPEG，质量 0.72），把「AI 用的原始帧」与「封面/高光帧」所需的抽帧能力从浏览器端迁移到服务端。

| 目标 | 说明 |
|------|------|
| 端点 | `POST /api/video/upload`（multipart，鉴权 `get_current_user`） |
| 入参 | `file`（视频）+ `mode`（single/full）+ `kind` + 可选 `hit_time`（击球瞬间秒数） |
| 出参 | 帧 base64 数组 + `duration` + `thumbnail`(base64) + `hit_time` |
| 抽帧 | single 7 帧 / full 8 帧；封面 single=hit / full=中点 |
| 限制 | single ≤ 15s、full ≤ 90s（沿用参考版） |
| ffmpeg | 系统 `ffmpeg` 优先，`imageio-ffmpeg` 兜底（魔搭 CPU 容器可能无系统 ffmpeg） |

## 二、现状

| 项 | 现状 |
|----|------|
| 上传模式 | `upload.py` 已有 avatar 上传（multipart 落盘 + 路径防护）可参照 |
| 存储 | `settings.UPLOAD_DIR`（`{DATA_DIR}/uploads`），视频落 `videos/{user_id}/` |
| 依赖 | `python-multipart`、`aiofiles` 已有；**缺 `imageio-ffmpeg`（兜底 ffmpeg）** |
| 参考资产 | `CoachAnalyze.tsx`：single 采样偏移 `[-0.6, -0.35, -0.15, 0, 0.2, 0.5, 0.9]`（7 帧）、full 均匀 `duration*(i+0.5)/8`（8 帧）、`captureFrame(video, 640, 0.72)` |

## 三、关键契约

- **采样时间点**（与参考版一致，`t=hit_time`）：

```
single: [-0.6, -0.35, -0.15, 0, 0.2, 0.5, 0.9] → clamp(hit+dt, 0.01, duration-0.01)
full:   [duration*(i+0.5)/8 for i in range(8)] → clamp(..., 0.01, duration-0.01)
```

- **封面时间**：single = `hit_time`；full = `duration/2`；
- **帧规格**：宽度 640px（等比缩放）、JPEG 质量 0.72；
- **响应**：

```json
{
  "code": 0, "message": "ok", "success": true,
  "data": {
    "frames": ["data:image/jpeg;base64,..."],   // 按时间顺序
    "duration": 8.5,
    "thumbnail": "data:image/jpeg;base64,...",
    "hit_time": 2.4,
    "mode": "single",
    "kind": "正手"
  }
}
```

- **时长限制**：single > 15s 或 full > 90s → 400 拒绝；
- **降级**：ffmpeg 不可用 → 503（提示配置 ffmpeg）；视频不可解析 → 400。

## 四、详细方案

### 4.1 服务层（新建 `server/app/services/video_service.py`）

| 函数 | 职责 |
|------|------|
| `find_ffmpeg()` | `shutil.which("ffmpeg")` 优先，否则 `imageio_ffmpeg.get_ffmpeg_exe()`，均无返回 `None` |
| `probe_duration(path)` | `ffprobe`（若有）取时长，否则解析 `ffmpeg -i` stderr 的 `Duration:` 行 |
| `build_sampling_times(mode, duration, hit_time)` | 按 §三 契约生成采样时间点（hit_time 缺省 = duration/2） |
| `extract_frames(path, times, width=640, quality=0.72)` | `ffmpeg -ss T -i path -frames:v 1 -vf scale=640:-1 -q:v` 逐点抽帧，返回 `list[bytes]`（JPEG） |
| `process_video(file_path, mode, hit_time)` | 编排：probe → 校验时长 → 采样 → 抽帧 → 封面帧 → 返回 dict |

要点：

- `find_ffmpeg` 每次调用检测（部署容器变化后无需重启）；不可用时抛 `FfmpegUnavailableError`（路由转 503）；
- `probe_duration` 优先 `ffprobe -v error -show_entries format=duration -of default=nw=1:nk=1`，解析失败回退 `ffmpeg -i` stderr 正则 `Duration: (\d+):(\d+):(\d+\.\d+)`；
- 抽帧命令用 `subprocess.run([...], capture_output=True, timeout=30)`，任一帧失败抛异常；
- 封面取「采样时间点中离 hit_time 最近的一帧」或单独 `-ss hit_time` 再抽一帧（推荐后者，语义清晰）。

### 4.2 路由（新建 `server/app/routers/video.py`）

- `POST /api/video/upload`，`APIRouter(prefix="/api/video", tags=["video"])`；
- 参数：`file: UploadFile = File(...)`、`mode: Literal["single","full"] = Form("single")`、`kind: str = Form("综合")`、`hit_time: float | None = Form(None)`；
- 流程：
  1. 校验 `file.content_type` 以 `video/` 开头（或扩展名 mp4/mov/m4v）→ 400；
  2. 落盘 `UPLOAD_DIR/videos/{user_id}/{uuid}.{ext}`（分块写入，参照 avatar）；
  3. `process_video(...)` 成功 → 返回 `ApiResponse(data=...)`；
  4. `FfmpegUnavailableError` → 503（detail 提示安装 ffmpeg）；其余异常 → 400；
  5. 返回前**不删除源视频**（75-4 落库需 `video_url`）；异常时清理临时文件。
- 注册 `main.py`：`from app.routers import video` + `app.include_router(video.router)`。

### 4.3 依赖与配置

- `pyproject.toml`：新增 `imageio-ffmpeg>=0.5`（兜底 ffmpeg 二进制）；
- 无需新增 config（沿用 `UPLOAD_DIR` / `MAX_UPLOAD_SIZE_MB`）。

## 九、风险与注意事项

| 风险 | 说明与对策 |
|------|-----------|
| 魔搭容器无系统 ffmpeg | `find_ffmpeg` 优先系统，回退 `imageio-ffmpeg`；仍无 → 503 提示 |
| ffprobe 缺失 | `probe_duration` 回退解析 `ffmpeg -i` stderr |
| 抽帧耗时 | 单点抽帧 ≤ 8 次，每次 timeout 30s，总耗时可控 |
| 请求体大小 | 上传本身即大体积，魔搭网关限制走 CF Workers 透传（67 已具备） |
