# 138 文件管理重构（统一门面 + MD5 命名 + 引用计数 + 扫描挂钩）

影响面：`server/app`（services / routers / models / alembic）、`admin/src/views/files`、`admin/src/api/files.ts`
小程序端：**无改动**（目录结构 `avatars|gears|videos/{user_id}/` 不变，仅文件名变化）

## 一、需求

> 文件管理重构，保留同一用户单一文件记录，文件名以 `{md5}.{后缀}` 的形式保存，
> 每个文件在小程序中使用一次引用次数 +1，文件扫描和业务挂钩。
> 后端使用统一的工具方法管理文件。

## 二、关键决策

| 项 | 决策 |
|---|---|
| 存储结构 | 保留分类目录 + 用户隔离：`UPLOAD_DIR/{avatars\|gears\|videos}/{user_id}/{md5}.{ext}` |
| 引用计数 | 业务关联时后端自动加减，前端无感 |
| 扫描挂钩 | 业务引用注册表 + 五态分类 |
| 存量迁移 | Alembic（DDL）+ 管理端一键迁移（数据，支持预演） |
| 旧 API | 一次性全量替换后删除，不留兼容别名 |

## 三、架构：唯一门面

```
routers / 其它 service
        │  只允许 import 这一个
        ▼
app/services/file_service.py   ← 统一门面
        │  内部实现，外部禁止直接 import
        ├── file_store.py         物理存储：MD5 命名、路径推导、写盘/删盘、MIME 兜底
        ├── file_refs.py          业务引用注册表（column / json_list / json_dict 提取器）
        └── file_ref_service.py   引用计数唯一变更实现（file_bindings 绑定表）
```

门面 API：

```python
# 登记
register(db, user_id, *, content=None, src_path=None, category, original_name="",
         ext="", mime_type="", security_checked=None, business=None) -> tuple[File, bool]
register_batch(db, user_id, items[FileDraft], business=None) -> list[File]
# 引用计数（唯一变更入口）
bind(db, user_id, rel_path, business_type, business_id, field="")
unbind(db, user_id, rel_path, business_type=None, business_id=None, field=None)
rebind(db, user_id, business_type, business_id, new_paths, field="") -> dict
unbind_record(db, business_type, business_id) -> int
# 路径与元数据
build_rel_path / resolve / abs_of / rel_of / exists / size_of / md5_of / mime_of / find_by_md5
# 查询扫描
owned_by / collect_business_refs / classify / scan / query_files / count_files / source_stats
# 删除回收
soft_delete / soft_delete_batch / cleanup / cleanup_unbound / cleanup_paths / cleanup_intermediates
# 迁移
migrate_to_md5(db, dry_run=True) -> dict
```

**架构守卫**：`tests/test_file_architecture.py` 断言 `app/routers/**` 与
`services/{pose_service,video_service,pipeline}.py` 不得出现 `uuid4(`、`open(...,"wb")`
写受管文件、`ref_count` 自增自减、直接 `from app.models.file import File`。

## 四、数据模型变更

### 1. `files` 表

- 删除 `uq_files_original_name`（MD5 命名后跨用户必然同名）
- 新增部分唯一索引（软删行被排除，允许重新上传）：

```sql
CREATE UNIQUE INDEX uq_files_user_md5_active
  ON files(user_id, md5) WHERE deleted_at IS NULL;
```

- `ref_count` 默认值改为 `0`，语义从「重复记录条数」改为「业务引用次数」

### 2. 新增 `file_bindings` 表

`file_bindings(file_id, user_id, business_type, business_id, field, created_at)`，
唯一约束 `(file_id, business_type, business_id, field)`。

它是引用计数的**唯一事实来源**：

- `bind` = 插入绑定（唯一约束天然幂等）→ `ref_count + 1`
- `unbind` = 删除绑定 → `ref_count - 1`
- `rebind` = 按目标集合差量同步，重复调用不重复计数
- 反查「某文件被哪些业务记录引用」不再依赖脆弱的字符串包含匹配

### 3. Alembic 迁移

| revision | 内容 |
|---|---|
| `b7d41e0c9a35` | 合并同 `(user_id, md5)` 重复记录 → 删 `uq_files_original_name` → 建部分唯一索引 |
| `d4e8b2f17c09` | 建 `file_bindings` + 回填主引用（avatar/photo/video_url/thumb）+ `ref_count` 重置为绑定数 |

## 五、业务引用注册表

`app/services/file_refs.py` 声明「哪些表哪些字段引用受管文件」：

| business_type | 模型 | 提取字段 |
|---|---|---|
| user | `User` | `avatar_url`（column） |
| gear | `Gear` | `photo`（column） |
| analysis | `Analysis` | `video_url` / `thumb`（column）、`highlights`（json_list）、`pose.skeleton_video_url` / `skeleton_thumb`（json_dict）、`pose.skeleton_frames`（json_dict 列表键） |
| analysis_video_info | `AnalysisVideoInfo` | `derivatives[].rel_path`（json_list_of_dict）、`source_file_id` / `playback_file_id`（外键列） |

## 六、扫描五态

`file_service.scan(db, user_id=None)`：

| 状态 | 含义 |
|---|---|
| `in_use` | 已登记，且被业务记录引用 |
| `unreferenced` | 已登记，但无任何业务引用 |
| `missing` | 已登记，但物理文件缺失 |
| `orphan` | 磁盘有文件，但 File 表无记录 |
| `unregistered_ref` | 业务记录引用了未登记的路径 |
| `marked_deleted` | 已软删，待物理清理 |

Admin `POST /api/admin/files/scan` 保持原有 `orphans` 字段兼容，新增 `status_counts`。

## 七、存量迁移

`POST /api/admin/files/migrate-md5?dry_run=true|false`（管理端「存量迁移」按钮先预演再执行）：

1. 推导目标路径 `{分类}/{user_id}/{md5}.{后缀}`
2. 已符合 → `already_named`；物理文件缺失 → `missing_files`
3. 目标已存在且内容相同 → 复用并删除源文件；内容不同 → `conflicts`（不覆盖）
4. 移动物理文件 + 更新 `rel_path` + 回填业务表旧路径
5. 合并同 `(user_id, md5)` 重复记录（保留 id 最小者，`ref_count` 求和）
6. 幂等：重复执行 `renamed == 0`
