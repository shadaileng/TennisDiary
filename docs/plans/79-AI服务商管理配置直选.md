# Step 79：AI 服务商管理 + 配置直选

## 一、背景

Step 78 引入了通用动态配置框架，AI 三件套（`ai.api_key` / `ai.base_url` / `ai.model`）可在 Admin 配置页在线编辑。但每次更换供应商 / 切换模型仍需手动填写接口地址与密钥，且无法维护多个可切换的 API 凭据组合。

参考开源 Agent 产品的 API Key 配置方式（如 LobeChat / Dify / FastGPT 的 Provider 模型）：**维护一个服务商列表，配置时直选已维护的服务商**。本次为 Step 78 的 AI 分类增强：

1. 新增 `ai_providers` 服务商表，**全部由 Admin 手动维护**（新增/编辑/删除，无代码内置预置，更灵活）。
2. 新增配置项 `ai.provider`（下拉直选），选中后 base_url / api_key 运行时**引用**服务商条目（修改条目全局生效，避免配置漂移）。
3. 模型保留独立覆盖：`model = ai.model 覆盖 > 服务商条目默认 model`。
4. 提供「自定义」选项回落现有三项独立编辑（老用户零迁移）。

## 二、目标

1. `ai_providers` 表：name / base_url / api_key / model / enabled / sort_order，Admin 手动维护。
2. `ai.provider` 可编辑 select 配置项，options 动态 = 全部服务商 + `custom`。
3. `get_ai_config` 引用解析：选中服务商 → base_url/api_key 直读条目、model 覆盖 > 条目默认；未选/自定义 → 独立覆盖 > 环境变量默认。
4. Admin 配置页 AI 卡片改版：服务商下拉直选 + 生效配置展示 + 「管理服务商」弹窗（增删改）。
5. 保护策略：被 `ai.provider` 选中引用的服务商禁止删除（409）；`name` 唯一。

## 三、方案设计

### 3.1 核心语义（引用式）

```
生效 AI 配置 = 选中服务商条目(引用) > 独立覆盖(ai.api_key / ai.base_url) > 环境变量默认
model = ai.model 覆盖 > 服务商条目默认 model > 环境变量 AI_MODEL
未选中服务商（custom/空）时回落现状：独立覆盖 > 环境变量默认
```

- 服务商条目修改后全局生效（引用非复制）。
- 选中条目被删除/禁用时自动回落 custom 语义，不中断服务。

### 3.2 数据模型 `app/models/ai_provider.py`（新增）

```python
class AiProvider(Base):
    __tablename__ = "ai_providers"
    id = Column(Integer, primary_key=True, autoincrement=True)
    name = Column(String(64), unique=True, nullable=False)    # 显示名（唯一，直选键）
    base_url = Column(String(255), nullable=False)            # OpenAI 兼容基地址
    api_key = Column(String(255), nullable=True)              # 密钥（页面仅掩码）
    model = Column(String(64), nullable=False)                # 默认模型
    enabled = Column(Boolean, default=True)                   # 启用状态
    sort_order = Column(Integer, default=0)                   # 排序
    created_at = Column(Float, default=0)
    updated_at = Column(DateTime, server_default=func.now(), onupdate=func.now())
```

- 登记到 `app/models/__init__.py`。
- Alembic 迁移 `add ai_providers table`（autogenerate）。

_it("ai.provider", "ai", "服务商", "直选已维护的 AI 服务商，自定义时使用下方独立配置",

### 3.4 服务商服务 `app/services/ai_provider_service.py`（新增）

| 函数 | 说明 |

| `list_providers(db) -> list[dict]` | 列表（api_key 掩码 + `is_selected` 是否当前被引用） |

- 掩码复用 `config_service.mask_secret`（`sk-****last4`）。

### 3.5 配置服务调整 `app/services/config_service.py`

- `get_ai_config(db)` 改造为引用解析，`AIConfig` 增加 `provider: str` 字段：

```python
provider_name = get_config_value(db, "ai.provider")          # 空 = custom
if provider_name and provider_name != "custom":
    p = get_provider_by_name(db, provider_name)
    if p:  # 引用生效
        api_key = p.api_key or 独立覆盖 ai.api_key or env
        base_url = p.base_url
        model = get_config_value(db, "ai.model") or p.model
# custom/条目缺失：独立覆盖 > env
```

- `_build_item` 支持动态 options：`ai.provider` 的 options = 全部服务商 name + `custom`（来自 DB，非注册表静态值）。

### 3.6 管理端 API `app/routers/admin/ai_providers.py`（新增）

前缀 `/api/admin/config/providers`，tag `admin-ai-providers`，全部接口 `require_permission("system:config")`：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/` | 服务商列表（掩码 + is_selected） |
| POST | `/` | 新增（body: name/base_url/api_key/model/enabled） |
| PUT | `/{pid}` | 编辑 |
| DELETE | `/{pid}` | 删除（被选中引用 → 409） |

校验：base_url 须 `http(s)://` 开头；name 唯一（新增与编辑均校验）；删除内置保护交由业务（本设计无内置，全部可删，仅保护「被引用」）。

### 3.7 运行时接线

- `app/main.py`：注册 `admin_ai_providers` 路由。
- `app/routers/admin/system.py`：ai-status 增加 `provider` 字段（当前生效服务商名，custom 为 `"custom"`）。
- `app/routers/ai.py`：`analyze` 已走 `get_ai_config(db)`，无需改动（引用解析在服务层）。

### 3.8 Admin 前端

| 文件 | 改动 |
|---|---|
| `src/api/config.ts` | `AiProvider` 类型 + `getProviders / addProvider / updateProvider / deleteProvider` |
| `src/views/system/config.vue` | AI 卡片改版：服务商下拉（providers + 自定义）+ 生效配置展示（key 掩码/base_url/model）+ 「管理服务商」弹窗（表格 + 新增/编辑表单 + 删除）；custom 时显示原三项独立编辑；保留模型独立覆盖输入 |

交互细节：

- 服务商下拉保存到 `ai.provider`（走既有 `PUT /api/admin/config/{key}`，`custom` 语义已内建）。
- 删除被引用服务商时前端直接提示后端 409 文案（「请先切换服务商」）。
- secret 输入留空 = 保持不变（沿用 Step 78 语义）；新增服务商时留空 = 空 key。
