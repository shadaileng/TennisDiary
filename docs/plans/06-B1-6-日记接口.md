# Step B1-6：日记 CRUD 接口

## 一、目标

实现 `/api/diaries` 日记数据的增删改查接口，作为 B1 数据层 CRUD 的第一块（后续 gears / weights / checkin 等同构接口可据此范式复制）。

## 二、前置条件

- B1-3 完成（Diary 模型 `app/models/diary.py`）
- B1-4 完成（Pydantic Schemas：`DiaryCreate` / `DiaryUpdate` / `DiaryResponse` / `CostItem` / `GearUse`）
- B1-5 完成（JWT 鉴权 `get_current_user`，所有数据接口需鉴权）

## 三、接口设计

| 端点 | 方法 | 说明 | 鉴权 |
|---|---|---|---|
| `/api/diaries` | GET | 当前用户日记列表（按 date 倒序） | 是 |
| `/api/diaries` | POST | 创建日记 | 是 |
| `/api/diaries/{id}` | GET | 日记详情 | 是 |
| `/api/diaries/{id}` | PUT | 编辑日记 | 是 |
| `/api/diaries/{id}` | DELETE | 删除日记 | 是 |

### 3.1 关键约束

- 所有查询强制 `user_id == current_user.id`，禁止越权访问他人数据。
- `costs` / `gears` 为 JSON 字符串存储（`Text` 列），接口层用 `list[CostItem]` / `list[GearUse]` 收发，入库前 `json.dumps`、出库后 `DiaryResponse` 经由 ORM `from_attributes` 时由模型方法还原（本接口层直接构造响应：将 JSON 解析为对应 Pydantic 列表）。
- `created_at` 入库为 Unix 时间戳（`time.time()`）；`DiaryResponse.created_at` 为 float。
- `intensity` / `mood` 在 `DiaryCreate` 已限定 1-5，路由层无需重复校验。
- 更新采用「仅覆盖传入字段」语义（`DiaryUpdate` 全可选）：对 `costs`/`gears` 等复杂字段，传入 `None` 表示不更新，传入列表则覆盖。

## 四、详细执行步骤

### 4.1 路由模块（`app/routers/diaries.py`，新增）

- `get_diaries`：`db.query(Diary).filter_by(user_id=...).order_by(Diary.date.desc()).all()`
- `create_diary`：`DiaryCreate` → 构造 `Diary`，`costs`/`gears` 经 `json.dumps` 落库；`commit`/`refresh` 后返回 `DiaryResponse`。
- `get_diary`：校验归属，不存在返回 404。
- `update_diary`：遍历 `DiaryUpdate` 已设置的字段更新；`costs`/`gears` 重新 `json.dumps`。
- `delete_diary`：校验归属后 `db.delete`。

> 注意：`Diary.costs` / `Diary.gears` 是 JSON 文本，需提供响应构造辅助函数 `diary_to_response(diary)`：解析 JSON 文本为 `list[CostItem]` / `list[GearUse]` 后实例化 `DiaryResponse`。

### 4.2 注册路由（`app/main.py`）

- `from app.routers import diaries`
- `app.include_router(diaries.router)`
