# 101：后端日志细化与异常静默处理修复

## 背景

生产环境排查问题时发现：部分异常被静默吞掉或只记录了 `str(exc)` 丢失 traceback，导致难以定位根因。本次全面审计后端所有 `except` 块，确保：
1. 所有异常至少记录 WARNING/ERROR 级别日志
2. 关键路径异常必须带 `exc_info=True` 保留完整 traceback
3. 降级/兜底场景必须有明确日志说明

## 问题分类

## 修复方案

### 原则

1. **`pass` → `log.debug/warning`**：静默场景必须有至少 DEBUG 级别日志
2. **`from None` → `from exc` 或先记录再 raise**：保留异常链
3. **`str(exc)` → `exc_info=True`**：保留完整 traceback
4. **降级场景必须有 WARNING 日志**：说明降级原因和触发条件
