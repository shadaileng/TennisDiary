# Phase B2：AI 网关三件套总纲

> **编号澄清**：总纲 01 中原始 **B2 = AI 网关三件套**（AI 代理 + 视频抽帧 + 姿态推理），至今未实施；项目内 `43-B2` 为执行中扩展出的**后台管理 API**，与本方案无关。本方案为总纲 B2 的实施总纲，编号顺延为 75。

## 一、目标

实现 Tennis Diary 小程序端「电子教练」所需的三大后端能力，将参考 Web 版中运行于浏览器的 AI 分析/视频抽帧/姿态推理整体收敛到 FastAPI 服务端：

| 能力 | 端点 | 说明 |
|------|------|------|
| AI 六维评分代理 | `POST /api/ai/analyze` | OpenAI 兼容接口代理，AI Key 仅存服务端 |
| 视频上传 + 抽帧 | `POST /api/video/upload` | 接收视频，ffmpeg 抽关键帧 |
| 姿态推理 | `POST /api/pose/analyze` | MediaPipe Python 推理，返回关键点与角度测量 |

完成后小程序端只需「上传视频 → 等待 → 出报告」，与总纲 01 §6.2 第 2 条「砍掉端侧姿态识别」的战略一致。

## 二、需求概述

| 需求项 | 说明 |
|--------|------|
| 功能范围 | AI 评分、视频抽帧、姿态推理三件套 + 电子教练前端（Phase 4）+ 分享工坊（Phase 5） |
| AI 兼容 | 复用参考版 `ai.ts` 的 prompt 与 JSON 契约（OpenAI 兼容 / 阿里云百炼），Key 移入服务端配置 |
| 上传方式 | 小程序 `uni.chooseVideo` → `uni.uploadFile`，multipart 直传后端 |
| 抽帧策略 | ffmpeg 按采样时间点抽帧（640px 宽 JPEG），single/full 两种模式 |
| 姿态推理 | MediaPipe Python（CPU 推理），输出 33 关键点 + 肘角/膝角/躯干倾角测量 |
| 鉴权 | 统一 `X-Auth-Token`（魔搭网关占用 `Authorization`，见 66） |
| 报告落库 | 分析报告持久化（参考 `AnalysisReport` 结构），支持历史查询与重复查看 |
| 部署约束 | 魔搭 Docker 创空间 CPU 实例，需验证 ffmpeg 可用性 |

## 三、当前项目现状

### 3.1 后端现状（server/）

- 路由：`routers/` 下已有 `auth/diaries/gears/weights/checkin/stats/files/upload/events` 与 `admin/`（13 个），**尚无 AI/视频/姿态路由**；
- 服务层：`services/` 仅 `wx_service.py`（微信登录）；
- 依赖（`pyproject.toml`）：已有 `httpx`（可复用做 AI 代理）、`Pillow`（图片处理）、`python-multipart`、`aiofiles`；**缺少 `openai`（可选）、`mediapipe`、系统级 `ffmpeg`**；
- 鉴权：统一 `X-Auth-Token` + `get_current_user`（66 改造后已稳定）；
- 统一响应：`{"code", "message", "success", "data"}`（55 已统一）；
- 部署：魔搭 Docker 创空间（当前启用）+ CF Workers 代理（67），CPU 实例。

### 3.2 参考源码可复用资产（docs/reference/tennis-diary/src/）

| 文件 | 内容 | 迁移去向 |
|------|------|---------|
| `ai.ts` | `chatVision`（OpenAI 兼容调用、120s 超时）、`analyzeSwing`（六维评分 prompt + NTRP 标尺 + JSON 解析兜底）、`buildLocalReport`（本地降级）、`ocrReceipt`、`polishCaption` | prompt 与契约原样搬入服务端；Key 存 `.env` |
| `pose.ts` | `getPoseLandmarker`（WASM + GPU 委托，浏览器端）、`detectPose`、`drawSkeleton`、`measureAngles` | 推理逻辑迁移为 MediaPipe Python；33 关键点与连接表沿用 |
| `pages/CoachAnalyze.tsx` | 三步交互（setup→video→running）、采样时间点（single 7 帧 / full 8 帧）、640px 抽帧、姿态测量、高光帧 | Phase 4 小程序页参考（抽帧改由服务端完成） |
| `pages/CoachReport.tsx` | 六维评分报告展示、精彩瞬间、分享入口 | Phase 4 报告页参考 |
| `pages/Share.tsx` | 分享卡片 Canvas 绘制、保存图片、文案复制 | Phase 5 分享工坊参考 |

### 3.3 关键契约（来自 ai.ts，须原样保留）

- 六维维度：`准备启动 / 动力链 / 击球时机 / 随挥收拍 / 拍面控制 / 身体稳定`；
- 报告 JSON：`score / summary / ntrp / dimensions[] / rhythm / strengths[] / improvements[]`；
- 评分标尺：90-100 职业级几乎不给；业余视频大多 55-70；`ntrp` 必须与总分档位一致；
- 降级路径：无 Key / 推理失败时返回本地降级报告（score=0 + 说明），不虚构分析。

## 四、技术方案

### 4.1 整体架构

```
小程序（uni-app）
  uni.chooseVideo → 上传视频（multipart）
        │
        ▼
FastAPI 后端（魔搭创空间）
  ┌─────────────────────────────────────────────────┐
  │ /api/video/upload   ffmpeg 抽帧（640px JPEG）    │
  │ /api/pose/analyze   MediaPipe 姿态推理(CPU)      │
  │ /api/ai/analyze     OpenAI 兼容代理（Key 服务端） │
  │                      └─→ 阿里云百炼 / 兼容端点    │
  │ 报告落库（SQLite，AnalysisReport 结构）          │
  └─────────────────────────────────────────────────┘
```

### 4.2 AI 评分代理（75-1）

- 入参：`frames`（base64 JPEG 数组）+ `kind`（正手/反手/发球…）+ `mode`（single/full）；
- 出参：`AnalysisReport`（六维 JSON，结构见 §3.3）；
- 实现：直接复用 `httpx` 调 `{baseUrl}/chat/completions`，无需引入 `openai` SDK（也可选装）；120s 超时；`temperature=0.3`；`max_tokens≈2500`；
- 配置：`AI_API_KEY` / `AI_BASE_URL` / `AI_MODEL` 写入 `server/.env`（模型名默认 `qwen-vl-plus` 等视觉模型）；
- 校验：返回内容 `extractJSON` 解析 + `dimensions` 兜底（与 `ai.ts` 一致）；
- 鉴权：`get_current_user`，失败走降级路径。

### 4.3 视频上传与抽帧（75-2）

- 上传：`POST /api/video/upload`，multipart 文件，落盘 `data/videos/{user_id}/`，限制时长（single ≤ 15s、full ≤ 90s，沿用参考版限制）与大小；
- 抽帧：服务端 `ffmpeg` 按采样时间点抽取（single：命中点 ±0.6/0.35/0.15/0/0.2/0.5/0.9 共 7 帧；full：全片均匀 8 帧），输出 640px 宽 JPEG（质量 0.72）；
- 帧交付：返回帧 base64 或帧文件 URL 列表 + `duration` + `thumbnail`；
- 依赖：系统级 `ffmpeg`。**需在魔搭容器内验证**：`ffmpeg -version` 可用则直接使用；不可用则在 Dockerfile / CI 预装（`apt-get install ffmpeg`）；
- 抽帧也可下沉到子方案内独立脚本（`scripts/extract_frames.sh` 辅助验证）。

### 4.4 姿态推理（75-3）

- 模型：MediaPipe Python `pose_landmarker`（`pose_landmarker_lite`，float16 task 文件，随包/下载后固定路径加载）；
- 推理：CPU 推理（魔搭无 GPU 委托），逐帧输入 JPEG → 输出 33 关键点（归一化坐标 + visibility）；
- 测量：沿用参考版 `measureAngles` 逻辑 → 肘角、膝角、躯干倾角；
- 出参：`landmarks[33] + metrics{elbowAngle, kneeAngle, trunkLean}`；
- 降级：模型加载失败 / 无人检测到时返回空结果，AI 侧走本地降级报告。

### 4.5 数据模型（75-4 前置）

- 新增 `AnalysisReport` ORM 模型（`id / user_id / kind / mode / score / ntrp / summary / dimensions(json) / rhythm / strengths(json) / improvements(json) / video_url / thumb_url / created_at`）；
- 登记 `app/models/__init__.py`，Alembic 迁移；
- 落库时机：AI 分析成功后写入，前端报告页可历史回看（Phase 4）。

### 4.6 部署与配置（贯穿）

- `server/.env` 新增 `AI_API_KEY / AI_BASE_URL / AI_MODEL`；
- Dockerfile（魔搭部署用）追加 `ffmpeg` 安装；`models/` 放 `pose_landmarker_lite.task` 或运行时下载（推荐随镜像打包，避免运行时下载失败）；
- 魔搭网关对请求体大小有限制时，上传接口需走 CF Workers 代理透传（67 已具备）。

## 六、风险与注意事项

| 风险项 | 等级 | 说明与对策 |
|--------|:----:|-----------|
| 魔搭容器无 ffmpeg | 🟠 中 | 先 `ffmpeg -version` 验证；不可用则 Dockerfile 预装；也可考虑纯 Python 方案（`imageio-ffmpeg` 自带二进制）兜底 |
| MediaPipe CPU 推理慢 | 🟠 中 | lite 模型 + 抽帧数量有限（≤8 帧）；必要时降采样输入图 |
| 魔搭请求体大小限制 | 🟡 低 | base64 帧会放大体积，抽帧前先压缩；超大视频走 CF Workers 分块透传 |
| AI Key 泄露 | 🟡 低 | Key 仅存服务端 `.env`，不进入小程序包；OpenAI 兼容端点域名不暴露给前端 |
| AI 幻觉（虚构分析） | 🟡 低 | 保留参考版「画面无法辨识」回退提示 + 本地降级报告 |
| 报告数据结构漂移 | 🟡 低 | 六维 JSON 契约固定，后端 `extractJSON` + 兜底校验，与前端 `AnalysisReport` 类型对齐 |
