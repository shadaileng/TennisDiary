# Step 81：AI 模型可用性校验 + 模型调试脚本

## 一、背景

生产环境 AI 分析静默降级为本地报告（score=0），排查后发现生效模型 `agnes-25-flash` 在 AgnesAI 上游不存在 → 每次请求 503 `model_not_found`，被 `POST /api/ai/analyze` 的 catch-all 吞掉。

根因：**模型名笔误**（文档正确名称为 `agnes-2.5-flash`，带点号）。由于配置期没有任何模型可用性校验，此类错误只能在小程序「发球」后才发现，且表现为静默降级。

## 二、目标

1. **后端**：新增 `POST /api/admin/config/providers/check-models`（权限 `system:config`），两级策略校验模型可用性：
   - **list 模式**：`GET {base_url}/models` 拉取服务商可用模型列表（OpenAI 兼容），比对命中/未命中；
   - **probe 模式**：服务商不支持 `/models` 时（如 Agnes 未文档化该接口）逐模型发 `max_tokens=1` 最小文本探测，模型名不存在时上游秒回非 200。
2. **Admin**：服务商表单加「校验模型」按钮，每行模型 ✓ 绿 / ✗ 红标色，list 模式附可用模型列表，probe 模式逐模型显示原因。
3. **调试脚本**：`server/scripts/debug-ai.py` 直连生效配置（与服务端 `get_ai_config` 同源），支持连通性探测 / 文本对话 / 模型列表 / 完整六维分析，绕开小程序反复发球。

## 三、方案设计

### 3.1 后端端点

```
POST /api/admin/config/providers/check-models
Body: { base_url: str, api_key: str = "", models: list[str] }
```

- 表单值直传，**无需先保存**（新增/编辑表单都能校验），不查库。
- 响应（`ApiResponse[dict]`）：
  - list 成功：`{ok:true, strategy:"list", available:[...], results:[{model, ok, message}]}`
  - probe 兜底：`{ok:true, strategy:"probe", results:[...]}`
  - 连接/超时/鉴权失败：`{ok:false, message}`（镜像 ai-connect 语义，401/403 提前返回「鉴权失败」）
- 解析兼容 `data[]` / `models[]` 数组，取 `id`/`name`/字符串。
- 15s 超时；无 Schema 变更，无需迁移。

### 3.2 调试脚本

```
uv run python scripts/debug-ai.py                 # 等价 --chat ping（最小探测）
uv run python scripts/debug-ai.py --chat "你好"    # 任意文本对话
uv run python scripts/debug-ai.py --models        # GET {base_url}/models
uv run python scripts/debug-ai.py --analyze --image a.jpg --image b.jpg --kind 正手 --mode single
uv run python scripts/debug-ai.py --chat --model X --base-url https://... --api-key sk-xxx
```

- 生效配置解析与服务端一致（`get_ai_config`：DB 服务商引用/覆盖 > env），`--model/--base-url/--api-key` CLI 覆盖优先。
- **不吞错**：非 200 直接打印真实状态码 + 响应体，退出码 1（区别于生产降级）。
- 图片 → base64 dataURL（与小程序生产格式一致），走生产同款 `analyze_swing` 链路。
- 纯函数（`build_data_url` / `parse_available_models`）可单测；空库自动回落 env 配置。

### 3.3 Admin 前端

- `api/config.ts`：`checkProviderModels(payload)` + 响应类型。
- 服务商表单模型编辑器：每行模型校验徽标 + 「校验模型」按钮（`useActionLock` 防重复）+ 结果区（list 可用列表 / probe 逐模型 / 失败 message）。

## 四、测试（TDD）

- `test_ai_providers.py::TestCheckModels`（monkeypatch `httpx.AsyncClient`，复用 TestAiConnect 的 FakeClient 模式）：
  - list 成功（`data[]` 对象 / `models[]` 扁平字符串两种形状）；
  - probe 兜底（GET /models 404 → 逐模型混合 200/503）；
  - `/models` 200 但解析为空 → 回落 probe；
  - 401 → `ok=false` 鉴权失败，不再 probe；
  - 超时 → `ok=false` 连接超时；
  - 缺 base_url / 空 models → 422；无 `system:config` 权限 → 403。
- `test_debug_ai_script.py`：`build_data_url`（前缀 + base64 还原）、`parse_available_models`（对象/扁平/异常）。
