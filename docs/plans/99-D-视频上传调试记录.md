# 99-D：视频上传「无法解析视频时长」调试记录

## 一、问题现象

设备（Android 14, nubia NX712J）通过小程序上传视频后，服务端返回：

```json
{"code":30000,"message":"无法解析视频时长","success":false}
```

同一视频文件在本地 ffprobe 可正常解析（121.12s），curl 上传也成功。**仅设备端上传失败**。

## 二、排查过程

### 2.1 初步验证：排除服务端和文件本身问题

| 测试 | 结果 |
|------|------|
| 本地 ffprobe `docs/reference/VID_20260816_160443.mp4` | ✅ rc=0, duration=121.12s |
| curl 上传同文件到服务端 | ✅ `code:0 dur:121.49` |
| 设备上传 9.7MB 视频 | ❌ `无法解析视频时长` |

结论：服务端 ffprobe/ffmpeg 正常，问题在设备→服务端传输或后续处理流程。

### 2.2 保留失败副本

提交 `ffbb054`：上传失败时 `shutil.copy2` 保留 `_debug_*.mp4` 副本，probe 日志改内联 rc/stderr。

重启服务器后重新上传，日志显示：

```
written=9744360 actual=9744360          # 上传了 9.7MB，写入完整
ffprobe 探测时长失败 rc=%s stderr=%r    # 未格式化（loguru 不支持 %s）
ffmpeg 解析时长失败 ... _seg0.mp4: No such file
```

关键发现：**第一次 ffprobe（原文件）成功**，但之后访问 `_seg0.mp4` 时报 "No such file"。

### 2.3 定位：finally 误删单片段产物

添加诊断日志后确认完整时间线：

```
23:02:32.101  process_video: cuts=[{'start':6.6,'end':7.93}] duration=121.12
23:02:32.101  validate_cuts OK
23:02:32.267  trim_video rc=0 dst_exists=True dst_size=126174   ← 裁切成功
23:02:32.268  trim_and_concat returned: exists=False            ← 文件瞬间消失！
23:02:32.268  probe_duration(_seg0.mp4): rc=1 No such file      ← 文件已不存在
```

**根因**：`trim_and_concat` 使用 `try/finally` 结构，`finally` 块在 `return seg_paths[0]` **之前**执行，把单片段产物 `_seg0.mp4` 删掉了。

```python
# video_service.py trim_and_concat
try:
    for i, cut in enumerate(cuts):
        seg = os.path.join(seg_dir, f"{stem}_seg{i}.mp4")
        trim_video(src, seg, cut["start"], cut["end"] - cut["start"])
        seg_paths.append(seg)
    if len(seg_paths) == 1:
        return seg_paths[0]  # ← finally 在此 return 前执行！
    # ... 多段拼接逻辑
finally:
    for seg in seg_paths:
        if os.path.isfile(seg):
            os.unlink(seg)  # ← 删掉了单片段产物
```

提交 `566580b` + `4c9742f`：单片段时先保存路径到局部变量、clear seg_paths、再 return。

### 2.4 二次修复：video_url 指向已删除文件

修复 trim 后上传成功，但后续 `/api/pose/analyze` 报 `"video_url 非法或不存在"`。

**根因**：`process_video` line 402-403 在裁切后删除了原始上传文件：

```python
if working != path and os.path.isfile(path):
    os.unlink(path)  # 删除原文件
```

但 router 返回的 `video_url` 基于原始 `abs_path` 计算，该文件已不存在。`_resolve_video_dir` 检查 `os.path.isfile(candidate)` 返回 None。

修复：`process_video` 返回 `working_path` 字段，router 用它计算 `video_url`。提交 `a842602`。

### 2.5 附加修复：loguru 日志格式化

日志中 `rc=%s stderr=%r` 始终显示为字面量而非实际值。loguru 使用 `{}` format 风格，不支持 `%s` printf 风格参数。改为 f-string。提交 `e828bef`。

## 三、根因分析

| # | 问题 | 根因 | 影响 |
|---|------|------|------|
| 1 | 单片段裁切后文件消失 | `try/finally` 中 `finally` 在 `return` 前执行，清理了本应保留的产物 | 所有 single 模式带 cuts 上传失败 |
| 2 | pose/analyze 报 video_url 非法 | router 用原始上传路径计算 video_url，但原文件已被裁切流程删除 | 裁切后无法进行姿态分析 |
| 3 | 日志 rc/stderr 未格式化 | loguru 不支持 `%s` printf 风格，参数被忽略 | 排查困难 |

## 四、解决方案

| 修复 | commit | 说明 |
|------|--------|------|
| `trim_and_concat` 单片段不删产物 | `566580b` + `4c9742f` | return 前先 save→clear→return |
| `video_url` 指向裁切后文件 | `a842602` | process_video 返回 working_path，router 据此计算 |
| 日志改 f-string | `e828bef` | loguru 兼容格式 |
| 上传失败保留副本 | `ffbb054` | `_debug_` 副本便于排查 |
| 上传写入诊断日志 | `f91c813` | 记录 written/actual 字节数 |

## 五、验证

- 单元测试 36 passed（test_video.py）
- 端到端：设备上传 9.7MB 视频 + cuts `[6.6, 7.93]` → 裁切成功 → 姿态分析 → AI 评分，全流程走通

## 六、经验总结

1. **Python `try/finally` + `return`**：`finally` 总在 `return` 前执行，不能假设 return 后不再运行清理代码。单片段场景下产物不应被视为临时文件。
2. **文件生命周期管理**：裁切流程删除原文件后，所有引用原路径的地方（video_url、后续分析接口）需要同步更新。
3. **loguru 格式化**：loguru 优先用 `str.format()`（`{}` 风格），`%s` 参数会被忽略。统一用 f-string。
4. **诊断日志策略**：在关键路径加诊断日志（ffprobe rc/stdout/stderr、trim_video cmd/dst_exists/dst_size、上传 written/actual）能大幅缩短排查时间。
