# 99-D：视频上传「无法解析视频时长」调试记录

## 一、问题现象

设备（Android 14, nubia NX712J, 192.168.10.93）通过小程序上传视频时，服务端返回：
```json
{"code":30000,"message":"无法解析视频时长","success":false}
```

同一视频文件在本地用 ffprobe 可正常解析（121.12s），curl 上传也成功。**仅设备端上传失败**。

## 二、排查过程

### 2.1 第一阶段：确认文件完整性

1. **本地 ffprobe 验证**：`docs/reference/VID_20260816_160443.mp4`（109MB, 121.12s）→ ffprobe 正常解析
2. **curl 上传验证**：`curl -X POST /api/video/upload -F "file=@..."` → `code:0 dur:121.49` 成功
3. **结论**：服务端 ffprobe/ffmpeg 本身没问题，问题出在**设备→服务端的传输环节**

### 2.2 第二阶段：保留失败副本

提交 `ffbb054`（fix(server)）：上传失败时保留 `_debug_*.mp4` 副本 + probe 日志改内联 rc/stderr。

重启服务器后重新上传，日志显示：
```
written=9744360 actual=9744360          # 上传了 9.7MB
ffprobe: rc=%s stderr=%r                # 未格式化（loguru 不支持 %s）
ffprobe: rc=1 stderr='...seg0.mp4: No such file'
```

关键发现：**文件上传成功（9.7MB），但 ffprobe 报 "No such file"**。

### 2.3 第三阶段：定位文件消失原因

添加诊断日志后确认：
- 第一次 ffprobe（原文件）→ **rc=0, duration=121.12s** ✓
- `validate_cuts` → OK（cuts=`[{"start":6.6,"end":7.93}]`）
- `trim_video` → **rc=0, dst_exists=True, dst_size=126174** ✓（片段裁切成功）
- `trim_and_concat returned: exists=False` ✗（产物瞬间消失）

**根因**：`trim_and_concat` 的 `finally` 块在 `return seg_paths[0]` **之前**执行，把单片段产物 `_seg0.mp4` 删掉了。

### 2.4 第四阶段：修复 finally 误删

提交 `566580b` + `4c9742f`：单片段时先保存路径到局部变量，再 clear seg_paths，最后 return。

### 2.5 第五阶段：video_url 指向已删除文件

修复 trim 后，上传成功但后续 `/api/pose/analyze` 报 `"video_url 非法或不存在"`。

**根因**：`process_video` 裁切后删除了原始上传文件（line 402-403），但 router 返回的 `video_url` 仍基于原始 `abs_path`，该文件已不存在。

修复：`process_video` 返回 `working_path`，router 用 `working_path` 计算 `video_url`。

提交 `a842602`。

## 三、修复总结

| 问题 | 根因 | 修复 | commit |
|------|------|------|--------|
| probe 日志 `rc=%s` 未格式化 | loguru 不支持 `%s` printf 风格 | 改用 f-string | `e828bef` |
| 上传失败不保留副本 | 无 `_debug_` 逻辑 | 新增 copy2 保留 | `ffbb054` |
| `trim_and_concat` 删掉单片段产物 | `finally` 在 `return` 前执行 | 先 save→clear→return | `566580b` + `4c9742f` |
| `video_url` 指向已删除文件 | router 用原始路径而非 working 路径 | 返回 `working_path` 字段 | `a842602` |
| 设备上传 9.7MB 文件 ffprobe 失败 | cuts 裁切流程 bug（见上） | 修复 trim_and_concat | — |

## 四、设备上传文件分析

失败文件 `9399ef57...mp4`（9,744,360 bytes = ~9.3MB）：
- ffprobe 可正常解析：**121.12s, 960x540, 24fps, h264+aac, isom brand**
- 不是传输截断（written == actual）
- 不是文件损坏（本地 ffprobe 成功）
- **真正原因**：服务端 `trim_and_concat` 的 finally 误删了裁切产物
