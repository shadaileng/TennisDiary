# 127：小程序端代码卫生与健壮性优化

## 一、背景与目标

对 `miniapp` 端做一轮代码卫生与健壮性审查后，修复以下四类问题：
1. **P0 缺陷**：`eventLogger.logWarn` 在批量达到阈值时整批丢失（业务埋点数据缺失）。
2. **console 噪音**：`App.vue`、`services/request.ts`、各 store/页面的 `logError + console.error` 双写，生产刷屏。
3. **封装不一致**：`analyze.vue` 裸 `uni.uploadFile` 绕过统一封装、`analysisStatus.ts` 魔法字符串 token 键。
4. **死代码与重复**：SSE 死代码、`getMe`/`getCheckins`/`createCheckin` 无引用导出、`resolveUploadUrl` 重复分支、`share.vue` 定时器未清理。

范围限定 `miniapp` 前端，后端无改动。

## 二、问题清单与修复方案

### 2.1 [P0] `eventLogger.logWarn` 达到阈值时整批丢失（bug）

**位置**：`src/utils/eventLogger.ts` 旧 L193-215。

**问题**：`logWarn` 中 `pendingBatch.push(...)` 后，两个分支都调用 `batchFlush()`，且 `>= 5` 分支随后执行 `pendingBatch = []`。但 `batchFlush()` 仅设置 3s 定时器，回调时才读取 `pendingBatch`。数组被提前清空后，触发阈值那批 warn 在 3s 后读到空数组，**全部丢失**。且注释「≥5 立即触发」实际并未实现，两分支代码完全相同属冗余。

**修复**：
- 抽出 `flushBatchNow()`：清定时器 + 取走 `pendingBatch` + 逐条上报。
- `batchFlush()` 内部定时器回调改为调用 `flushBatchNow()`。
- `logWarn`：`pendingBatch.length >= BATCH_THRESHOLD` 时立即 `flushBatchNow()`（真正实现「≥5 立即触发」），否则 `batchFlush()`（3s 防抖）。
- `logInfo` 维持 3s 批量，无此问题。

**变更文件**：`src/utils/eventLogger.ts`

**修复**：改用 `utils/upload.ts` 的 `uploadRaw`（内部统一拼接 `BASE_URL+API_PREFIX`、从 `STORAGE_KEYS.token` 取 token、解析 `{code,data}`、错误抛 Error），`analysisId = uploadRes.id` 语义不变。埋点链路（成功 logInfo / 失败走外层 catch logError）保持不变。

**变更文件**：`src/pages/coach/analyze.vue`、`src/utils/upload.ts`（无改动，复用现有能力）

**2.3.2 `analysisStatus.ts` 清理与常量收口**

**位置**：`src/services/analysisStatus.ts`。

**问题**：
- L41 `uni.getStorageSync("td_token")` 魔法字符串，未走 `STORAGE_KEYS.token`。
