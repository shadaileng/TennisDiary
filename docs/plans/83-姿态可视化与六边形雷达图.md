## 一、背景与问题

1. **姿态检测结果不可见**：`miniapp/src/pages/coach/analyze.vue:167` 仅在 AI **降级**（`score===0`）时才调用姿态推理；AI 正常出分时完全跳过。且即使运行，结果只拼接进摘要文字（`analyze.vue:180`），无独立可视化。
2. **六边形雷达图未移植**：Web 参考版 `docs/reference/tennis-diary/src/components/Charts.tsx:137` 有 `Radar` 六边形雷达图（`CoachReport.tsx:79` 使用）；小程序 `report.vue:30` 把六维评分画成**横向条**。
3. **无骨架标注**：后端从未在封面帧/视频上绘制 Pose 骨架；`video_url` 存储后小程序从不播放原视频。

## 二、目标

- 每次分析**都执行姿态推理**（与 AI 并行，不再受 `score===0` 门槛限制）；
- 姿态结果（三角度 + 骨架）随分析报告**落库**，历史详情可回看；
- 报告页新增：**六边形雷达图**（六维评分）、**姿态测量卡片**（肘角/膝角/躯干倾角）、**骨架标注封面**、**原视频/骨架视频切换**；
- 后端新增用户端**媒体服务**（`/api/media/{path}`），供小程序 `<image>/<video>` 加载服务端文件。

## 三、总体设计

```
上传视频 ──► /api/video/upload ──► frames + thumbnail + video_url
                │
                ├─► /api/ai/analyze（AI 六维，15-90s）────┐
                │                                        ├─► 并行（Promise.allSettled）
                └─► /api/pose/analyze（姿态，1-2s，save_skeleton）─┘
                        │ 每帧 33 关键点 + 三角度
                        │ 检出帧 Pillow 画骨架 → {base}_sk{i}.jpg
                        │ ffmpeg 编码 {base}_skeleton.mp4（libx264）
                        ▼
                pose = { detected, metrics, skeleton_frames[],
                         skeleton_video_url, skeleton_thumb }
                ▼
        POST /api/analyses（report + pose 一并落库）
                ▼
        报告页：雷达图 + 姿态卡片 + 骨架封面 + 原/骨架视频切换
```

## 四、方案设计

### 4.1 姿态数据落库（`Analysis.pose`）

- `Analysis` 新增 `pose` 列（Text，JSON），Alembic 迁移 `add_pose_to_analyses`（head `9e8d74e6ab01` → 新 revision）；
- 结构约定：

```json
{
  "detected": true,
  "metrics": { "elbowAngle": 96.4, "kneeAngle": 147.5, "trunkLean": -4.4 },
  "skeleton_video_url": "videos/{uid}/{base}_skeleton.mp4",
  "skeleton_frames": ["videos/{uid}/{base}_sk0.jpg", "..."],
  "skeleton_thumb": "videos/{uid}/{base}_sk2.jpg"
}
```

- `AnalysisCreate` / `AnalysisResponse`（用户端）+ `AnalysisDetailAdminResponse`（管理端）增加 `pose: dict | None`；
- `analysis_to_response` / admin 详情透传 `pose`（`_parse_json_field` 容错）。

### 4.2 骨架绘制与骨架视频（`pose_service.py`）

- 新增 `draw_skeleton(image_bytes: bytes, landmarks: list[dict]) -> bytes`：
  - Pillow 打开原帧，叠加绘制骨架（对齐 Web `pose.ts` `drawSkeleton`）：
    - 18 条连接线（`[11,12],[11,13],[13,15],[12,14],[14,16],[11,23],[12,24],[23,24],[23,25],[25,27],[27,31],[24,26],[26,28],[28,32],[15,17],[15,19],[16,18],[16,20]`），线色 LIME `#C8DA2B`，`lineWidth` 随宽度缩放；
    - 12 个关节点（肩/肘/腕/髋/膝/踝 11..28），白色实心圆；
    - 髋部中点重心标记（白色外圈 + LIME 内圆 + 十字准线）；
    - 端点 `visibility < 0.4` 跳过（与 `measure_angles` 阈值一致）；
  - 重新编码 JPEG（quality 0.85）返回 bytes；
- `analyze_frames(frames, video_url=None, save_skeleton=False)`：
  - 检出帧时若 `save_skeleton` 且 `video_url` 给定 → 画骨架存 `{video_dir}/{base}_sk{i}.jpg`（与视频同目录）；
  - 收集骨架帧路径；≥2 帧时调用 `encode_skeleton_video(skeleton_paths, out_path, duration)`：
    - 骨架帧写入 concat 列表，`ffmpeg -f concat -safe 0 -i list.txt -vf fps={fps},scale=trunc(iw/2)*2:trunc(ih/2)*2 -c:v libx264 -pix_fmt yuv420p -movflags +faststart {base}_skeleton.mp4`；
    - `fps = n_frames / duration`（钳制到 [1, 30]），复用已有采样帧 → 慢速关键帧动画，零额外推理；
    - `scale=trunc(iw/2)*2` 保证偶数宽高（x264/yuv420p 对奇数尺寸直接报错，实测 `360x269` 会 `rc 187` 空输出）；
    - ffmpeg 不可用（`find_ffmpeg()` 为 None）→ 跳过编码，仅保留骨架帧（优雅降级）；
  - 返回结构增加：`skeleton_frames`（相对 URL）、`skeleton_video_url`、`skeleton_thumb`（取 metrics 所在帧对应骨架帧，无则首帧）；
- `video_url` 相对路径 → 磁盘绝对路径（限定 UPLOAD_DIR 内，`normpath` 防穿越）。

### 4.3 姿态接口扩展（`POST /api/pose/analyze`）

请求（保持兼容，`frames` 仍为 base64 dataURL 列表）：

```json
{ "frames": [...], "video_url": "videos/1/abc.mp4", "save_skeleton": true }
```

- `video_url` / `save_skeleton` 可选（默认关）；开启且检出人体 → 返回骨架三字段；
- 校验：`video_url` 非法/越界 → 400。

### 4.4 用户端媒体服务（新路由 `app/routers/media.py`）

- `GET /api/media/{path:path}`：
  - 路径限定 `UPLOAD_DIR` 内（`normpath` 防穿越）；
  - **归属校验**：仅 `videos/{current_user_id}/...` 前缀（视频/帧/骨架文件均按用户分目录）；
  - **鉴权**：优先 `X-Auth-Token` 头，缺失时回退 `?token=` 查询参数（小程序 `<image>/<video>` 组件无法携带自定义请求头）——`app/core/auth.py` 新增 `get_current_user_media` 依赖；
  - content-type 映射复用 `files.py` 的 `_MEDIA_TYPES`（jpg/mp4 等），回退 octet-stream；
  - 文件不存在 → 404。
- 注册进 `main.py`。

### 4.5 小程序：六边形雷达图组件（`components/RadarChart.vue`）

- canvas 2d，移植 Web `Radar`（`Charts.tsx:137`）：
  - 三档网格环（0.33/0.66/1）、辐条线、数值多边形（LIME 填充 0.35 + 描边 2px）、顶点名称+分数标签（墨色）；
  - `data.length < 3` 显示空态「暂无评分数据」；
  - 与 `LineChart.vue` 同款 `uni.createSelectorQuery` 获取 canvas 节点 + dpr 缩放。

### 4.6 小程序：分析流程常驻姿态（`analyze.vue`）

- 移除 `score===0` 门槛；`analyzeSwing` 与 `analyzePose` **并行**（`Promise.allSettled`，姿态 ~1-2s 被 AI 15-90s 掩盖）；
- `analyzePose(frames, { video_url, save_skeleton: true })`；
- 结果组装 `pose` 对象随 `createAnalysis` 落库；AI 失败（不应发生，后端有降级）或姿态 503（模型缺失）任一失败不影响整体（各失败分别兜底）。

### 4.7 小程序：报告页增强（`report.vue`）

- **六边形雷达卡**：`<RadarChart :data="dimensions" />`（保留原「分维度点评」横向条卡，与 Web 一致）；
- **姿态测量卡**：`analysis.pose` 存在且 `detected` → 三角度读数（肘角/膝角/躯干倾角，`Math.round`）；`detected=false` → 「未检测到人体姿态」；无 `pose` → 隐藏；
- **封面**：优先 `pose.skeleton_thumb`（骨架标注帧），回退 `analysis.thumb`；
- **视频区**：`analysis.video_url` 与 `pose.skeleton_video_url` 都存在 → 显示「原视频 / 骨架视频」切换，`<video>` 换源；骨架帧缩略图横滑（`pose.skeleton_frames`）。

### 4.8 小程序：工具/类型/列表

- `types/index.ts`：`PoseMetrics` / `AnalysisPose`；`Analysis`/`AnalysisCreate` 增 `pose?: AnalysisPose`；
- `utils/index.ts` `resolveUploadUrl`：`videos/{uid}/...` → `${BASE_URL}/api/media/...?token=<storage token>`（直接读 `STORAGE_KEYS.token`，避免 utils 与 pinia 耦合；未登录游客不拼 token，由后端 401）；
- `coach.vue` 列表项：`a.pose?.detected` → 摘要旁「骨架 ✓」小徽标（可选增强）。

### 4.9 Admin（最小改动）

- `AnalysisDetailAdminResponse` 增 `pose` 字段并透传；详情弹窗展示三角度（复用既有静态文件路由渲染 `skeleton_thumb`）。

## 八、风险与注意事项

| 风险 | 说明与对策 |
|------|-----------|
| 骨架视频帧率低 | 复用 7/8 采样帧编码（fps=n/duration 慢速关键帧动画），零额外推理；后续可增帧率档位 |
| `?token=` 出现在 URL | 小程序媒体组件无法带 header，折中接受；JWT 30 天，日志/网关可能短暂记录，属既定取舍 |
| ffmpeg 缺失 | `find_ffmpeg()` 为 None 时跳过 mp4 编码，仅保留骨架帧（不阻断分析） |
| 旧数据无 pose | `analysis.pose` 为 null → 前端隐藏姿态卡/骨架封面，回退 `thumb` |
| 迁移顺序 | 须基于当前 head `9e8d74e6ab01` 生成，禁止 `create_all` |
