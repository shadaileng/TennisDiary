# 98：分享工坊分享图添加小程序码

## 一、背景与目标

### 1.1 现状问题

分享工坊生成的分享图（月度战报 / 今日日记 / 技术评分）仅含标题、数据卡片与底部一句 slogan，**缺少小程序码入口**，接收者无法扫码直达小程序，分享拉新转化弱。

### 1.2 目标

1. 在**三张模板**的分享卡底部统一追加微信小程序码，提升传播转化
2. 小程序码固定绘制于卡片底部右下角，左侧带「扫码体验 / Tennis Diary」竖排标签
3. 保持管线同步绘制模式（非阻塞），图片预加载后注入管线上下文
4. Playwright 视觉回归覆盖二维码区域

## 二、资源处理

源码位于 `docs/reference/TD网球日记.png`（**实际为 JPEG 数据**，文件头 `FF D8`，430×430）。`docs/reference/` 已被 `.gitignore` 忽略，且扩展名与实际内容不符，需重编码为真 PNG 后放入静态资源目录随包发布。

```bash
# 用 @napi-rs/canvas 重编码（一次执行）
node -e "const {createCanvas,loadImage}=require('@napi-rs/canvas');const fs=require('fs');
(async()=>{const img=await loadImage('docs/reference/TD网球日记.png');
const c=createCanvas(img.width,img.height);c.getContext('2d').drawImage(img,0,0);
fs.writeFileSync('miniapp/src/static/td-qr.png',c.toBuffer('image/png'));})()"
```

产物：`miniapp/src/static/td-qr.png`（PNG 签名 `89 50 4E 47`，约 80KB）。

## 三、实现设计

### 3.1 架构

微信 2d canvas 的图片绘制是**异步**的（`canvas.createImage()` + `img.onload` 后 `ctx.drawImage`），而现有 `DrawPipeline` 为纯同步执行。方案：

1. 页面 `draw()` 先通过 `node.createImage()` **预加载** `/static/td-qr.png`，`await onload` 完成后将图片对象注入上下文
2. 新增 `qrStage` 步骤（并入 `footer` 阶段）：同步调用 `ctx.drawImage` 绘制，**不阻塞管线**
3. 图片加载失败时优雅降级：跳过二维码绘制、底部留白、日志记录，不影响出图主流程

### 3.2 布局

```
┌─────────────────────────────────────────────────────────┐
│                                                         │
│            卡片主体（月报/日记/技术评分）                │
│                                                         │
├─────────────────────────────────────────────────────────┤
│  用 Tennis Diary 记录我的网球成长 🎾    扫码体验        │
│  (slogan)                      Tennis Diary            │
│                                      ┌──────────┐      │
│                                      │ 二维码160 │      │
│                                      └──────────┘      │
└─────────────────────────────────────────────────────────┘
```

- `footer.height`：120 → **240**（为二维码留出底部空间）
- 二维码：尺寸 160×160、右边距 70，垂直居中于底部留白区
- 标签：二维码左侧右对齐两行竖排文案「扫码体验 / Tennis Diary」
