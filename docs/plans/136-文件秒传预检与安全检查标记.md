# 文件秒传预检与安全检查标记

## 1. 问题描述

### 1.1 现状分析

当前文件上传流程存在两个问题：

**问题 A：秒传返回值 Bug（理论风险）**

`upload.py` 中 `/upload/gear-image` 和 `/upload/avatar` 端点在 mirage 命中时：
1. 创建新 File 记录（复用原文件路径）
2. 删除新上传的物理文件
3. 返回 `rel_path`（原文件路径）

返回值逻辑正确（返回的是原文件路径），但流程冗余：客户端先上传文件到磁盘，服务端再删除。对于大文件（如装备封面），浪费带宽和磁盘 I/O。

**问题 B：安全检查标记缺失**

文件安全检查（`imgSecCheck`）结果未持久化到 File 记录。每次秒传命中时，无法知道原文件是否已通过安全检查。

### 1.2 目标

1. **新增 `/upload/check` 端点**：客户端上传前先按 MD5 预检，命中则零流量
2. **新增 `security_checked` 字段**：记录文件安全检查状态，预检时直接返回
3. **三态响应**：命中+安全通过 / 命中+安全未通过 / 未命中

## 2. 解决方案

### 2.1 `/check` 端点设计

```
客户端                                  服务端
  │                                       │
  │  1. 计算文件 MD5 + size               │
  │──────────────────────────────────────>│
  │  POST /upload/check                   │
  │  JSON: { md5, size_bytes }            │
  │                                       │
  │                 2. 按 MD5 查询 File    │
  │                 3. 检查物理文件存在    │
  │                 4. 读取 security_checked│
  │                                       │
  │<──────────────────────────────────────│
  │  响应：                                │
  │  - hit: false                         │
  │  - hit: true, safe: true, url: "..."  │
  │  - hit: true, safe: false             │
  │                                       │
```

**三态响应逻辑**：

| 场景 | 条件 | 返回 | 客户端行为 |
|------|------|------|-----------|
| 未命中 | MD5 无匹配 / 文件不存在 | `{hit: false}` | 正常上传 |
| 命中 + 安全通过 | `security_checked=1` | `{hit: true, safe: true, url}` | 直接使用 URL |
| 命中 + 安全未通过 | `security_checked=0` | `{hit: true, safe: false}` | 显示安全提醒 |

**关键约束**：
- `/check` 端点**只查询，不执行安全检查**（安全检查由上传端点负责）
- `security_checked=0` 的文件保留（不删除），返回安全未通过提醒
- 物理文件不存在时视为未命中

### 2.2 `security_checked` 字段设计

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `security_checked` | Integer | 0 | 0=未检查/安全检查未通过，1=已通过安全检查 |

**写入时机**：
- `/upload/gear-image`：安全检查通过后 `File.security_checked = 1`，失败时保留文件（security_checked=0）
- `/upload/avatar`：同上
- `/upload/check` 命中时：读取并返回，不修改

**存量数据迁移**：Alembic 迁移时将所有 `security_checked=0` 设为 1（假设已通过安全检查）。

### 2.3 前端两步上传流程

```
选择图片
  │
  ▼
uni.getFileSystemManager().getFileInfo({ filePath, digestAlgorithm: "md5" })  ────  直接获取 digest（MD5）
  │
  ▼
POST /upload/check  ────  预检（JSON）
  │
  ├─ hit=true, safe=true  →  返回 URL，完成
  │
  ├─ hit=true, safe=false →  显示安全提醒 toast
  │
  └─ hit=false            →  POST /upload/gear-image 正常上传
```

### 2.4 MD5 计算方案

- **API**：`uni.getFileSystemManager().getFileInfo({ filePath, digestAlgorithm: "md5" })` 返回 `digest` 字段即 MD5
- **无需第三方库**：微信小程序原生支持，无需 js-md5
- **平台兼容**：iOS/Android 均支持

## 6. 风险与注意事项

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 存量数据 security_checked 误判 | 假设已通过安全检查 | 早期文件已通过 imgSecCheck |
| `/check` 并发请求 | 同一文件同时预检 | 幂等操作，无副作用 |
| uni.getFileSystemManager().getFileInfo 兼容性 | 小部分旧版本不支持 | iOS 14+ / Android 均支持 |
