# Step 21：前后端 `.env` 配置模板

## 一、目标

1. 前端 baseURL、请求超时从硬编码改为 `.env` 环境变量驱动（Vite `import.meta.env`）
2. 后台支持自动加载 `server/.env`（`python-dotenv`，绝对路径）
3. 前端 storage 键名 `td_*` 收口到常量文件，统一管理
4. 只提交 `.env.example` 模板，实际 `.env.*` 由各环境手动配置（不提交）

## 二、决策记录

| 决策点 | 结论 |
|---|---|
| `.env.*` 是否提交 | 只提交 `.env.example` 模板，实际 `.env.*` 不提交 |
| 后台 `.env` 加载方式 | 方式 B：`python-dotenv` + `load_dotenv()`，用绝对路径显式加载 |
| storage 键名收口 | 新建 `src/constants/storage.ts`，统一 `td_` 前缀 |

## 三、技术方案

### 3.1 前端：`.env` 环境变量化

uni-app（Vite 5.2.8）原生支持 `import.meta.env`：

- `pnpm dev:h5` / `dev:mp-weixin` 自动加载 `.env.development`
- `pnpm build:*` 自动加载 `.env.production`
- `import.meta.env.VITE_API_BASE_URL` 读取模板变量，未配置时按平台兜底（小程序端 `127.0.0.1`，H5 端 `localhost`）

### 3.2 前端：storage 键名收口

`td_token`、`td_user`、`td_settings` 三处魔法字符串统一收口到 `src/constants/storage.ts`，`request.ts`、`auth.ts`、`settings.ts` 均引用常量。

### 3.3 后台：`.env` 自动加载

- 新增 `python-dotenv` 依赖
- `config.py` 顶部用绝对路径 `load_dotenv(Path(__file__).resolve().parent.parent / ".env")`
- 这样无论从哪个目录启动，都能正确加载 `server/.env`
