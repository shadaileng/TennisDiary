# Step 116：上传文件类型服务端探测与文件修复功能

## 一、目标

1. **上传即正确**：上传时由服务端探测真实文件类型，将正确的 `mime_type` 落库到 `File` 表，替代不可靠的客户端 `Content-Type`。
   - 音视频：调用 `ffprobe` 探测流类型（`video`/`audio`）与容器格式，映射为正确 MIME。
   - 图片：扩展名 + 可选 PIL 校验真实格式（伪扩展名纠正）。
2. **预览兜底**：预览/下载端点用**确定性扩展名映射**兜底，不再依赖运行时 `mimetypes.guess_type`（线上 slim 镜像可能把 `.mp4` 解析成 `audio/mp4`，导致前端用 `<audio>` 标签渲染，Chrome 把它当音频）。
3. **文件修复功能**：扫描 `File` 表，按物理文件重新探测并修正 `mime_type`（含存量空值记录）。提供 admin 端点 + CLI 脚本。

## 二、现状问题分析

### 2.1 根因

数据库 `files` 表中该 mp4 记录：

```
(43, 'f68e5a39...mp4', 'videos/2/f68e5a39...mp4', '', 'video')   # mime_type 为空
```

- 为空原因：上传来自小程序 `uni.uploadFile`，微信端未带 `Content-Type`，后端 `video.py:95` 用 `file.content_type or ""` 存储，落库为空。
- 预览弹窗判断音频/视频**只看这个 `mime_type` 字符串**（`FilePreview.vue:83-84`）：
  ```js
  const isVideo = computed(() => props.mimeType?.startsWith('video/'))
  const isAudio = computed(() => props.mimeType?.startsWith('audio/'))
  ```
- admin `preview_file` 端点（admin/files.py:497-500）在 `mime_type` 为空时走兜底：
  ```python
  guessed = mimetypes.guess_type(file_record.original_name or file_record.rel_path)[0]
  ```
- **关键问题**：`mimetypes.guess_type` 依赖运行环境的系统 `mime.types`，在不同镜像里 `.mp4` 的映射不一致。线上 ModelScope 的 slim 镜像 `mime.types` 较精简，`.mp4` 可能被注册成 `audio/mp4`。一旦返回 `audio/mp4`，前端用 `<audio>` 渲染 mp4 字节，Chrome 即把它当音频处理。

### 2.2 对比

| 端点 | MIME 来源 | 是否可靠 |
|------|-----------|----------|
| 用户端 `files.py`/`media.py` 下载 | 写死 `_MEDIA_TYPES`（`.mp4`→`video/mp4`） | ✅ 可靠 |
| admin `serve_admin_file`（实际文件字节） | 写死 `_ADMIN_MEDIA_TYPES`（`.mp4`→`video/mp4`） | ✅ 可靠 |
| **admin `preview_file`（告诉前端"这是什么类型"的字符串）** | `mimetypes.guess_type`（环境相关） | ❌ 不可靠 → 本次 bug |

> 实际文件字节本身没问题（serve 端点 content-type 正确），出错的只是"告诉前端类型"的字符串。

## 三、设计方案

### 3.1 共享 MIME 工具 `app/core/mime.py`

- `EXTENSION_MIME: dict[str, str]`：确定性映射（不依赖运行时 `mimetypes`）：
  - 图片：`.jpg/.jpeg`→`image/jpeg`、`.png`→`image/png`、`.gif`→`image/gif`、`.webp`→`image/webp`
  - 视频：`.mp4`→`video/mp4`、`.mov`→`video/quicktime`、`.m4v`→`video/mp4`
  - 音频：`.m4a`→`audio/mp4`、`.mp3`→`audio/mpeg`
  - 其他：`.pdf`→`application/pdf`
- `detect_image_mime(path)`：扩展名映射 + 可选 PIL 校验（读取真实格式纠正伪扩展名）。
- `detect_media_mime(path)`：
  - `ffprobe -v error -show_entries stream=codec_type,format=format_name -of json <path>`
  - 解析 `streams`：含 `video` 流 → 按 `format_name` 映射（`mp4/mov/m4v`→`video/mp4`、`video/quicktime`）；仅有 `audio` 流 → `audio/mp4` 等。
  - ffprobe 不可用/失败 → 回退 `EXTENSION_MIME`。
- `detect_mime_type(path, upload_source)`：facade——
  - 图片类（avatar/gear_image/其他 image）→ `detect_image_mime`
  - 音视频类（video/video_frame）→ `detect_media_mime`
  - 兜底：`EXTENSION_MIME` → `application/octet-stream`

### 3.2 上传入口落正确值

| 文件 | 位置 | 改动 |
|------|------|------|
| `app/routers/video.py` | L95 `get_or_create_file(mime_type=file.content_type or "")` | 非秒传、文件落盘后改为 `mime_type=detect_media_mime(abs_path)` |
| `app/routers/upload.py` | L71（头像）、L169（装备图） | 非秒传、文件写盘后改为 `detect_image_mime(abs_path)` |

> 注意：`get_or_create_file` 先建记录后写盘（video.py），探测须在写盘后、`db.commit()` 前更新 `file_record.mime_type`。秒传分支复用 `existing.mime_type`（存量可能仍空，由修复功能兜底）。

### 3.3 预览/下载端点兜底

- `app/routers/admin/files.py` 的 `preview_file`（L497-500）与下载端点（L443-445）改用 `EXTENSION_MIME` 兜底，去掉 `mimetypes.guess_type`。

### 3.4 文件修复功能（扫描在库文件并修正）

- `app/services/file_service.py` 新增 `repair_file_mime_types(db, only_empty=True)`：
  - 扫描 `File` 表（默认仅 `mime_type` 为空/可疑），对每条记录按物理文件 `detect_mime_type` 重新判定。
  - 与存储值不同则更新 `mime_type`，返回 `{scanned, repaired, unchanged, details}`。
- admin 端点 `POST /api/admin/files/repair`（带 `@audit`，参照现有文件端点）调用上述逻辑。
- CLI 脚本 `server/scripts/repair-files.py`：离线/CI 直接复用同一逻辑。
- **管理端 UI**：`admin/src/views/files/index.vue` 新增「修复文件类型」按钮，调用端点并弹窗展示统计（扫描数/修正数/未变/跳过）与明细列表。

### 3.5 收敛重复映射

- `files.py`/`media.py`/`system.py` 中三处 `_MEDIA_TYPES`/`_ADMIN_MEDIA_TYPES` 统一引用 `EXTENSION_MIME`（serve 端点也走 `detect_media_mime`），消除漂移。

## 八、注意事项

1. **ffprobe 可用性**：线上 slim 镜像已装 ffmpeg（视频抽帧依赖）；`detect_media_mime` 在 ffprobe 缺失时安全回退扩展名映射，不抛错。
2. **性能**：上传多一次 ffprobe（秒级），与现有抽帧 ffmpeg 开销同级，可接受；修复功能为管理员主动触发，非请求热路径。
3. **幂等**：修复功能重复执行不产生副作用（值相同则不改）。
4. **权限**：repair 端点仅管理员，记录审计日志。
5. **向后兼容**：存量空 mime 记录由修复功能 + 预览兜底双层保障，不强制立即迁移。
6. **日志规范**：异常统一 `%s` 风格（见 AGENTS.md 核心约束 5）。
